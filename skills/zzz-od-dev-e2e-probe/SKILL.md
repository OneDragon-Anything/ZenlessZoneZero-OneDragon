# 实机 E2E 探测（项目专属流程）

**定位**:开发/评估一个新玩法自动化前，用**探测**（probe）在实机游戏里摸清 UI 路径、OCR 可识别性、点击可达性——不改生产代码，只搭临时探测设施。区别于 `zzz-od-dev-debug-automation`（那个是排查**已有**自动化跑失败，从日志入手；本 skill 是**还没有**自动化，从实机入手）。

**铁律**:探测全程不改生产代码/配置；探测结束后必须完整收尾（见第 6 节）。

## 1. 探测方式二选一

- **A. 调试插件**（要复用框架能力时）:在 `app/plugins/` 下建临时插件（plugin.json + factory.py + *_app.py，结构抄现成插件），app 主体写成「用 `goto_screen` 进入目标界面 → 空转或命令循环」。用 launcher `-a <app_id>` 单应用运行。⚠️ 单应用运行同样吃 run_record 跳过机制——当天已跑过会被跳过，**删对应 `config/<实例>/app_run_record/<app_id>.yml` 前先备份**。
- **B. 独立提权探测进程**（要自由迭代、不依赖框架时）:写一个命令循环脚本，从**命令文件**读指令（screenshot/ocr/click/key/focus/setfocus/syscmd/done 等），把结果（截图/OCR 文本）写回结果文件，agent 在游戏外写命令→读结果→再写命令迭代。现成脚本在 `zode-agent/probe/` 可抄协议。命令文件逐条执行、每条带结果回执，**不要**一次批量下发后盲等。

选型判据:要验证「框架识别/节点逻辑在这个界面上行不行」用 A；要摸「这个界面长什么样、元素在哪、点哪有用」用 B。两者可叠加（插件负责进界面，命令循环负责细看）。

## 2. 启动与提权（先决条件，错了全盘皆输）

- 游戏 exe 清单要求管理员权限 → **与游戏交互（发输入/读后台窗口）的进程必须同为提权进程**，否则输入被 UIPI 静默吞掉（不报错，表现为「点了没反应」）。
- 启动游戏优先走**计划任务**（一条龙计划任务 RunLevel Highest，`Start-ScheduledTask` 同用户不弹 UAC）；计划任务被当日记录挡住时，用 **run_record 劫持法**:备份并删当日记录 → 触发计划任务 → 游戏窗口出现后杀 launcher/python 保住游戏 → **立即恢复记录**。
- 应急提权可用 ms-settings/fodhelper 注册表劫持，**用完必须删临时注册表键**；且注意:经劫持链启动的进程上下文有已知异常（见 design.md），能走计划任务就走计划任务。
- **输入健康取决于启动上下文**:同一段注入代码，计划任务链启动的游戏输入正常；异常链启动的游戏可能键盘全吞+鼠标被 ClipCursor 焊死。探测中遇到「输入全部无响应」，**先查游戏是怎么启动的**，再怀疑代码。

## 3. 迭代循环判据

- 截图用 PIL ImageGrab（本机未装 mss）；OCR 必须传 **3 通道图**（灰度 2 维会 ValueError 且被节点重试吞掉，表现为静默跳过——离线脚本同理）。
- **截图新鲜度先用连拍自证**:连续抓 2-3 张比对哈希/差异。画面里有动态元素（镜头在动、角色在转）时，单张截图极易被误判成「旧帧」——先证明截图管线新鲜，再去排查别的，不要跳到「框架截图是旧帧」的结论。
- 找元素:OCR 拿文本位置 / 模板匹配拿图块位置；确认「看到了」和「能点中」是两回事，点击后必须再截图验证状态变化。

## 4. 点击无响应的排查顺序

1. **注入管线自检**:把同样的注入代码往记事本等无 UIPI 限制窗口发一段文字/按键。记事本收不到 = 管线本身坏（查 SendInput 的 INPUT 结构——x64 必须含 MOUSEINPUT 共 40 字节，短结构 SendInput 返回 0）；收到了 = 管线好，是游戏侧不吃。
2. 游戏侧不吃 → 先确认进程提权等级匹配（第 2 节）、游戏窗口有焦点。
3. 合成点击（SendInput/mouse_event）对**部分游戏 UI 无效**（如底部按钮条），换路径:键盘快捷键、地图传送等绕过 UI 点击。判断标准:同位置对明显该响应的界面（如其他按钮）也无响应 = 系统性免疫，别在同一位置反复重试。
4. 内核级驱动（如飞智 gvinput）可作为最终手段，但 stop 不掉（返回 1052）且因果未证实，不作为首选。

## 5. 探测中的禁止事项

- 不改生产代码与 `_group.yml` 等配置；临时动过必须**精确恢复**并逐项核对。
- 不杀一条龙计划任务链、不动自动化记忆。
- 探测进程要**事先记下自己的 PID**（提权进程的 CommandLine 非提权进程读不到，事后按 PID 清理，否则清不干净、多实例还会抢命令文件）。

## 6. 收尾清单（全做完才算结束）

1. 按 PID 杀掉所有探测进程（含提权探测进程、调试插件跑的 python/launcher）。
2. 恢复所有备份（run_record、临时配置）。
3. 删除临时注册表键（如用过提权劫持）。
4. 关闭游戏。
5. 探测报告落 `zode-agent/probe/REPORT-<日期>-<主题>.md`:目标、方法、发现（界面路径/坐标/结论）、未解决问题、建议。
6. 删除或归档一次性探测脚本与调试插件（可复用的留 `zode-agent/probe/`）。
