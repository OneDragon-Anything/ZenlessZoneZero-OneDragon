# zzz-od-dev-e2e-probe — 设计记录

## 为什么做

2026-11-04 古怪回收处活动兑换可行性探测，用户明确「你曾多次完成 e2e 测试，现在也要自己来，我不在电脑前」。整个探测从零手搓:提权启动游戏、搭探测脚本、建调试插件、踩完输入死锁/截图新鲜度/点击免疫一堆坑，耗时大半天。事后复盘发现这些判据每次实机探测都要用，但全部散落在会话记忆里，下次还会重踩 → 固化成 skill。用户原话:「这开发太费劲了，e2e 测试流程还没固定下来形成技能吗?」

## 定位与边界

- **管**:在实机游戏里**从零摸一条 UI 流程**的项目专属流程（探测方式选型、提权与启动、迭代判据、点击免疫对策、收尾）。
- **不管**:排查**已有**自动化跑失败（→ `zzz-od-dev-debug-automation`，从日志入手）；定位到问题后决定怎么修（→ `zzz-od-dev-deciding-a-fix`）；具体活动的界面流程/坐标（游戏事实 → doc）。

## 关键决策 + 理由

- **与 debug-automation 分立而非合并**:两者入口完全不同（一个从「用户反馈跑失败+日志」入手，一个从「什么都没有+实机」入手），description 里互相指认边界，避免触发错技能。
- **探测方式写成「二选一 + 可叠加」而不是只推一种**:调试插件（A）复用框架 goto_screen/run_record 生态但迭代慢（每次改逻辑要重启 app）；独立命令循环进程（B）迭代快但要手搓一切。这次实战是 B 为主、最后为了验证框架路径又补了 A——判据按「要验证什么」给，不锁死。
- **命令文件协议而非 socket/MCP**:探测进程是提权进程，与 agent（非提权）之间唯一可靠通道是文件；且逐条命令+回执让 agent 能逐步验证，盲等批量结果出问题时无法定位。
- **「输入健康取决于启动上下文」写成第 2 节硬判据**:本次最大弯路——数小时以为注入代码有 bug，实际是游戏经 fodhelper 劫持链启动导致键盘全吞+ClipCursor 焊死在窗口中心；而计划任务链启动的同一段代码一切正常。结论:输入异常先查启动链。
- **fodhelper/ms-settings 劫持法保留但降级为「应急」**:它确实解决了「无人在场无法点 UAC」的问题，但①有注册表残留风险（必须清理）②启动上下文有上述已知异常。优先级:计划任务 > run_record 劫持计划任务 > 劫持提权。
- **点击免疫写成「排查顺序」而非「结论」**:本次发现底部按钮条对一切合成点击免疫（连 hoverclick 都不行），但只验证了当前版本+当前窗口状态，不能断言永远免疫。写成「先自检管线→查提权/焦点→换路径绕过→内核驱动最后手段」，让下次探测者按序排除而不是背死结论。
- **「截图连拍自证新鲜度」**:本次第二大弯路——棕发/蓝发误判持续数小时，根因是录像店闲置镜头绕角色转（画面在动），截图一直是新鲜的。判据:怀疑旧帧前先用连拍哈希证明截图管线新鲜。
- **收尾清单单列一节且「全做完才算结束」**:本次踩过「非提权进程读不到提权进程 CommandLine 导致清理失效」（解法:事先记 PID）和「探测进程被自己的清理脚本误杀」（解法:按 PID 名单清理）——不写成硬清单必然漏。
- **现成资产指 `zode-agent/probe/`**:按 skill-guide 规范 3，这是项目内稳定资产路径（运维台账，跨会话存在），探测协议脚本（recycle_probe.py）与报告都在这，属「skill 要读写的稳定操作对象」，可引。
- **SKILL.md 不写**:本次具体坐标/窗口中心值/活动名/gvinput 细节——游戏事实或案例偶然细节，归 design.md 与 doc。
- **GREEN 验证状态**:RED（本次裸跑踩坑历程）即下方案例；GREEN 待下次实机探测时校准——确认按 SKILL.md 走能省掉哪些弯路，判据有不实用/遗漏的回来改。

## 案例:古怪回收处兑换探测（踩坑论据，2026-11-04）

> 具体细节记这，不进 SKILL.md。

- **目标**:评估「迷宫诡域-古怪回收处」每日 400 售价物品自动兑换的可行性。用户策略:每周上限 8 个；找不到 400 的就不卖、直接报。
- **流程**:ESC → EVENTS → 活动列表点击进入（成功）；赛季剩 27 天（12/2 结束），无紧迫时间限制。
- **卡点**:活动页底部「前往」按钮条对合成点击免疫（hoverclick、连点均无效），零号空洞同位置也不响应 → 备选路径 M 键地图传送，未验证完。
- **输入死锁排查历程**:fodhelper 提权链启动游戏后键盘全吞+ClipCursor 焊死 (1280,731)；验证注入管线正常的方法是往记事本发 HELLO123（收到了=管线好）。SendInput 曾返回 0，根因 INPUT 结构 24B<40B（x64 须含 MOUSEINPUT），修正后 err=0。
- **截图误判**:长时间怀疑框架截图是旧帧（棕发 vs 蓝发），连拍哈希证明是录像店闲置镜头绕角色转、截图一直新鲜。
- **探测设施**:独立提权命令循环脚本（`zode-agent/probe/recycle_probe.py`，协议 enter/shot/ocr/click/key/focus/minrestore/dump/setfocus/launchapp/syscmd/done/hoverclick）+ 调试插件（`app/plugins/wrc_probe/`，app 主体=返回大世界+命令循环）。多实例并存会抢命令文件；探测进程被自己的清理脚本误杀过一次。
- **Git Bash 陷阱**（与探测相关，详见 workspace 记忆）:以 / 开头的命令参数会被 MSYS 路径转换毁掉，探测协议命令经文件传递则不受影响。
- **最终状态**:全部进程清理、注册表键删除、游戏关闭、报告 `REPORT-2026-11-04-weird-recycle.md` 交付。
