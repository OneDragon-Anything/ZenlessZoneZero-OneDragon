# 设计记录

## 定位

这个 skill 约束自动战斗 YAML 的操作、状态处理器和模板引用写法。它不定义具体角色的战斗逻辑。

## 合并流程

自动战斗运行时读取 `.merged.yml`，但人工维护源是 `sample.yml`。因此在 skill 中明确禁止直接修改 `.merged.yml`，并要求改完 sample 后调用 `new-config` 的构建脚本。

这样可以避免源文件与运行产物分叉，也让所有自动战斗目录的合并结果保持一致。构建产物需要提交，因为运行时依赖它。

## CG 与失衡计时

游戏内 CG 或播片会暂停失衡计时，但 `自定义-失衡时间` 仍按真实时间变化。技能模板若包含这类演出，必须以实测 CG 时长使用 `seconds_add` 补偿，否则后续判断会提前认为失衡结束。该规则写在 `SKILL.md` 的倒计时方法旁，避免只知道负值可延长状态，却遗漏它的必要使用场景。

## 长按与并发输入

长按不能只发送一次按下再等待。自动战斗的其他并发操作可能对同一按键发出松开事件，使长按提前结束。因此 `SKILL.md` 规定长按期间每 0.5 秒重复发送按下，并在结束时显式松开。

## 长操作与打断（持续操作直到状态达成）

自动战斗里大量动作是「持续操作直到某种状态达成」（长按直到资源耗尽、连招直到某 buff 生效）。原 skill 只把 `interrupt_states` 当字段名列在状态树示例里、没讲语义，实际写出来常出两类错：漏写打断（动作只能自己跑完才响应）、把动作和停止条件嵌套进同一个状态分支（无法中途响应）。

因此 `SKILL.md` 补上该模式：持续操作分支的 `states` 是「可执行条件」、`interrupt_states` 是「中途打断条件」；停止条件要平铺成同级分支、不可嵌套；顶层 handler 也要挂打断。参考的现成范式是站场型角色的「长按普攻直到资源见底再合轴」这类模板。

## seconds 是触发时间偏移，不是时长

源码里 `设置状态 seconds: N` 把状态触发时间记为「当前时刻 + N」；判断 `[状态名, a, b]` 命中当「当前时刻 − 触发时间 ∈ [a, b]」。因此「设置后持续 N 秒」= `seconds: N`（正数）+ 判断 `[状态名, -N, 0]`（负数窗口，因为触发时间在未来）。

早期 SKILL.md 把设置写成 `seconds: -N`，是错的：负的触发时间落到过去，判断永远命中不了。踩坑背景：把 `seconds: 2` 当成「2 秒后生效」、又用默认窗口 `[状态名]`（= `[0, 1]`）判断，结果状态在设置后第 2~3 秒才命中，角色一切进场就掉到默认分支离场。

## 轮换-合轴 与 轮换-紧急 是两个时机

团队切入分「主动轮换（合轴）」与「强制切入（紧急）」两个时机，由两个全局模板分别承载。原 SKILL.md 只在「如何新增一个角色」里并列提了两句文件名，没说区别，容易只在一个地方挂角色、或把两处条件写反。因此在 `SKILL.md` 补 §6.4，说明两个时机的语义与条件宽严差异：合轴门槛宽（有资源就进）、紧急门槛严（资源与关键技能同时达成才强制切入）。
