# zzz-od-dev-character 设计记录

## 定位与边界

- 覆盖新增可自动战斗角色的四层流程：Agent 定义、头像模板、状态模板、自动战斗 YAML。
- 只记「怎么做」的方法论与判据；具体游戏事实（某角色的键位、坐标、机制）归 docs，不进本 skill。
- 自动战斗 YAML 语法细节引用 `agent-auto-battle-config`，不重复。

## 关键决策与理由

### 状态名必须带「角色名-」前缀（2026-08 修正）

- **踩坑**：希格莉德适配时 `AgentStateDef('巡空枪势', ...)` 漏了角色前缀，自动战斗 YAML 里 `states: "[巡空枪势]"` 一直匹配不到，表现为状态「刷不出来」。实测确认后改为 `'希格莉德-巡空枪势'`，YAML 同步改为 `[希格莉德-巡空枪势]` 即恢复正常。
- **为什么这么定**：`state_name` 会进入自动战斗状态系统，系统内状态名是全角色共享的命名空间。角色专属状态不带前缀会和其他角色的同名状态冲突或无法被 YAML 精确引用；项目现有状态全部遵循「角色名-状态名」（如 简-萨霍夫跳、雅-落霜）。
- **判据**：凡属于单个角色机制的状态，`state_name` 一律写成「角色名-状态名」；YAML 里 `states` / `interrupt_states` 引用必须与之一字不差。通用状态（前台-能量、按键可用-x）不带角色前缀。

### connect_cnt 与检测区域大小

- 踩坑：希格莉德状态模板检测区域只有 1 个像素点，却写了 `connect_cnt=5`，连通域面积阈值永远达不到，状态永远不触发。
- 判据：`connect_cnt` 是「连通块或像素数量阈值」，必须小于等于检测区域内可能出现的最大同色连通面积；区域只有几个像素时设 1 即可，别照抄大区域模板的阈值。

### 采样颜色必须与框架色彩空间一致

- 踩坑：本地采样用 `cv2.COLOR_BGR2HSV`，框架 `filter_by_color` 用 `cv2.COLOR_RGB2HSV`，红蓝色相互换，导致对着截图调出来的颜色区间全错。
- 判据：调 `hsv_color` / `hsv_color_diff` 前，先用与框架相同的 `COLOR_RGB2HSV` 转换采样截图颜色，再定中心值与容差。

### 模板坐标直接来自模板 config.yml

- 判据：状态模板的 `point_list` 就是检测区域，调色/验证时直接对该坐标采样，不要在整张截图里重新找目标位置；坐标基准是 1080p。
