# 贝果路线与出生点

本文说明打点路线、出生点和开启选择的数据规则：文件位置、格式、写入保护、开启选择和旧数据迁移。编辑器操作见[贝果开发工具](bagel_flow_editor.md#网页路线编辑器打点路线)。正式运行的出生识别见[贝果自动化方案](bagel.md#出生识别与导航)。

## 术语

| 术语 | 含义 |
| --- | --- |
| 出生点 | 入场时角色所在的固定位置。出生点在出生点清单中登记，独立于路线首点：移动路线首点不改变出生点位置 |
| 路线 | 一串有序点位，顺序就是行走顺序。每条路线绑定一个出生点 |
| 默认路线 | 随程序发布的路线。内容只读，可以开启、关闭、复制和试跑 |
| 自定义路线 | 用户新增、录制或复制得到的路线。可以编辑节点、改名和删除 |
| 开启选择 | 每个出生点当前用于正式运行的路线。一个出生点最多开启一条路线，也可以不开启 |

## 文件与标识

| 文件 | Git | 内容 |
| --- | --- | --- |
| `assets/game_data/bagel/spawn_points.yml` | 跟踪 | 出生点清单，以及首次使用时开启的默认路线 |
| `config/bagel/routes/<标识>.sample.route.json` | 跟踪 | 默认路线 |
| `config/bagel/routes/custom_<标识>.route.json` | 忽略 | 自定义路线 |
| `config/bagel/route_settings.yml` | 忽略 | 开启选择 |
| `config/bagel/legacy_routes_backup/<时间>/` | 忽略 | 旧版路线迁移前的备份 |

### 出生点清单

每个出生点登记以下字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定标识。路线和开启选择用它引用出生点 |
| `name` | 显示名称 |
| `layer` | 完整分层名，如 `雅努斯幻境/Custom` |
| `x`、`y` | 全局坐标，坐标体系见[分层小地图说明](bagel_fixed_map.md) |
| `radius` | 识别半径，单位为地图像素。定位结果与出生点的距离不超过该值，才算命中 |
| `initial_route` | 首次使用时开启的默认路线标识。`null` 表示首次使用时不开启路线 |

当前清单登记了雅努斯幻境的 5 个出生点。识别半径均为 100 地图像素：

| 标识 | 显示名称 | 全局坐标 | 首次使用时开启 |
| --- | --- | --- | --- |
| `janus_video_store` | 录像店 | `(822,348)` | 录像店-默认 |
| `janus_worksite_station` | 白鸽工地站 | `(341,432)` | 白鸽工地站-默认 |
| `janus_south_station` | 六昏街南站 | `(1002,466)` | 六昏街南站-默认 |
| `janus_construction` | 改建工程区 | `(602,30)` | 不开启 |
| `janus_worksite_depths` | 工地深处 | `(255,829)` | 不开启，没有默认路线 |

坐标取自录像定位，依据和限制见[出生点素材索引](../../../game/screens/image/bagel_spawn_points/README.md)。清单只包含已观察到的出生位置，不能证明出生点已经全部登记。城郊幻境没有登记出生点。正式应用的入场地图范围不因编辑器显示城郊地图而改变。

### 路线文件

路线文件使用 JSON，格式版本为 2：

```json
{
  "version": 2,
  "route_id": "录像店-默认",
  "name": "录像店-默认",
  "spawn_id": "janus_video_store",
  "started_at": "2026-10-25T23:34:41+08:00",
  "ended_at": "2026-10-25T23:35:16+08:00",
  "points": [
    {"x": 830, "y": 351, "layer": "雅努斯幻境/Custom", "kind": "beacon"}
  ]
}
```

- `route_id` 创建后不变，并与文件名主干一致。文件名与标识不一致时，文件按损坏处理。
- `name` 是显示名称。改名只修改 `name`，不修改标识和文件名，所以开启选择不受改名影响。全部路线的显示名称不能重名。
- `spawn_id` 是绑定的出生点。路线创建后，编辑器不提供更换出生点的操作。
- 路线文件不保存开关状态。路线是否开启由开启选择决定。
- 点位字段与类型见[路线文件中的点](bagel_flow_editor.md#路线文件中的点)。

来源由文件位置决定：`*.sample.route.json` 是默认路线，其余 `*.route.json` 是自定义路线。程序不接受网页声明的来源。自定义路线标识必须符合 `custom_` 加小写字母、数字或下划线的形式。默认路线和自定义路线分别加载，不存在同名文件覆盖默认路线的规则。

### 路线能否开始

路线的首点必须同时满足以下条件，路线才能从出生点开始执行：

1. 首点是途径点。
2. 首点与出生点在同一完整分层。
3. 首点与出生点的距离不超过该出生点的识别半径。

开启路线、保存自定义路线和正式运行时都检查这些条件。不满足时，开启和保存被拒绝，正式运行拒绝开始。

## 开启选择

开启选择为每个出生点保存一个路线引用，或保存 `null` 表示不开启：

```yaml
version: 1
active_routes:
  janus_video_store:
    source: default
    route_id: 录像店-默认
  janus_construction: null
```

每个出生点只有一个引用，所以同一出生点不会同时开启两条路线。切换路线时，程序更新该出生点的引用，再一次写入整个文件。

| 条件 | 处理 |
| --- | --- |
| 配置文件不存在，旧版路线目录也不存在 | 按出生点清单的 `initial_route` 初始化。只引用存在且绑定该出生点的默认路线 |
| 配置文件不存在，旧版路线目录存在 | 先迁移旧数据，见[旧版路线迁移](#旧版路线迁移) |
| 配置文件存在，某个已登记出生点没有记录 | 该出生点按不开启处理。新发布的默认路线不改变用户的选择 |
| 配置文件存在，但记录了未登记的出生点 | 忽略该记录，编辑器显示提示 |
| 配置文件损坏 | 报告错误，不重新初始化。正式任务拒绝开始，编辑器的写入操作报告同一错误 |
| 引用的路线不存在、损坏、绑定其他出生点或不能开始 | 该选择标记为无效，不自动换成其他路线。正式任务拒绝开始 |
| 删除开启中的自定义路线 | 先把该出生点改为不开启并写入，再删除文件。不自动开启其他路线 |

路线与开启选择不区分账号，所有账号共用。

## 写入规则

所有写入都经过 `BagelRouteStore`。编辑器、录制器和执行器不自行拼接路径。

- 默认路线只读。保存、改名和删除只接受自定义路线标识；默认路线标识一律拒绝。该检查在 Python 侧执行，不依赖网页隐藏按钮。
- 新增路线时，首点为出生点坐标上的途径点。新增和录制的路线可以选择创建后开启；默认不开启。
- 复制路线生成新的自定义路线：使用新标识和新名称，保留出生点和全部节点参数，初始不开启。复制不改变源路线和当前开启的路线。
- 每次写入先写同目录临时文件，读回核对后再替换目标文件。核对失败时，原文件保持不变。

## 旧版路线迁移

旧版路线存放在工作目录的 `bagel_routes/`，格式版本为 1，带 `enabled` 开关，不绑定出生点。开启选择配置不存在且旧目录中有路线文件时，程序按以下顺序迁移：

1. 把旧目录整体复制到 `config/bagel/legacy_routes_backup/<时间>/`。旧目录本身保持不动。
2. 按下表处理每个旧文件。
3. 写入开启选择。

| 旧数据 | 处理 |
| --- | --- |
| 与某条默认路线同标识，节点相同 | 沿用旧开关：旧文件启用时，开启该默认路线 |
| 与某条默认路线同标识，节点不同 | 另存为自定义路线「原标识-旧版修改」，绑定该默认路线的出生点。旧文件启用时，开启这条自定义路线。默认路线保留 |
| 其他路线，首点只满足一个出生点的开始条件 | 另存为绑定该出生点的自定义路线，名称为原标识。旧文件启用时，开启这条自定义路线 |
| 其他路线，首点不满足任何出生点或满足多个出生点 | 不迁移，只留在备份中，日志列出文件名和原因 |
| 文件损坏或版本不是 1 | 不迁移，只留在备份中，日志列出文件名和原因 |
| 同一出生点有多条旧路线启用 | 该出生点不开启任何路线，日志提示在编辑器中选择。不按文件顺序选取 |

迁移不提供绑定确认界面。未迁移的路线需要用户在编辑器中重新新增或录制。

迁移只在开启选择配置不存在时运行一次；配置写入后不再读取旧目录。比较节点时只比较点位，不比较时间和开关。

更新程序时，旧目录中被 Git 跟踪的 4 条旧默认路线会被删除，所以这些文件的旧开关无法读取。这种情况按首次使用初始化。旧目录中用户自己录制的路线不受 Git 跟踪，更新后仍可迁移。

## 模块分工

| 模块 | 职责 |
| --- | --- |
| `bagel_route_model.py` | 出生点、路线、点、路线引用的数据定义与格式转换，以及路线开始条件检查。不依赖 Qt 或录制器 |
| `bagel_route_store.py` | 出生点清单与路线文件加载、默认路线写入保护、自定义路线保存、复制、改名、删除、开启选择、迁移 |
| `bagel_spawn.py` | 用一次定位结果匹配出生点，区分唯一命中、未命中和多个命中。不截图，不读写配置 |
| `bagel_route_recorder.py` | 游戏内录制。首个点必须满足所选出生点的开始条件，停止后保存为自定义路线 |
| `bagel_route_walker.py` | 识别出生点，执行开启的路线或试跑指定的路线 |

## 已知限制

- 出生识别半径 100 地图像素沿用旧锚点距离，尚未针对出生点识别做实机标定。
- 工地深处没有默认路线。抽到该出生点时，正式运行按没有开启路线处理。
- 迁移没有绑定确认界面，首点无法唯一对应出生点的旧路线需要手动重建。
- 出生点清单只能通过修改 `spawn_points.yml` 维护，编辑器不提供新增或移动出生点的操作。
