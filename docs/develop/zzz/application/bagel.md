# 贝果计划（自动化方案）

> 本文讲怎么自动化贝果计划（脚本流程、配置、前置、设计决策）。
> 玩法见 [gameplay/贝果计划.md](../../../game/gameplay/贝果计划.md)，画面见 [screens/贝果计划.md](../../../game/screens/贝果计划.md)。

**当前范围**：高危雅努斯、零携带、零投资。只跑两条短线：录像店复活点（武备箱后再开电子保险箱）、白鸽工地地铁站复活点（只开武备箱）。其它出生点退出重开，不清理仓库。不投资、不购买。出现在一条龙列表里，排在驱动盘拆解之后、通知之前；已经保存过的一条龙顺序不会被改掉。新加进列表时默认关闭，打开后才和其他日常一起排队。

## 1. 脚本流程

`BagelApp` 从已识别的安全画面进入研究站，循环到成功次数上限（默认 1；填 0 不限成功次数）：

1. 校验配置并读取两个出生地的发布流程快照（`flow.yml`）；旧账号 `bagel_routes.yml` 不再参与正式运行。旧运行记录的 `pending` 不阻止启动。是否可以开新局，以入场时当前画面的零携带核验为准。
2. 已在入口或选图时继续；已在备战时先返回选图，重新选择并核对雅努斯高危；否则只从普通大世界、地图、菜单、快捷手册、普通仓库或达塔对话调用地图传送到奥蒙德研究站「迷宫诡域」。启动时已在达塔前或达塔对话中，也先走通用返回大世界与地图传送，不就地打开入口。传送落地后再识别达塔并交互打开入口，核对高危雅努斯、零携带和零投资。未知画面及其他玩法局内停止留现场。
3. 用小地图认出生点。
4. 录像店复活点：到武备箱 → 开箱 → 装入安全箱 → 到电子保险箱 → 按光圈解锁 → 再装入 → 主动退出 → 入仓，并按开关清理。
5. 白鸽工地地铁站复活点：到武备箱 → 开箱 → 装入安全箱 → 主动退出 → 入仓，并按开关清理。按小地图路点配准导航，不做遇敌恢复。
6. 其它出生点：退出并返回入口，不清理也不计成功局数；没有尝试次数上限。
7. 导航、开箱、入箱、解锁途中出现整局失败结算：退出到仓库，同样入仓并按开关清理，不计成功。结算核验通过后，前两次失败返回入口自动重开；连续第 3 次失败仍先完成仓库结算，再停在仓库。正常有物入仓的成功局将连续失败次数清零；空箱局和非支持出生点不清零。退出、入仓、清理或返回入口失败时直接停止，保留原始错误和现场，不继续重开。
8. 安全箱有物且确认入仓并完成清理（清理关闭时只入仓）后计成功一局；空箱局返回研究站入口但不计数，连续 3 次空箱后停止。正数上限达到后成功结束；填 0 时不按成功次数结束，仍受失败、异常和空箱停止条件约束。入仓、清理失败或清完仍满则停在现场，不继续下一局。

## 2. 设计决策

- **拖拽先按住再移动**：首次入箱、满箱对换和失败后的重拖统一使用 `duration=0.8`、`press_time=0.1`，按下后额外等待 0.1 秒，给游戏时间抓起物品，避免拖成结果列表滚动。等待不缩短原有移动时长；仍须核对拖拽前后两格的变化，不能因已等待就认定入箱成功。控制器默认值和前后台行为见[拖拽按下等待](../../one_dragon/drag_timing.md)。
- **只认两条出生点**：其它点退出重开，不漫游找箱。
- **入场只核对当前携带**：备战页的武备、装备、道具价值必须明确为 0，背包和安全箱必须明确为零占用；非零或识别不清均停止。仓库可以有库存，无需追溯上一局物资去向。正常收集和独立抽出生点都不读取 `pending` 来决定是否入场；原有画面白名单、零投资和本局结算核验继续生效。
- **价值整屏优先、裁图兜底**：先从整屏 OCR 结果中筛选武备、装备、道具的标题条区域；对应标题完整匹配且恰好一段纯数字才采用，否则裁出完整标题条重新识别。裁图优先采用唯一一段纯数字；没有纯数字时，才从唯一一段「1–2 个非数字前缀 + 完整数值」中提取数字。未读出、两段以上纯数字或多个前缀候选均返回空字符串，不能当作零。标题条不只截数值末尾，也不做亮白过滤，避免道具价值 `0` 被读成 `O`。背包、安全箱和投资金额仍直接裁各自的完整区域读取，投资金额保留独立颜色过滤与严格零值校验。
- **出生前确认局内**：入场操作确认雅努斯高危后，出生识别再检查局内喧响值；单帧 OCR 漏识别最多复看 3 帧，持续不符就停止留现场，不算一次出生检查。
- **搜查中拾取**：武备箱或电子保险箱进入「搜查中」后就观察结果格。物品格连续两帧外观稳定才按现有品质与类型顺序拖入空安全箱，每件仍回读核对；箱满时等明确看到「搜索结果」再判断是否对换，避免动画中的角标误判。无可装物品继续等待。只有明确看到「搜索结果」才允许关闭面板、退出局内，不能因安全箱满或暂时没有结果而提前结束。
- **多画面入场边界**：已有贝果入口直接复用；普通大世界（包括达塔前）、达塔对话、菜单、快捷手册和普通仓库统一交给已存在的返回大世界与地图传送流程，传送失败立即停。达塔对话只作为允许传送的已知画面识别，不在启动时点击「出发出发」；达塔交互仅在本次传送后执行，避免为这两个起点保留另一套入场动作。音擎、驱动仓库属于其他应用的局部画面，贝果入口在全局识别失败时只按完整仓库标题补认，不能把普通仓库误当作贝果结算仓库。战斗、其他玩法内部、贝果结算仓库和未识别画面不自动退出或盲点。
- **入箱不按名单**：读格子左右两侧底色认品质（颜色与实拍依据见[画面文档](../../../game/screens/贝果计划.md#格子)），按 `Z > S > A > B > C > 未知` 排序，读左上角标认类型。每次拖一件并回读。材料优先级低于所有非材料，同为材料时按品质排序。金币留在搜索结果，不占安全箱。箱满时，只用严格更优的结果对换箱内优先级最低的物品；材料也可以参与对换，但必须核对拖拽前后两格确实变化。不能换就关面板，不拖进背包，不记失败。同一结果格对换后会留下安全箱换出的物品，即使品质和类型变了也不再对换，避免来回交换。搜查状态偶尔漏识别最多等待 5 帧；正式执行器的收集、关闭步骤入口也遵循这项规则：对应容器标题必须仍在，等待期间不发送输入，状态恢复后才运行子操作；标题不符立即停止。拖拽后的核对也保留原始前后对照等待，不补拖。拖拽核对时标题消失或状态持续漏识别则停止。
- **蓝紫色带分开**：品质识别仍取两侧底色的 HSV 中位数。B 色相为 90–119，A 收窄为 120–160，C 为 50–85；Z、S 色带不变。饱和度或亮度低于 40、未匹配色带时仍返回未知，不用 B、C 兜底。局部实拍测试覆盖 B/C/A 与空格，并验证 B 可换 C、C 不可换 B；完整排序测试覆盖五种品质与未知，原有 Z/S/A 实拍继续回归。
- **角标模板保留完整图案**：从 1080p 实拍重新裁取角标，按图案轮廓选择位置与尺寸；白色图案完整保留且上下左右留白接近，不通过降低匹配阈值弥补裁偏。全部九张模板检查图案边界，并回放局内、仓库截图验证识别。白色箱子的两张实拍模板统一归为材料，未匹配的角标仍按其他处理。来源、尺寸与裁剪坐标见 [贝果画面「格子」](../../../game/screens/贝果计划.md#格子)，实拍识别与裁图回归测试在独立测试仓。
- **入仓看占用，不看物品名**：点「放入仓库」后，安全箱要清空，仓库「全部 N/M」的 N 不能下降；未满仓时堆叠允许 N 不变。安全箱只减少部分格子时立即停止，不能重复点击或继续清理；格子完全未变才按原规则有限重试或判满仓。满仓时安全箱即使清空，若占用仍为 N=M，也不能凭堆叠推测入仓成功。安全箱仍占用且 N≥M 连续 6 帧，记为仓满并停止。安全箱仍有物资时禁止批量出售，保留现场，不再走先清理后入仓。
- **遗留物资禁止开新局**：入场前若仍在结算仓库且安全箱有物资，停止并保留现场；不能借新局或人工恢复把未核对物资计入成功。仓满腾位方式尚未确证，当前保护不等于满仓自动整理已完成。
- **返回时的奖励提示**：结算仓库点「返回研究站」后，若同时识别到「撤离奖励提示」和奖励转移说明，只确认一次，再等待研究站 HUD。
- **清理按方案选**：开关默认开，关时只入仓。默认方案勾贵重物品、战术棱镜、其他和 C/B/A/S，不勾 Z、装备、战术道具、门禁卡、全部。自定义方案可选类型与品质，二者都必须非空；快速选择两组同时勾选才出售对应物品，「全部」始终不选。每次回读所有选项，没选的取消。件数为 0 就确认筛选再取消出售；有件数才走出售预览并确认。不点整理，不点自动转化货币。仅在仓库主界面确认安全箱为空时允许进入批量出售；出售后还要确认安全箱仍空且仓库占用下降，否则不能报告清理成功。仓满且安全箱有物则停下，等待确认游戏出售范围及安全腾位方式。结算末尾用新截图再次核对安全箱为空、仓库占用小于容量；关闭清理或没有可出售物品也必须经过这步，仍满则留在仓库，不计成功、不返回入口。
- **交互看提示条，不看头顶名字**：右侧 F 图标用模板，不用字母识别。交互步骤要求局内 HUD、目标提示和 F 图标同时出现；搜查面板还在时不按。
- **收集只处理当前容器**：正式任务与开发执行共用同一收集行为：搜查完成后保留面板，关闭由独立步骤负责；面板被打断后停止留现场，重新交互须显式执行对应步骤。不再提供收集操作自动关闭、补开武备箱的旧模式。
- **电子保险箱按光圈点**：先看到小圈，再等红圈或黄圈扩到候选半径，每轮只按一次，共 4 次。提示消失就停。四次按完仍要等到搜查面板，不能按次数当成打开成功；搜查结束由逐件入箱流程确认。
- **电子保险箱交互前的 HUD 容错**：仅在按 F 进入解锁前，把喧响值 `UPROAR` 的文字匹配阈值设为 0.8，容忍 `IPROAR` 这类单字错识；仍须同时命中右侧电子保险箱交互提示。正式执行器与保险箱子操作共用这项 HUD 判据，正式入口另外要求 F 图标，避免外层严格检查挡住已有容错。其它调用继续使用画面配置的 0.9，不修改共享区域。已进入解锁或搜查面板时不补按 F。
- **录像店复活点走路**：先到武备箱，不改收集顺序；电子保险箱默认路线为：巷口 `(186.6,84.9)` → 楼角 `(201.6,109.5)` → 接近点 `(213,110)` → 保险箱前 `(218,110)`，删除原贴右墙转折点。巷口仍在 14 像素内切段；楼角在距路点 2 像素内才切下一段，接近点留在墙根。远段按住前进；朝向差 7° 以内不转，不超过 45° 时边走边转（单次最多 30°），再大则停车转（最多 90°）。已贴墙且距最后接近点 6 像素内就松键，等待 0.5 秒后用新截图进入 0.08 秒碎步，给截图延迟和停步前移留出余量。末段只认交互提示，不按终点距离回头；暂时定位失败时也不能因拾取提示恢复按住前进。已经定位成功后，小地图连续 3 帧对不上才停。贴墙和末段停步都要对照录像与小地图轨迹验收，成功开箱不能代替这些要求。
- **贴墙卡位停止**：电子保险箱远段按住前进期间，若配准位置连续 3 秒没有离开 2 像素范围，松键失败并保留现场，不再原地按到导航超时。该防护只限制卡位耗时，不负责自动绕障。暂停时松键并清除卡位计时，恢复后重新校准朝向，暂停时间不计入持续前进时间。
- **小地图色偏与定位**：半透明小地图会透出场景颜色，静止时道路附近的背景也会变化。先将灰度图平滑并做 CLAHE（局部对比度均衡），逐张匹配参考图；完全没有合格匹配时，再用每像素 B、G、R 三通道的最小值生成灰度图，压低彩色背景，按同样流程重试。两种表示分别与同种表示的参考图匹配，不混合特征。补充路径仍要求至少 8 个内点，并保留覆盖面积、缩放、旋转和残差校验；任一路径得到的参考图坐标相差超过 5 像素仍拒绝，不因冲突换路径。
- **白鸽工地地铁站复活点走路**：与录像店共用路点导航，按当前位置到下一路点的方向转向，远处连续前进、近处短步。默认武备箱路点来自实测交互区，可在独立开发工具中修改和插入转折，验收后导出发布资源。正式流程到达最后路点附近并出现武备箱提示才停；到坐标却没有提示会等待后报错，定位不足时松键。

## 3. 配置（`BagelConfig`）

| 字段 | 默认 | 应用是否使用 |
|---|---|---|
| `max_success_rounds` | 1 | 0–1000 的成功局数上限；0 不限成功次数。非支持出生点和失败局不计数 |
| `auto_clean_warehouse` | 开 | 关闭时只入仓；开启时按方案出售 |
| `clean_mode` | `default` | `default` 使用固定组合；`custom` 使用下面两组选择 |
| `clean_types` | 空 | 自定义时的类型，不含「全部」，可选装备、战术道具、门禁卡 |
| `clean_qualities` | 空 | 自定义时的品质，可选 C/B/A/S/Z |

任务配置页与锄大地、恶名狩猎一样使用主窗口内的完整可滚动设置页，通过统一返回按钮回到任务列表。页面随主窗口移动和调整大小，内容超出可见高度时可使用滚轮或拖动滚动条查看；不再使用固定在齿轮旁的浮层。每次进入页面都会重新绑定当前账号与应用组，多选值与说明一起刷新，加载过程不写回配置。贝果专用多选卡片显式使用无信号赋值接口，避免通用适配器误选 Fluent 父类的同名接口；不修改公共卡片行为。“成功次数”（成功局数上限；填 0 不限次数。）和“清理仓库”（成功与失败局入仓后清理仓库）始终显示。清理开启时显示“出售方案”，说明为“默认出售贵重物品、战术棱镜和其他物品的 C–S 品质”；选择自定义时再显示出售类型与出售品质，均须非空。设置自动保存。旧配置里的 `targets_text` 不再读取或写回，也不清理用户配置文件；入箱仍按固定的品质和类型顺序处理。

旧运行记录里的 `collection`（含 `targets`、`pending`）保留，读取文件仍沿用原格式校验；正常收集与独立抽出生点不按其中的未完成状态阻止启动，也不将旧进度算成本次成功局数。记录类只负责应用运行状态、旧文件校验和原子保存，删除旧物资任务建立、入箱入仓记账及停止判断接口。正常状态更新原样保留旧 `collection`，不继续推进其中的任务。旧账号路线仅保留读取和显式导入，不再提供旧格式写入与快照接口；导航使用角色箭头方向，不保留未使用的黄色视野扇区算法及配置。

内置路线和出生参考图在 `assets/game_data/bagel/`。路点表示导航切段位置，截图到松键之间仍可能前移。

### 独立流程开发工具与局部地图

**路线可视化工具仍处于早期 demo 阶段，仅供开发试用，尚不是成熟稳定的工具；离线测试通过不代表已完成实机验收。**

普通贝果设置已移除路线编辑入口。开发者使用源码命令 `uv run --env-file .env python -m zzz_od.gui.view.bagel.bagel_route_editor --instance 1` 打开三栏工具：地图、业务步骤、属性面板。首次试跑才初始化游戏控制与 OCR。完整说明与验收状态见 [贝果流程开发工具](bagel_flow_editor.md)。

- `flow.yml` 是正式业务步骤与路点的唯一运行来源。版本 2 把每个路点移动、靠近目标、交互、解锁、装入安全箱、关闭面板分别作为步骤；旧版本严格校验后在内存拆分，读取不改源文件。显示名称不参与动作派发。`BagelApp` 启动时加载不可变快照，调用与开发执行相同的 `BagelRunFlow`；外层继续负责入场、结算、清理和重开。
- `route.yml` 保留参考图配准参数及旧格式导入所需资料；正式移动步骤不从中取执行坐标。两个出生地坐标独立，出生均为 `(100,100)`，不能拼成世界地图。参考像素覆盖不保证可通行，不提供自动绕障。
- 开发草稿位于 `config/devtools/bagel/`，独立于账号和应用组。保存草稿不影响普通任务；导出正式资源才生成仓库中的 `flow.yml` 变更。两个操作都做完整校验、原子替换和回读。损坏文件停止报错，不静默回退。
- 旧账号 `config/<账号>/bagel_routes.yml` 保留，只在显式导入时读取。路点映射为移动步骤并补齐原业务动作；仅有旧朝向与时长的 B 配置不能还原坐标，工具拒绝导入并提示从发布流程建草稿。
- 地图使用浅色底图，支持缩放、平移、拖点、交互位置选择和轨迹断线；显示到达范围与允许越过路点的范围。每个移动步骤完成后停步，可覆盖到达范围、靠近方式、提前停步距离、交互范围及移动时限；默认值与实际导航共用。
- 开发执行改为勾选哪些步骤就执行哪些，支持不连续选择，始终按列表顺序运行；点击行只编辑，不决定执行范围。每步重新检查画面，不补做未勾选项，没有勾选暂停或断点继续。运行期间锁定草稿与勾选清单，停止及关闭窗口等待线程清理完成。
- 开发工具仅防止当前窗口重复试跑，不与主程序、MCP 或其他工具进程自动互斥。试跑前须停止其他控制端的任务，并等待其结束。
- 贝果正式应用和操作基类为每次执行单独包装暂停、恢复回调，结束时停用订阅、等待已经开始的回调完成，并从运行总线解绑。初始化或收尾异常也走同一清理路径；执行入口返回前完成清理，使旧队列回调不能影响下一次执行。本约束只作用于贝果操作，不改变公共事件总线或其他应用。贝果局内执行器与开发试跑共用输入清理函数，暂停和收尾时重置持续按键，并额外释放定时前进、交互及鼠标拖拽；后台拖拽另向游戏窗口发送左键松开消息。清理不取消正在执行的拖拽循环。

模型、执行与离屏 Qt 测试位于独立测试仓。流程执行器使用真实截图覆盖 HUD 错字、搜查状态暂缺及恢复；贝果操作使用真实事件总线和线程覆盖监听清理、旧事件失效、执行返回前等待回调。应用层覆盖 A/B 发布流程及连续失败结算；各动作的失败透传集中在执行器层，避免对每个路线位置重复跑三局。收集与独立关闭保留真实多帧推进测试，历史定位截图只合并搭建、不减少样本。旧记录加载保存、零携带、禁止误出售和图标完整性测试继续保留。离线通过不等于两个出生地均已完成实机转角、贴墙、停步与交互验收。
