## 1. 脚本流程

`BagelApp` 从已识别且允许启动的画面进入贝果主界面，循环执行到成功次数上限。默认上限为 1，设置为 0 时不限制成功次数。

1. 校验配置和路线开启选择。开启选择无效，或没有任何出生点开启路线时，任务不开始。规则见[贝果路线与出生点](bagel_route_storage.md#开启选择)。
2. 首次启动时若在贝果仓库，先转存携带物，再返回上一页。该转存不主动出售；满仓或残留按一次出售重试处理，不增加任务计数。随后按[快捷手册入口规则](bagel_speedup.md#快捷手册入口与局间返回)准备首次入场；正常后续轮次复用贝果主界面。各起点的处理规则见[入场与携带核验](#入场与携带核验)。
3. 选择并核对雅努斯高危，进入备战页。
4. 核对当前画面的零携带状态。首次入场可以先清空非零携带，再复核零携带。后续各局发现非零携带时停止。
5. 核对零投资并入场。
6. 用小地图识别出生点，执行该出生点开启的路线，按游标顺序推进。识别规则见[出生识别与导航](#出生识别与导航)。
7. 主动退出到仓库（结算后若弹出拟态单质提示，先点确认，见[退出与结算提示](#退出与结算提示)），核对安全箱物资入仓，再按清理开关处理仓库。
8. 核对结算结果，更新成功局数，决定结束任务或开始下一局。

正常完成链为「执行局内流程 → 正常局退出 → 结算仓库 → 成功局返回入口」。只有路线执行器明确返回「路线走完」，才能进入正常局退出；其它成功状态按提前结束处理，不计成功。正常局退出先释放输入，再调用退出操作确认到达结算仓库；退出失败时停止，不继续入仓或开启下一局。

打点路线按点类型执行：途径点是纯路点，3px 内算路过；箱类点按距离慢步或碎步靠近。当前目标是电子保险箱时，进入目标点 15px 半径后保持 0.08 秒短步。可信提示出现后松键，再按类型交互：电子保险箱执行光圈解锁，机械保险箱长按 F，普通箱子和门点按。每局只执行一条路线。路线结束并完成末尾现场判断后，进入退出结算；执行器不衔接其他路线，也不朝其他出生点移动。导航只按坐标移动，不提供遇敌恢复。

**电梯点。** 电梯点是唯一不按「到达」判定的点：小地图在进电梯时会整块消失，坐标与朝向都读不到，3px 之类的到达判据在电梯口根本不成立。执行分四段，见[电梯进出](#电梯进出)。

出生点不在已登记范围内，或该出生点没有开启路线时，走非支持出生点那条退出重开的路：退出本局、返回入口、重新入场，不计成功、不消耗整体重试次数。出生点识别没有稳定结论时，按失败局收尾，消耗整体重试次数。开启的路线在运行中被发现无效时，任务停止。

寻路卡位、定位失败、局内步骤或操作超时、被敌人击杀、容器恢复失败、装入安全箱无法安全继续（面板状态不明、连续两件物品搬不动），以及搜查或解锁中断，均进入失败收尾。正式应用释放输入、记录原因和截图，再根据新画面退出到仓库。核对安全箱入仓并按开关清理后，正式应用才决定是否消耗整体重试次数重开。次数耗尽时，应用仍先完成结算，再停在仓库。失败局不计成功。详细规则见[整体重试说明](bagel_failure_retry.md)。

| 结算结果或配置 | 计数和后续动作 |
| --- | --- |
| 正常完成局，安全箱有物，已确认入仓并完成清理 | 增加 1 个成功局数。清理关闭时，只需完成入仓和结算核验 |
| 失败局，即使安全箱有物，已确认入仓并完成清理 | 不增加成功局数 |
| 安全箱为空 | 跳过出售，仍核对安全箱为空且容量可读，满仓也允许返回入口；不增加成功局数。连续 3 次空箱后停止 |
| 成功次数上限为正数，且已达到上限 | 任务成功结束 |
| 成功次数上限为 0 | 继续执行，仍受失败、异常和连续空箱停止条件限制 |
| 入仓失败、清理失败、再入仓后仍有残留或状态不明 | 停在当前画面，不开始下一局 |

## 2. 设计决策

### 运行日志

贝果应用与子操作按以下规则记录文本日志，节点返回值、重试次数、执行时序和开发工具事件保持原行为：

- 同一操作内，节点、来源节点、等待状态和附带数据均相同时，只打印第一次等待。持续收到相同等待时，每隔至少 5 秒汇总观察次数和时间跨度；状态变化、操作退出、超时或人工停止时补齐尚未输出的汇总。不同操作实例不共用计数。
- 重试、成功、失败逐次输出，重试带当前次数和上限，附带数据有值时一并记录。异常堆栈、截图路径、动作与识别变化不按等待去重。
- 通用操作只提供日志扩展入口，默认输出保持原样；贝果只合并自己的等待。不修改全局日志等级或过滤 OCR 日志，开发工具的逐轮调试事件仍按原机制发送。
- 出生点重选规则在任务启动时说明一次，每局只写入场序号、识别结果和后续动作。任务结束汇总入场、成功、失败结算、连续空箱、整体重试和返回位置。
- 局内流程记录步骤序号、名称、动作、结果和耗时。重复的前置检查不重复报告步骤开始；导航 INFO 保留完整路线快照并补充目标、重新靠近标记，坐标、容差等原有配置不删减。流程原始配置另写 DEBUG。
- 物品识别首次输出完整列表，后续只输出新增、变化和不再参与当前识别的格位；保留种类、品质及未知值。入箱日志记录源格、目标格和对换双方物品。
- 启动转存记录双击对象、坐标和携带读数；批量入仓记录背包、安全箱和仓库的前后占用。出售日志记录触发原因、步骤顺序、实际筛选项、命中数和出售后的仓库／安全箱占用变化。数量来自界面识别，不把筛选命中数直接当作已出售数。

文本汇总保留相同等待的总次数和首末观察跨度；跨度包含中途暂停，不等于连续发送输入的时长。不逐条重复相同轮询；需要每帧时间和定位坐标时使用已有调试事件与 DEBUG 输出。图像识别、搬运和出售的验收范围不因日志改动扩大。

### 收益统计

收益统计只写日志和任务结束推送，不参与流程判断；读数失败只记为「未读到」，不影响装箱、退出和结算。实现见 `bagel_stats.py`。

**一局的范围。** 一局从「零携带入场」开始，到返回入口结束。结果分为成功入仓、空箱、失败局、非支持出生点和未完成。每局结束输出一行「贝果本局统计」，含结果、调查收益、本局用时和本局红色物品。

**调查收益。** 本局调查收益取最后一次读数。零携带入场时记为 0，之后按以下时机更新：

1. 路线执行器每次关闭搜查面板后，读局内 HUD 背包图标旁的数字（区域「调查收益」）。游戏只显示到 0.1K。
2. 装箱或关闭面板失败时，路线执行器先补读一次，再按原失败原因结束本局：
   - 已回到局内（看得到普通攻击按键）时，读 HUD。连续两帧读数相同才采用，以避开涨幅浮字刚出现时的错读。搜查被打断时面板已关闭，走这一条。
   - 面板仍开着时不读。底栏数字左侧的金币图标会被 OCR 读成「9」，错值每帧相同，连续两帧相同也挡不住，见[收益读数](../../../game/screens/贝果计划.md#各画面要点)。
   - 已是 DEFEAT 画面，或 3 秒内读不到稳定读数时，不更新。
   - HUD 数字上方可能浮出涨幅（如 `+10K`），OCR 读不出浮字前的「+」，所以只取读数区域最下面一行。
3. 正常退出前，应用再截一张新图读 HUD。

读不到时沿用上一次读数。失败局在结算画面上读不到 HUD，用失败前最后一次读数，所以还没开始装箱就失败的局记为 0。装箱中途失败且没有补读到稳定读数时，读数不含这一箱已入箱的物品，比实际偏低。非支持出生点记为 0。不读取退出后结算画面的精确收益，以免等待滚轮数字停稳。

**红色物品。** 只统计红色（Z 品质）物品，按类型汇总件数。类型用装箱时的格子识别结果，蓝图单独作为「蓝图」类型。账本按以下顺序更新：

1. 拖拽发出前，登记拖入的类型和品质。
2. 确认入箱后，把该安全箱格换成这件物品，数量记为未知。
3. 装箱正常结束后，按画面重读安全箱各格的类型和品质；只对红色格子读下方数量，装备显示的「Lv.50」按 1 件计。

装箱中途结束时，账本保留第 2 步的结果。数量未读到的红色物品按 1 件计。

**任务总表。** 任务结束时输出「贝果收益统计」：

- 局数：按结果分别计数。
- 用时：任务开始以来的时间，扣除用户暂停，包含出售、非支持出生点和返回入口。
- 调查收益合计：所有局相加，失败局也计入。调查收益没读到的局不计入合计，单独标出局数。
- 每小时：调查收益合计 ÷ 用时。
- 红色物品：所有局相加，失败局也计入。

**出售所得。** 关闭「获得」弹窗前读齿轮硬币数（区域「出售获得数量」），为精确值。出售会连同已有库存一起卖，所得只写日志，不摊到每局，也不进推送。

**用时。** 用时按程序节点切换计时，并扣除用户暂停的时长：正式应用在暂停回调里停表，恢复回调里继续。

**结束推送。** 贝果计划出现在「通知设置」里，按本应用的节点通知设置推送一条收益摘要：成功和失败局数、用时、调查收益合计、每小时收益和红色物品。异常停止时，摘要第一行写停止原因的第一段。推送不附截图。

正常结束和异常停止可能发生在任一节点，单个节点的 `@node_notify` 无法覆盖，所以摘要在应用的 `after_operation_done` 里发送，规则与节点通知相同：

| 节点通知设置 | 摘要的发送方式 |
| --- | --- |
| 关闭 | 不发送 |
| 仅失败 | 只在异常停止时立即发送 |
| 逐条 | 立即发送 |
| 合并 | 放进通知池，由框架在应用结束时和结束通知合并发送 |

用户手动停止时不发送摘要，与其他应用一致：框架只发送生命周期结束通知「运行失败」。

**已知限制。** 失败局退出后安全箱物品是否全部保留，尚未核实；失败局的收益和红色物品可能偏高。红色物品数量和推送尚未经实机核对。

### 路线数据记录

路线数据记录用于判断每个出生点跑路线好，还是直接重开好。它跨任务累计每局数据，在任务结束时按出生点输出汇总表。它只写本地文件和日志，不推送，不参与流程判断。实现见 `bagel_route_stats.py`。

**记录。** 每局返回入口后，程序向 `.log/bagel/route_records.jsonl` 追加一行 JSON。规则如下：

- 所有实例写同一个文件。路线好坏与账号无关。
- 未完成的局（任务在局中停止）不写。
- 写入失败只记一条警告。
- 不设开关。
- 每次启动任务时，删除 7 天前的记录和无法读取的行。

一行的字段：

| 字段 | 含义 |
| --- | --- |
| `version` | 记录格式版本，当前为 1。字段含义变化时递增，旧版本的行在清理时删除 |
| `ended_at`、`instance` | 局结束的本地时间；实例号 |
| `map_id` | 地图。取识别到的出生点所在地图；不在已登记范围内时取定位所在地图；入场后没有定位成功时为 `null` |
| `spawn_id` | 出生点标识；不在已登记出生点范围内时为 `null` |
| `route_source`、`route_id`、`route_name`、`route_version` | 本局执行的路线；没跑路线时都为 `null` |
| `outcome` | 成功入仓、空箱、失败局、非支持出生点 |
| `seconds` | 本局用时，与收益统计相同：已扣除暂停，包含本局触发的出售 |
| `income` | 本局调查收益，与收益统计相同；没读到为 `null` |
| `red` | 红色物品，按类型记件数 |

路线版本是路线点内容的 8 位摘要。点的坐标、分层、类型或顺序改变时，版本也改变；只改名称时，版本不变。

**汇总表。** 任务结束时，程序读取近 7 天的记录，按地图输出「贝果路线数据」。任务中途停止时同样输出。本次任务没有写入记录时不输出。每张地图先输出一行全局数据，然后每个已登记出生点各输出一行：

- **全局每小时收益**：近 7 天内调查收益已读到的局，调查收益合计 ÷ 用时合计。包括所有出生点和以前的路线设置。
- **直接重开用时**：结果为「非支持出生点」的所有局的平均用时。所有出生点共用这个值。
- **开启了路线的出生点**：只统计当前开启的路线的当前版本。该行列出以下内容：
  - 局数；
  - 成功率：成功入仓局数 ÷ 局数；
  - 每局收益和每局用时：只用调查收益已读到的局计算平均值，没读到的局数在行末标出；
  - 额外每小时收益；
  - 结论。
- **没有开启路线的出生点**：列出直接重开的局数和平均用时。
- **「未登记」**：出生点不在已登记范围内的直接重开局。有这类局时才输出这一行。

失败局计入路线的局数、成功率和平均值。失败局的收益取失败前最后一次读数；还没开始装箱就失败的局，收益为 0。规则见[收益统计](#收益统计)。

**判据。** 跑路线和直接重开都要入场、识别出生点、退出和返回入口，两者只差跑路线那一段时间。直接重开时，这段时间用于开后面的局，平均每小时可以获得全局每小时收益。因此按下式计算：

> 额外每小时收益 = 路线每局收益 ÷（路线每局用时 − 直接重开每局用时）

| 结论 | 条件 |
| --- | --- |
| 样本不足 | 收益已读到的局少于 5 局 |
| 无法判断 | 近 7 天没有直接重开的局，或路线每局用时不比直接重开长 |
| 保留 | 额外每小时收益高于全局每小时收益 |
| 建议关闭 | 额外每小时收益不高于全局每小时收益 |

只看路线自身的每小时收益（每局收益 ÷ 每局用时）会低估路线：这个算法把入场、识别和退出的时间也算成了跑路线的成本。

**出售用时。** 出售发生在触发出售的那一局的结算里，计入该局用时，不单独扣除。只有入仓局会累计出售次数，直接重开的局不会触发出售。因此平均来看，出售用时按入仓局数分摊到各条路线。样本少时，出售会增大用时的波动。

**已知限制。**

- 以下两个前提尚未验证：各出生点直接重开的用时相同；出生点均匀随机出现。
- 所有出生点都开启路线时，没有直接重开的样本，所有路线都显示「无法判断」。要取得直接重开用时，可在 `config/bagel/route_settings.yml` 里暂时关闭一个出生点的路线。
- 全局每小时收益包括近 7 天内以前路线设置下的局。修改路线设置后，旧的局要过 7 天才会全部移出统计范围。
- 汇总表的门槛和判据尚未用实机数据核对。

### 入场与携带核验

先按[首次启动恢复](bagel_start_recovery.md)处理遗留局和物资，再按[快捷手册入口规则](bagel_speedup.md#快捷手册入口与局间返回)准备入口，最后核对地图、难度、五项携带读数和投资金额。普通大世界、地图、菜单、快捷手册、普通仓库与达塔对话共用通用返回和地图传送。

音擎仓库和驱动仓库的全局识别失败时，入场操作用完整仓库标题补充识别。区域缺失时跳过该项，不将普通仓库当作贝果结算仓库。地图传送失败时停止。

首次清空资格、读取上限和后续局残留保护只在[启动清空](bagel_clear_loadout.md)维护。入场的选图与暂停规则见[等待规则](bagel_speedup.md)。

单代理人可以入场，不要求补齐队伍。核实零携带后，程序按关键片段识别已知入场提示，识别成功才点击确认。确认后继续核对其他入场提示和零投资，不跳过地图、携带或投资检查。未知提示仍停止，不点击确认。

识别前，程序删除提示中的空白和标点。一条提示的全部片段都命中，才算识别成功。片段的字按顺序出现在提示中即为命中，中间可以夹有其他文字。五个字及以上的片段允许 OCR 错漏一个字，四个字及以下的片段必须完整。

| 提示 | 游戏原文 | 识别片段 |
|---|---|---|
| 代理人队伍未满编 | 代理人队伍未满编，是否继续出战？ | `队伍未满编` |
| 零装备价值 | 当前装备价值为0，未达到推荐价值258000，将会面临极大挑战，是否继续前往？ | `当前装备价值为0`、`未达到推荐价值` |
| 未装备武备 | 存在未装备武备的代理人，是否直接出战？ | `未装备武备` |
| 未穿戴队伍装备 | 未穿戴队伍装备（异体刃、抗蚀器），是否直接出战？ | `未穿戴队伍装备` |

零装备价值提示中的推荐价值随难度变化，留档的非高危提示显示 72100。程序取提示中最长的数字串：数字串有四位及以上、并且与高危推荐价值相差两位及以上时，按未知提示停止。数字串不足四位时不判断难度，难度以选图页的核验为准。

入场提示按阅读顺序拼接文字识别（OCR）结果。程序先按文字框中心高度排序，再按通用规则将中心高度相差不超过 5 像素的片段合为一行，行内从左到右拼接。这样可避免同一行文字框的轻微高度差颠倒句子。拼接保留全部识别文字，不改变金额和容量的读取方式。

### 价值读取

武备、装备和道具分别在完整标题条中定位金币，再识别标题与金币右侧的完整金额。金币位置随金额长度移动，不能用固定横坐标裁掉金额高位。金币定位沿用投资页的颜色、尺寸和唯一候选判据；备战标题条允许金币左侧有标题，通过标题与金额的位置关系区分两者。

读取顺序如下：

1. 在每个标题条中按金黄色、尺寸和面积定位唯一金币。图标缺失、候选不唯一、扩边越界或分隔区出现白色内容时，该项返回未知。
2. 在截图副本上遮挡金币及其边缘，保留标题、完整金额和原输入尺寸。先识别右侧面板；文字框面积超过 70% 落在某标题条内时，才归入该区域。
3. 对应标题必须位于金币左侧，金币右侧必须只有一段完整纯数字金额。OCR 文字框含有空白，可以向左伸入已遮挡区，但不能越过遮挡区左边界。程序在遮挡后的文字框内检查白色像素：必须存在可见内容，且最左白色像素不得位于遮挡区右边界以左。这项检查不改变 OCR 输入，也不扩大遮挡范围。标题、金额或位置关系不明确时，依次改用遮挡后的完整标题条和整屏识别。所有阶段都使用遮挡后的像素，不回退到带金币的金额识别。
4. 所有阶段均失败时，该项保留空字符串。候选金额为零时，只要已执行阶段的金额文字存在非零证据，也返回未知。两个独立数字框不直接拼成金额；含字母或标点的金额不剥去前缀后放行。
5. 完整 ASCII 数字统一解析为整数。`0`、`00`、`000` 均表示零；`01`、`100` 仍为非零。非零携带继续拦截，缺失或冲突继续按既有预算重读。

金币从图像中排除后，不再把原图中落在金币位置的误读当作金额证据。其他位置的非零或跨边界文字不能忽略。未知诊断记录金币定位结果、各次识别文字与拒绝原因；入场失败日志同时记录五项实际读数。

价值读取不使用整条亮白过滤，避免改变数字轮廓。背包和安全箱仍各自读取完整容量区域，保留原有格式与零占用约束；`00/15` 不因价值解析调整而自动视为空背包。投资金额继续使用独立的颜色过滤和严格零值校验。

不同金币高光、金额长度和连续入场次数的实机覆盖范围尚未全部明确；离线图片识别不能替代实机验收。

### 投资金额归零

识别到投资页后，先在完整金额区域定位唯一金币，并遮挡金币及其左侧，再按区域颜色过滤读取金额。遮挡保留原始输入尺寸，边界随金币位置移动，避免固定裁剪截断长金额。金币缺失、候选不唯一或金币左侧仍有白色数值时，返回未知，不按零放行。

操作读取完整金额后决定动作：

| 读数 | 动作与完成条件 |
| --- | --- |
| 正整数，或带 `K/M` 的正数，如 `500K`、`1.5M` | 点击 MIN。点击成功后等待 1 秒，下一轮重新截图读取金额 |
| 初始金额或复核金额精确为 `0` | 点击「前往空洞」。点击成功后，才记录投资已确认 |
| 空值、`O`、`00` 等不明确读数 | 只重新读取，不发送输入 |

点击 MIN 成功不表示金额已归零。非零归零和读数不明共用 3 次重试预算。MIN 未识别或点击失败也消耗 1 次。预算耗尽后，操作再读 1 帧。金额仍不是 `0` 时，操作停止并保存现场。

投资重试预算单独记录，避免节点等待重置框架重试次数。重复执行时，预算清零。点击入场后，操作不重复归零或确认。

### 出生识别与导航

**出生点识别。** 路线执行器的第一个节点识别出生点，期间不移动角色：

1. 每轮用新截图定位一次，在全部已登记出生点中匹配。匹配条件是同一地图，且距离不超过该出生点的识别半径（当前均为 100 地图像素）。
2. 连续 2 次新截图得出相同结论，才采用该结论。定位失败会打断连续计数。
3. 命中多个出生点时，等待下一帧，不任取一个。
4. 从识别开始 10 秒内仍没有稳定结论时，识别失败。

匹配对象是全部出生点，不先排除没有开启路线的出生点。否则角色站在没有路线的出生点时，可能被错判为附近另一个有路线的出生点。

| 识别结论 | 正式运行 | 试跑 |
| --- | --- | --- |
| 不在任何出生点范围内 | 退出重开 | 试跑结束，说明没有可执行路线 |
| 命中出生点，该出生点没有开启路线 | 退出重开 | 不适用：试跑使用指定路线 |
| 命中出生点，路线首点不满足开始条件 | 任务停止，报告路线配置无效 | 试跑失败 |
| 试跑路线绑定的出生点与命中出生点不同 | 不适用 | 试跑失败，说明角色所在出生点 |
| 命中出生点，路线可以开始 | 从路线第 1 点开始 | 从路线第 1 点开始 |

路线开始条件见[路线能否开始](bagel_route_storage.md#路线能否开始)。每局识别出生点时读取一次路线，形成本局快照；执行中编辑路线不影响本局。不做「就近接入」：从路线中段甚至终点接入会把前面的路段整段跳过。不漫游寻找箱子。

**出生前确认局内。** 入场操作确认雅努斯高危后，出生检查再次识别普通攻击按钮。单帧模板漏识别时，最多复看 3 帧。持续不符时，出生检查结束并进入[失败收尾](bagel_failure_retry.md#失败收尾)，不计一次出生检查。已确认零投资的入场若在加载期间出现高危死亡结算，也由出生检查进入失败收尾。

**分层小地图定位。** 出生识别、路线执行和网页编辑器共用分层底图，坐标为跨层可比的全局坐标，详见[分层小地图说明](bagel_fixed_map.md)。旧 C 路线已转换为当前打点格式，点位、坐标转换依据和适用限制见[C 路线说明](bagel_c_route.md)。

定位丢失时立刻停步：继续按着前进会走到不知道哪里去，恢复定位后再接着走。连续 10 秒定位失败才判失败，给分层定位的全层搜索留时间。导航不提供自动绕障。

**导航等待截图与局内 HUD。** 局内 HUD 指游戏中的常驻状态和操作按钮。输入已经交给独立的输入线程，投递立刻返回，所以导航每次决策前要确认上一动作真的落地了：

| 条件 | 处理 |
| --- | --- |
| 转向或即时动作仍在执行（`idle()` 为假） | 不重发输入，每 0.02 秒再观察；此状态不表示前进短按已结束 |
| 动作后的截图尚未更新 | 每 0.05 秒等待新截图，不重发输入 |
| 前进短按尚未结束，或截图不晚于实际松键时刻 | 每 0.02 秒继续观察，不开始下一步；定位丢失、到点或可信提示出现仍可取消当前短按 |
| 识别到暂停菜单的「退出战斗」 | 立即松开前进键，报可恢复失败 |

单帧没识别到普通攻击按钮不松前进键：长距离行进时某一帧模板没命中就松键，表现就是走两步停一下。只有确认暂停菜单才算中断。等待不消耗节点重试次数，但仍受当前导航步骤的整体时限限制。

**输入独立成线程后的时序代价。** 投递即返回带来一个新问题：动作刚下发，画面还没变，此刻截图读到的是动作之前的状态。所以「转向落地」和「动作后的新截图」两个等待不能省，省掉会一直对着旧画面做决策，表现为反复转同一角度、反复点同一格。

**打点路线导航。** 途径点是纯路点：3px 内算到点并推进游标，10px 内改用慢步。普通箱、机械保险箱和门沿用原距离分段：3px 外慢步，1.9–3px 碎步，小于 1.9px 且没有可信提示时原地等待。

电子保险箱以当前路线点坐标为圆心，首次进入 15px 半径时取消尚未结束的长步，转入 0.08 秒短步。该状态保持到当前点结束，定位暂时回到 15px 外也不恢复长步。3px 外继续按目标方向纠偏；1.9–3px 内沿用不转向的短步；小于 1.9px 且没有可信提示时原地等待。切换点位后清除短步阶段状态。判定只针对当前目标电子箱，不扫描附近其他箱子。

各类容器仍可在 40px 采信范围内识别到可信提示后结束接近。执行器取消移动并转入交互，不要求电子箱先进入 1.9px，也不增加固定停稳等待或多帧停稳复核。15px 是短步切换半径，不是开箱距离；提示可能在到达目标坐标前出现。实际停步位移、开箱站位和受击情况仍需实机核对。

导航与碎步节点共用同一移动判定。远处提示不会跳过移动、定位缺失处理或单点超时检查；未取得当前定位时，不用历史坐标确认交互。两种移动节点统一以「提示已出现」转入按类型交互，避免状态名称不一致导致路线提前结束。

转向一次转到目标角度（`TURN_FRACTION` 为 1.0），向下取整、不足 1 度补 1 度，1 度内算对准，实际下发角还要按 `turn_ratio` 校准值换算。束角 10 度：偏差在 10 度以内不松前进键、边走边微调；超过 10 度先松键停车转，转到位再走——同时下发大角度转向和前进会互相干扰，表现为原地乱转。30px 外按住前进并每轮点一次闪避维持冲刺；进入 30px 内松键改走路，没有停稳缓冲。

慢步单次按压 0.5 秒，投递后每 0.1 秒重新观察；短步单次按压 0.08 秒。两者都要求当前短按结束，并取得实际松键后的新截图，才允许下一步；节点等待时间不表示按完后另停相同时长。3px 内不按坐标纠正角度，该近点阶段仍单独计时 5 秒，超时跳过当前点。电子箱在 3–15px 内的短步不计入这 5 秒，仍受箱类单点 75 秒与输入次数上限约束。途径点单点时限为 45 秒。原地等提示 1 秒无提示也跳到下一个点。导航参数见[开发工具](bagel_flow_editor.md)。

**贴墙卡位停止。** 持续前进但窗口内位移不足 2px 满 3 秒时，导航松开按键、报告失败并保留现场。该检查仅限制卡位耗时，不提供自动绕障。

暂停时，导航松开按键并清除卡位计时。恢复后，导航重新校准朝向。暂停时间不计入持续前进时间。

### 输入线程与动作打断

全部按键由 `BagelInputWorker` 单独下发，执行主线只投递、不等返回。原来「按下并保持一段时间」在主线上 `sleep`，睡的那段时间既不截图也不决策，走路就不跟手。

**三条通道，互不打断。** 分成三条是为了让它们能同时进行，而不是排队互相顶掉：

| 通道 | 语义 | 打断规则 |
| --- | --- | --- |
| 前进／后退（状态） | 只记「该不该按住」，线程把真实键位对齐到意图 | 重复调用无副作用，后一次意图直接覆盖前一次 |
| 转向（互斥） | 相对位移，一次转到位 | 上一条还在转时新请求直接丢弃，不排队也不叠加 |
| 即时动作（队列） | 点按 F、点屏幕中间、长按／松开 F、闪避、侧移 | 按顺序执行，不插队 |

三条通道各自独立，所以转向永远不会把前进顶掉——两者共用一个通道时曾出现转向期间前进被顶掉、人物原地不动。转向用「丢弃」而不是「排队」，是因为它是相对位移：排队会越积越多一路转过头，叠加则会拼命转。

**快速响应带来的两个坑。** 投递立刻返回之后，主线几乎在同一瞬间就会截图，此时画面还是动作之前的：

- 转向下发后要等约一帧（`TURN_SETTLE`，0.02 秒）再放开忙状态，否则会读到转之前的朝向，下一轮再转一次同样的角度。
- 冲刺前要先补按前进键。前进键由通道线程每 10 毫秒对齐一次，`hold_forward()` 返回时键还没真按下；这时立刻点闪避，游戏先执行静止闪避，再按前进就表现为「先退一下再走」，看起来像在按 S。

**定位丢失与败退。** 导航定位丢失后先松键，并核对是否已经出现 DEFEAT 结算。确认结算时直接报告「贝果撤离失败」，交给应用的失败局退出和入仓流程，不再等待定位恢复。尚未到结算画面时，仍按原规则等待定位，连续 10 秒失败后停止移动。该判断不提供战斗或避敌能力。

**持续前进的输入计数。** 从停止或短按切换为持续前进时，执行器记一次输入。已经持续按住 W 时，后续保持请求不重复计数，也不更新输入时间。否则长路段即使持续接近目标，也会因观察次数多而耗尽单点 100 次输入额度。转向和新短按仍各自计数；单点超时和卡位检查继续生效。

**前进短按。** 前进线程同一时刻只接受一个短按，从实际按下 W 后开始计时，到期后松键。短按尚未完成时，新短按请求被拒绝，不排队、不延长。持续前进和停止请求会取消旧短按的截止时刻；不再为每个请求创建独立定时器，避免旧定时器松开后续输入。执行器按实际松键时间判断下一张截图是否可用于发起新短按。切换到短步阶段时，先取消旧长步；短步期间仍持续截图，允许到点、定位丢失或交互提示出现时提前停止。

**停止。** 退出路径统一调 `shutdown()`：取消未结束的短按，停三条通道并显式释放 W、S、F。暂停时取消前进短按并松开前进与后退，不打断正在执行的即时动作。

### 容器交互与解锁

**交互提示识别。** 交互步骤使用右侧目标提示条，并用模板识别圆形 F 图标。箱子头顶名称不能作为交互依据。局内 HUD、目标提示和 F 图标必须同时出现。搜查面板仍在时，操作不按 F。

**局内判断复用普通攻击按钮。** 入场、出生识别、导航、容器交互、搜查中断和退出，均使用 `战斗画面/按键-普通攻击` 的既有模板和阈值，不读取左侧计分文字。

电子保险箱必须匹配对应交互提示，正式执行器还要求 F 图标。普通武备箱缺少攻击按钮时，操作等待。确认攻击按钮和交互提示后，操作才按 F。已处于解锁或搜查面板时，操作使用对应面板的判据，不补按 F。

**打点路线交互分派。** 碎步移动与导航移动共用同一套提示识别：取最上面一条提示（按 F 生效的目标），按图标与条目文字分类。可信提示出现后松键并转交互，不另做停稳复核。电子保险箱执行光圈解锁；机械保险箱长按 F，面板一出就松手，后面与普通箱走同一套收集，面板用底部共用的安全箱标记确认；普通箱子、门、刷卡处点按 F。电梯点不走这套分派，见下节。

**路线末尾现场交互。** 路线走完后，执行器原地观察交互提示。现场交互节点首次识别到类型后，保留该类型直到本次交互结束。按 F 后提示消失时，仍调用已保存类型对应的结果检查；公文包等普通容器识别到搜查面板后转入收集入箱，机械保险箱继续检查长按结果，门和刷卡处沿用提示消失的完成判据。不能在分派结果检查前重新要求场景提示存在，否则面板打开后会持续消耗提示重试次数。完成交互或切换点位时清除类型，下次现场交互重新识别。路线末尾的连续开箱、收集与退出结算尚未完成实机验证。

### 电梯进出

电梯点是唯一不使用到达判定的点类型，由独立的「进出电梯」节点处理，不经过普通导航。点调度遇到 `elevator` 类型的点时直接交给它，不会落到导航移动或碎步移动。

**为什么不能用到达判定。** 进电梯后小地图整块消失，全局坐标和镜头朝向都读不到。贴墙、扇形遮挡也会让定位失败，所以定位失败不能当进电梯的证据；反过来，电梯口也凑不出 3px 这种精度。唯一可靠的信号是**读不到镜头朝向**（`player_angle()` 返回 `None`），这一点由需求方确认，不能替换成 `locate()` 返回 `None`。

**四段流程。**

1. **进门**：朝电梯点走，途中持续读朝向。一旦读不到朝向，立刻松前进，视为已进入电梯，不判到达、不推进游标。定位暂时缺失但朝向还在（贴墙）时不松前进，等下一帧。走满 10 秒还没进电梯按失败处理——这一段还在场景里，失败后能正常退出游戏。
2. **等选项**：一直点屏幕中间推进对话，直到配置的楼层文字在「电梯选项」区域被 OCR 匹配到。不设超时。
3. **点选项**：一直点匹配到的那个选项，直到它从画面上消失。不设超时。
4. **出梯**：按点上的出梯方向（`elevator_exit`，`forward` 前进 / `backward` 后退）一直按住，直到重新读到朝向（小地图回来）。不设超时。

第 2、3、4 段一律不设超时：此时角色在电梯里，界面被对话框占住，超时判失败也退不出游戏，只能干等。所以这三段只认各自的信号，信号不来就一直做。

**电梯点的字段。** 只有 `kind` 为 `elevator` 时才会写入 `elevator_option`（楼层文字，空串表示这电梯没有选项、直接进门）与 `elevator_exit`（`forward` 或 `backward`），其它类型的点即使带了这两个字段也会被清空。字段在网页路线编辑器里编辑，见[流程开发工具](bagel_flow_editor.md#电梯两项参数)。

**节点接线约束。** 导航移动在途径点判定到点后必须回到点调度重新按类型分派，不能直接自环回导航移动：此时游标已推进到下一个点，那个点可能是电梯或箱子，直接自环会让电梯点落进箱类的慢步分支，被当成箱子逼近，永远进不到进出电梯节点。

**旧步骤执行器的容器恢复。** 旧 `flow.yml` 步骤执行器的停稳确认、补按 F 和重新靠近规则见[容器恢复说明](bagel_container_recovery.md)。打点路线执行器使用本节的提示交互规则，不执行旧步骤执行器的停稳复核。

**电子保险箱光圈解锁。** 正式流程连续执行开箱 F 和光圈解锁。发送开箱输入后，操作立即观察界面，不等待独立步骤交接。确认解锁界面的同一张截图也用于观察光圈。界面出现时，操作记录交互完成并开始解锁。解锁失败归入解锁阶段，由整体失败重试收尾。

开发工具仍按勾选项独立执行交互和解锁。草稿格式和步骤标识保持原样。

光圈操作先观察小圈，再等待红圈或黄圈扩至候选半径。每轮只按 1 次，共 4 次。解锁提示消失时，操作停止输入。完成 4 次点按后，操作仍需等到搜查面板出现，才能确认解锁成功。等待期间，电子保险箱标题和解锁提示均消失、普通攻击按钮持续出现在跨度至少 0.5 秒的新截图中时，报告解锁中断，交给正式应用失败收尾。单帧局内画面先复核；解锁或搜查特征恢复、画面不明时清零中断确认。搜查完成由逐件入箱流程确认。

连续执行消除了固定等待和重复观察造成的空档。开箱按键时长和光圈阈值由当前操作实现定义。当前实现没有首轮晚进入补偿，也不识别游戏进度。

**光圈验证范围。** 离线回归覆盖首张小圈只出现 1 次时参与判断、完整 4 轮解锁，以及中断后停止输入。连续开箱时首圈的命中率尚未确认。

### 收集与对换

**容量识别。** 当前画面保留 5 个显示位置，但可用容量由每格状态决定。识别返回占用格、可用空格和锁定格，保留原显示下标；实际容量为占用格数与可用空格数之和。填空只使用可用空格，对换只使用占用格；没有可用空格即按满箱选择，不比较固定的 5。时钟图标表示空闲，挂锁表示不可用。识别函数接受任意非空格心序列，不按容量推测锁定位置。实际画面容量范围见[玩法说明](../../../game/gameplay/贝果计划.md#备战物资与仓储)，函数接收更少格心不表示已支持新的画面排布。

局内入箱、仓库入仓、启动转存、出售前空箱核验和后续局入场共用此规则。各画面使用各自的格心坐标。

**坐标与缩放。** 古怪试炼的结果区按可见外框确认格心。列 X 为 `1353、1453、1554、1655、1756`，两排 Y 支持 `245/366` 与 `256/377` 两组已量测排布；面板确认、角标识别、结果格观察、品质取样和拖动源点共用本次定位结果。第一赛季的结果区不属于该定位范围，不能混用。

局内安全箱格心为 `X=259、360、461、562、663，Y=898`。仓库保留独立坐标，启动转存与结算仍共用 `X=267、371、475、579、683，Y=897`，不随右侧结果面板移动。画面与来源见[新赛季格子定位](../../../game/screens/image/bagel_item_badges/README.md#新赛季格子定位)。

截图控制器默认将游戏窗口截图缩放到 1920×1080。安全箱识别只接收该标准图像，不另做缩放。识别函数拒绝未标准化图像，不表示游戏窗口必须为 1080p。

局内与仓库共用以下分类顺序，分别使用各自坐标：

1. 在格心周围 96×96 的灰度区域匹配 48×56 挂锁模板。使用归一化相关系数衡量图案相似程度，该分数不是概率。
2. 分数不小于 0.90 时，判为锁定；分数为 0.75 至小于 0.90 时，返回未知。
3. 分数低于 0.75 时，检查中央 64×64 区域。灰度标准差至少 20 时，判为占用；标准差为 1–12 且平均亮度为 12–45 时，判为空闲。其余返回未知。

空闲判据的下限排除纯黑及纯色遮挡，上限保留时钟空格。搜查面板可操作性检查先于格子判断；这些阈值不能代替开关动画检查。

**结果格观察与登记。** 底部最大值不小于 240（0xF0）时视为物品候选，小于 40（0x28）时视为加载中。采样框横向以格心居中取 ±16 像素，纵向取格心下方 31–47 像素。中间亮度需要进一步区分空格候选与揭示动画；阈值、逐格登记、统一收尾和超时规则见[搜查结果登记与收尾](bagel_search_completion.md)。

单帧空格候选不能撤销已经看到的加载证据。已确认物品可先处理，不必等待整个结果区揭示完。所有正常收尾都检查未确认格，并在下一张新截图上复核；不按等待轮数耗尽放行。安全箱、仓库与拖拽核验继续使用各自原有判断。

#### 搜查面板可操作性

容器标题、安全箱标题和「全部拾取」在开关动画期间仍可能被识别。初始登记保留定位有效时的加载证据；选择物品、报告完成或补拖仍必须通过面板位置与连续画面稳定检查。

| 条件 | 处理 |
| --- | --- |
| 已确认本局 DEFEAT | 报告本局失败，优先于面板和格子识别 |
| 容器标题与解锁提示消失，且已识别局内普通攻击按钮 | 报告搜查中断，不要求箱子名称或 F 提示；正式应用退出结算后按整体重试预算重开，不原地补开 |
| 文字条件不全、结果格无法定位，或尚未取得两张位置一致且稳定的新截图 | 等待 0.3 秒，不发送输入；连续第 10 轮仍不能确认时报局内流程失败 |
| 连续两张新截图的结果格心一致，两块取样区域均稳定 | 继续当前步骤，清零连续面板等待次数 |
| 面板可操作，但安全箱仍未知 | 等待 0.3 秒，最多额外复查 3 次；第 4 次仍未知时停止并保存现场，不自动退出本局重开 |

位置检查限定在结果区 `[1290,170,1820,445)`，使用 Canny 40/100 提取卡片外框。候选外框宽 88–98、高 105–115，横向中心与预定列相差不超过 4 像素。每排至少三个不同列的外框须支持同一纵向偏移，再把测量中位数归到已知的 `−11` 或 `0` 像素偏移；误差超过 2 像素则不确认。没有足够外框时不回退到固定格心。允许一像素边缘噪声，但最终格心不会随轮廓逐帧抖动。

稳定检查比较结果区 `[1306,188,1803,433)` 与标题空白带 `[1520,156,1740,168)`。连续两张截图的时间必须递增，结果格心必须一致，两块区域的灰度平均绝对差都须小于 6。结果区检查包含物品变化，但不能代替单格有效角标条件。位置不明、位移或重复截图不能放行；位置变化后至少重新取得两张一致的截图。

发送拖拽后重新建立两帧稳定基线。等待期间保留拖前截图、源格、目标格和动作类型；恢复后先核对原次搬运，不因等待直接重拖。单格的亮度与角标复核、填空与对换的前后核验仍独立执行。框架确认终止或中断后才丢弃待核对数据。

单格拖拽前的截图继续使用已登记的格心。初始登记后格心发生变化时报告可恢复业务失败，不把另一组位置套入旧的逐格记录；拖后仍须核对原拖动源点。该定位只支持已量测的新赛季排布，不跟随关闭动画搬运。截图到输入之间仍可能受击，因此仍保留拖后核验和失败收尾。

正常主动关闭由独立关闭步骤处理，不因预期的面板消失触发搜查失败。

锁定格通过图标模板识别，不依赖文字识别（OCR）读取低对比度的 `LOCK`。截图不完整、模板缺失、挂锁匹配处于疑似范围或格子外观不明时，函数返回未知。操作不处理物品，也不报告清空成功。锁定格在显示序列中不要求连续；调用者使用每格明确状态，不补猜未锁定的格数。

发送拖拽前的新截图必须再次确认目标属于对应的可用空格或占用格。锁定集合变化时停止；目标占用状态变化时重新挑选。拖后与补拖前检查拖前后锁定集合一致、目标未锁定，且拖前类别符合本次动作。对换后目标不再占用时停止，不继续补拖。

启动转存使用[清空战备的重读上限](bagel_clear_loadout.md)。安全箱持续未知、开放格变化或无法核对拖拽目标时，停止并保存现场，不进入整体重试。仓库侧未知也不作为空箱或出售依据。满箱后的物品选择见[满箱对换](#满箱对换)。

**适用限制。** 格心数量可变不表示函数会自动定位任意排布。两格、三格与小容量仓库的实际排布，以及小容量下的完整收集、对换和入仓行为仍待核对。不同容器与非标准窗口缩放下的连续操作效果也不能只凭静态识别推定。金币在自动化中按角标主动排除，不依赖游戏拒绝拖拽来跳过。

挂锁与时钟的可核对像素及压缩限制见[安全箱素材索引](../../../game/screens/image/bagel_safe_and_notice/README.md)。画面范围见[安全箱格子](../../../game/screens/贝果计划.md#安全箱格子)。

**单格入箱条件。** 所有结果候选都要求底部最大通道值不小于 240，并匹配到已有类型角标模板；不因「全部拾取」可见而跳过角标检查。有效角标指模板匹配通过，不能用左上有白色像素替代。金币始终排除。

候选物品须在连续新截图中得到一致的类型和品质；未知品质保留原优先级排序，未知角标仍待确认。发送填空或对换拖拽前，操作等待 0.1 秒，再取得新截图，复核面板、底部亮度及角标类型。亮度仍达标且角标类型与选择时一致才发送拖拽。0.1 秒从选定源格后开始等待，不从亮度首次达标时计时。实际输入前还包含截图、识别及既有拖拽按下等待。

亮度达标但角标未匹配时，该格继续等待。之后亮度暂时掉回空档，也不能作为空箱或满箱的收尾依据。已有其他可处理物品时继续处理它们；没有可执行动作时每轮等待 0.3 秒。等待不增加搬运失败次数，不在超时后强行拖动。无进展与总用时限制见[等待与失败](bagel_search_completion.md#等待与失败)。

该规则不比较整张物品图案是否静止，以免已揭示的动态图案被持续阻拦。每件物品拖入后仍重新读取结果核验。角标未收录或长期被遮挡的格子可能一直等待到操作超时；不同物品的角标出现时刻与游戏允许搬运的时刻是否完全一致，尚未完成实机确认。

安全箱满时，已确认候选仍可按优先级对换。当前没有可对换物品不代表后续不会揭示更优物品；未确认格清空后，操作重新评估候选，再执行收尾复核。「全部拾取」不参与完成判断。

#### 物品识别与优先级

识别函数用格子左右两侧底色判断品质，用左上角标判断类型。颜色和类型说明见[画面文档](../../../game/screens/贝果计划.md#格子)。入箱不按物品名称、用途或账号解锁状态筛选。

收集节点通过面板检查后，以 INFO 级别记录结果区已识别物品的格号、种类和品质，包括被筛除的金币、角标未匹配的「其他」和品质未知的 `?`。选择入箱或对换目标时，同样记录已读取的安全箱物品。每个区域首次识别时输出完整列表，后续只输出格号、种类或品质的变化，以及不再进入本轮识别的格位；相同结果不重复打印，每次执行重新记录。格位不再进入识别不等于已成功搬运。日志前缀为「贝果物品识别」，表示当次识别结果，不代表物品已可拖动。

「蓝图优先」默认开启。蓝图用于解锁制造，普通成品不能代替对应蓝图，因此开启时将蓝图单独分组，先比较分组再比较品质。仅提高类型排序值不能实现低品质蓝图优先于高品质普通物品。

| 开关 | 分组顺序（高 → 低） | 同组比较 |
| --- | --- | --- |
| 开启 | 蓝图 → 非蓝图且非材料 → 材料 | 先比品质，再比类型；蓝图之间只比品质 |
| 关闭 | 非材料（包括蓝图）→ 材料 | 先比品质，再比类型 |

金币直接排除，不参与分组和比较。同组先比较品质：`Z(5) > S(4) > A(3) > B(2) > C(1) > 未知(0)`。品质相同时，再按下表比较类型。

| 类型 | 排序值 | 范围与例外 |
| --- | --- | --- |
| 特殊奖励 | 7 | 专指菲林／零号业绩，不代表全部撤离奖励；不跨品质优先 |
| 贵重物品 | 6 | 使用原有钻石角标的物品 |
| 蓝图 | 5 | 仅关闭开关时参与同品质类型比较；开启时独立为最高组 |
| 门禁卡 | 4 | 门禁卡角标 |
| 战术棱镜 | 3 | 铃铛、人像两种角标 |
| 装备 | 2 | 异体刃、抗蚀器、背包；不单设「金包」优先级 |
| 战术道具 | 1 | 普通骸影等战术道具，不按名称视为蓝图 |
| 其他 | 0 | 未匹配角标的物品 |
| 材料 | -1 | 已由分组规则排在非材料之后 |
| 金币 | -2 | 始终排除，不参与入箱选择 |

开启蓝图优先时，蓝图高于任何品质的特殊奖励。非蓝图的类型排序值不随开关变化。

候选结果格和箱内替换目标共用 `BagelSlotMark.priority(blueprint_priority)`。正式应用从当前账号、应用组的 `BagelConfig` 读取开关，依次传给 `BagelRunFlow`、`BagelStoreSafe` 和 `choose_store_action`，不依赖全局当前运行组。独立开发试跑未传参数时默认开启。

已识别为蓝图但品质未知时，仍属于蓝图，只在蓝图内部排最后。底层识别将未匹配角标返回为「其他」；结果格入箱时将其保留为待确认，不直接参与拖动。箱内物品仍保留原有的「其他」排序。普通骸影和普通装备不因名称相同而视为蓝图。

优先级相同时不对换。金币留在搜索结果中，不占安全箱，也不进入候选。金币角标在揭示动画期间可能读不出来，因此拖拽前还要用新一帧再核对一次，见[拖拽时序](#拖拽时序)。每次只拖 1 件，再重新读取结果核验。开关不改变收集范围、停止条件、拖拽核验、重试预算或仓库出售规则，不提供仓库防出售保护。

#### 满箱对换

安全箱有空位时，选择当前可处理结果中优先级最高的物品。开启蓝图优先时，多张蓝图先选高品质；没有蓝图时仍装普通物品。

安全箱满时，操作只用优先级严格更高的搜索结果物品，替换箱内优先级最低的物品。材料可以参与对换。拖拽前后，两格必须确实发生变化。

| 条件 | 对换规则 |
| --- | --- |
| 开启，箱内含非蓝图 | 蓝图换出最低优先级非蓝图，不受品质限制；例如 S 蓝图可以换出 Z 特殊奖励。非蓝图不能换出蓝图 |
| 开启，箱内全是蓝图 | 只有更高品质的新蓝图才能换出最低品质蓝图；同品质或更低品质不换，不保证保留全部蓝图 |
| 关闭 | 按非材料、品质、类型比较；例如 Z 普通物品可以换出 S 蓝图 |

对换后，原结果格会留下安全箱换出的物品。即使该格的品质和类型发生变化，操作也不再对换该格，避免来回交换。

没有可对换物品时，操作按搜查完成条件关闭面板，不将物品拖入背包，也不记为失败。

#### 搜查状态暂缺与拖拽核验

收集操作中的文字漏识别与面板过渡共用[面板等待上限](#搜查面板可操作性)。正式执行器在收集和关闭步骤入口另设搜查状态等待预算，最多额外等待 5 轮；入口规则如下：

| 条件 | 处理 |
| --- | --- |
| 对应容器标题仍在，搜查状态暂时漏识别 | 等待期间不发送输入。状态恢复后才运行子操作 |
| 容器标题不符 | 立即停止 |
| 拖拽后等待核验 | 保留原始前后对照，不补拖 |
| 拖拽核验时标题消失 | 已确认回到局内则报告中断；其他情况有界等待并保留拖前数据 |
| 状态持续漏识别 | 达到面板等待上限后报局内流程失败，交给正式应用退出本局重开 |

#### 拖拽时序

首次入箱、满箱对换和失败后的重拖，统一通过 `BagelStoreSafe._drag_item()` 调用 `drag_to`。调用按控制器模式选择 `DragTiming`，显式指定三段时序，不再传入 `duration`：

| 模式 | 按下等待 | 移动时间 | 松开前等待 |
| --- | --- | --- | --- |
| 前台 | 0.3 秒 | 0.3 秒 | 0.2 秒 |
| 后台 | 0.02 秒 | 0.6 秒 | 0.2 秒 |

这些参数保留原有前后台时序。前台按下后先等待，让游戏抓起物品，避免将搬运识别成结果列表滚动；后台保留原有较短按下等待和较长移动时间，不在接口适配中统一调参。参数只用于物品搬运，不修改公共默认值。快捷手册的列表滚动不传 `timing`，使用[控制器默认时序](../../one_dragon/one_dragon_architecture.md#拖拽时序)。

暂停或停止不打断当前拖拽，等待其完成并松开鼠标后，再由框架处理运行状态。输入与异常清理规则见[拖拽输入与清理](../../one_dragon/background_mode_design.md#拖拽输入与清理)。

填空时，面板稳定且目标格由空变有就记为成功，源格占用仅作辅助，不能对已占用的目标再拖。源格有物、目标仍空时最多额外重拖三次（首次加重拖共四次），每次保持同一目标。对换维持额外重拖一次。两格都空时先等一帧，仍未入箱则停止；未知格、锁定格及面板中断沿用原有保护。

**拖不动的结果格按跳过处理，不停机。** 重拖预算用完、画面仍无变化时，操作把该结果格记为「不可入箱」（失败三次即放弃这一格），后续挑选跳过它，继续装剩下的物品；全部跳完时由装入安全箱按正常完成收尾。对换重拖后两格外观仍无变化同样跳过。金币本来就不进安全箱，其它物品也可能被游戏拒绝搬运，一件搬不动就停整局的代价远大于把它留在搜索结果里。跳到哪一格、当场读到什么，都写进日志。

**连续失败退出本局重开。** 连续两件物品搬不动就不再磨下去：操作报 `贝果局内流程失败`，原因写进返回数据，由正式应用释放输入、退出本局、结算仓库，再按[整体重试](bagel_failure_retry.md)预算重开。一件搬不动只是这一格的问题，连续两件多半是这一局的面板或交互已经不对，继续磨只会把整局时间耗光；退出时游戏只保留安全箱物资，比把整个任务停在这里划算。跳过时当场复核到金币的不计入连续失败：金币不占安全箱，本来就不该搬。

**面板失败与安全箱未知分开处理。** 面板位置与文字条件持续不满足、缺少拖拽前后对照、物品离开搜索格却没进安全箱，仍报 `贝果局内流程失败`，由正式应用退出结算并按预算重开。安全箱格子持续未知、开放格变化或目标状态无法核对时直接停止并保存现场，不能使用同一可重开状态。本局 DEFEAT 和搜查中断仍用各自的状态上报。

**拖前复核。** 等待 0.1 秒后取得的新截图必须晚于选择时截图，并重新通过面板检查。源格亮度不再达标或角标未匹配时，返回等待；角标类型改变时，重新挑选；读到金币时跳过该格，不计搬运失败。复核通过后，才登记本次对换并保存拖前基线，避免一次等待被误记为已经对换。

操作仍需核对拖拽前后两格的变化，不能把拖拽结束作为入箱成功依据。显式时序下的前后台入箱、对换、重拖和暂停后松键，以及公共默认时序下的快捷手册滚动，尚未完成实机验收。

#### 品质与角标识别

品质识别取格子两侧底色的 HSV（色相、饱和度、亮度）中位数。相对已校准格心，左带为 `[-36,-28,-30,20)`，右带为 `[30,-28,36,20)`，各 6×48 像素。两带避开中央物品图案、左上角标和底部数量／等级文字；合并两带全部像素求中位数，不按饱和度挑选像素。

整块区域取最高饱和度像素会受到物品图案干扰，例如金色金币图案盖过蓝底，橙红色图案盖过紫底。基线双长条在格心校准后可识别已归档样本；当前双长条向内调整，减少小幅格心偏差时取到黑边的机会。对照素材、方法与适用范围见[品质取样对照](../../../game/screens/image/bagel_item_badges/README.md#品质取样对照)。色相范围如下：

| 品质 | 色相范围 |
| --- | --- |
| B | 90–119 |
| A | 120–160 |
| C | 50–85 |

饱和度或亮度低于 40，或色相未匹配色带时，识别函数返回未知，不默认归为 B 或 C。

**角标模板裁剪。** 角标模板按图案轮廓选择位置和尺寸。白色图案必须完整保留，上下左右留白接近。裁剪偏移应通过重新裁剪修正，不能通过降低匹配阈值弥补。

类型识别在格心左上搜索真实物品格模板。搜索框相对格心为 `x=[−56,−20)`、`y=[−64,−28)`，尺寸 36×36，覆盖现有 24×24 和 24×26 模板并保留余量。结果格的搜索框必须随本次测得的格心移动：第一排格心 y=245 时搜索 y=[181,217)，y=256 时搜索 y=[192,228)。搜索面积较 52×52 减少约 52%，模板与阈值保持不变。图像依据见[角标顶部覆盖](../../../game/screens/image/bagel_item_badges/README.md#角标顶部覆盖)。

识别取匹配分数最高的类型；最高分低于 0.75 时返回「其他」，不通过降低阈值补偿裁切。不同角标外观使用独立模板，不按名称推断类型。模板类型、尺寸和像素来源见[贝果画面「格子」](../../../game/screens/贝果计划.md#格子)。

特殊奖励仅是局内入箱分类，不新增仓库出售筛选项。仓库仍按游戏的筛选类型出售；此分类不提供防出售保护。

#### 入箱识别与执行限制

- 尚未确认 A/B/C/未知品质蓝图、零号业绩独立物品格，以及全部背包外观的实机识别效果。
- 尚未完成两种蓝图开关下的完整局、满箱全蓝图对换、同品质不换和非蓝图不能换出蓝图的实机验收。
- 蓝图与特殊奖励分类在其他光照、不同窗口缩放条件下的适用性尚未确认。
- 归档单帧只用于核对角标和品质，不证明连续拖拽、对换或结算成功。录像解码像素的限制见对应素材索引。

#### 收集与关闭的职责

正式应用和开发执行共用收集行为。收集操作通过[逐格检查与新截图复核](bagel_search_completion.md#正常完成)后保留面板，由独立关闭步骤负责点击返回并确认回到局内。单独执行关闭步骤不提供搜查完整保证。

搜查或搬运期间确认面板消失并回到局内后，子操作报告中断，无须识别实际攻击来源。正式应用按[搜查中断判据](#搜查中断处理)退出重开，开发工具保留现场。两者均不在原地补开容器。

### 搜查中断处理

收集、关闭搜查或光圈解锁发生可恢复业务失败或实际超时时，执行器读取新截图。只有同时满足以下条件，才判为搜查中断：

- 已回到贝果局内。
- 武备箱和电子保险箱的搜查面板均已消失。
- 解锁提示已消失。

步骤入口已被打断时，执行器使用同一判据。正式应用按[整体重试](bagel_failure_retry.md)退出到仓库，核对安全箱物资入仓后，再决定是否重开。中断局不计成功。

未知画面、面板仍在时的拖拽错误，以及退出或入仓失败，均停止。开发工具只返回中断状态，不自行退出或补开容器。

### 退出与结算提示

退出到仓库依次执行：打开暂停菜单、点击退出、确认退出、等待结算、处理提示并确认仓库。结算点「继续」之后，仓库可能先短暂显示，再被拟态单质失活提示覆盖。因此提示检查与仓库等待由 `BagelWaitWarehouse` 在同一循环处理，不能在单帧未发现提示时永久跳过。

每轮先检查截图时间，再按以下顺序处理画面：

| 条件 | 操作与完成判据 |
| --- | --- |
| 截图时间未递增 | 等待新截图，不点击，也不增加仓库计数 |
| 完整失活标题命中 | 清零仓库计数；识别该提示的「确认」，按文字中心点击。按钮暂不可见或点击失败时继续观察 |
| 标题未命中，且「放入仓库」「返回研究站」同时命中 | 累计仓库帧。连续至少三张新截图、跨度至少一秒，才确认到仓库 |
| 其他画面或暂停 | 清零仓库计数，重新等待 |

标题区域匹配完整说明「带出的拟态单质已失活，转化为惰性单质」，文字匹配阈值为 0.90。等待间隔为 0.5 秒。提示处理与仓库确认共用 30 秒上限，超时失败并保存现场；区域配置缺失等程序错误直接失败。

正常退出、失败收尾、直接从提示页启动退出操作及首次启动恢复共用该等待操作。入仓首次核对和点击后的核验也检查迟到提示。关闭提示后，操作重读仓库：

- 尚未发送入仓点击时，重新建立数量基线。
- 已发送入仓点击时，保留原基线，继续核对物资去向。

提示确认不增加入仓或成功次数。入仓自身仍受原有节点和操作时限约束，不因提示重置预算。

**适用限制。** 提示出现与点击响应的实际时序，以及提示关闭后的完整自动结算行为仍待核对。具体物品的触发条件和确认后去向见[玩法说明](../../../game/gameplay/贝果计划.md#退出与仓库)。画面特征见[贝果计划画面](../../../game/screens/贝果计划.md#各画面要点)，来源与压缩限制集中在[结算提示素材索引](../../../game/screens/image/bagel_safe_and_notice/README.md)。

单件物品在重拖预算内搬不动不算这类拖拽错误：它是游戏拒绝搬运（金币）或物品没抓到，按[拖拽时序](#拖拽时序)跳过该格继续装别的，不影响面板状态判断；连续两件搬不动则按同节报局内流程失败，与这里一样走退出本局重开。

### 入仓核验

点击「放入仓库」后，操作同时核对安全箱和仓库占用。仓库「全部 N/M」中的 N 表示占用，M 表示当前界面显示的实际容量。M 不能固定取 280。下表中的占用变化均与点击前读数比较。

| 结果 | 判定与处理 |
| --- | --- |
| 安全箱清空，N 增加 | 入仓成功。包括占用从 `(M−1)/M` 增至 `M/M`，恰好满仓的情况 |
| 安全箱清空，N 不变，且 N<M | 入仓成功。允许物品合并到已有堆叠 |
| 安全箱清空，N 不变，且 N≥M | 正式结算允许满仓合并堆叠；独立入仓工具仍保留原保护 |
| 安全箱清空，但 N 下降或必要读数无法核对 | 停止，不计入仓成功 |
| 安全箱只减少部分格子 | 正式结算交给一次出售后再入仓；独立入仓工具仍停止 |
| 安全箱格子完全未变 | 允许有限重试或判满仓 |
| 安全箱仍占用，且 N≥M 连续 6 帧 | 记为仓满并停止 |

正式结算的满仓或残留处理见[出售间隔与残留处理](bagel_sale_interval.md)。独立入仓、独立清理工具默认仍保留原保护。入仓核验不按物品名称判断。

入仓成功后，正式应用按清理开关处理仓库，再执行[出售与结算核验](#出售与结算核验)。安全箱为空且容量可读即可结束结算并返回入口；仓库已满不再阻断。入仓后恰好满仓时，正式应用仍可按现有清理规则提前出售一次。

### 仓库清理与返回

#### 出售方案

清理开关默认开启。关闭时，正式应用只执行入仓。出售按以下方案选择：

| 方案 | 类型 | 品质 |
| --- | --- | --- |
| 默认第 1 步 | 贵重物品、战术棱镜 | C/B/A/S |
| 默认第 2 步 | 其他 | C/B/A |
| 自定义 | 按 `clean_steps` 从上到下，每一步使用该步选择的类型，不能为空 | 每一步使用该步选择的品质，不能为空 |

默认方案保留 S 品质「其他」，包括金色蓝图和 S 品质材料；同时保留全部 Z 品质、装备、战术道具和门禁卡。两步必须分别执行，不能合并类型和品质后出售，否则会重新包含「其他 × S」。它按游戏筛选分类保留物品，不逐件识别蓝图，也不按名称、重复数量或解锁状态判断。

配置、设置页和启动恢复共用同一份默认步骤。默认模式直接使用这两步，不改写已有 `clean_steps`；自定义模式仍按已保存的步骤执行。显式传入的空步骤组保持为空，不能回退到默认出售。单步出售操作必须显式接收筛选范围，调用者负责执行完整方案。

全部筛选按钮独立于默认方案定义。每一步先取消范围外的选项，再补选目标项；第 2 步必须取消 S 品质及第 1 步的类型。两步实际筛选范围、连续出售和返回仓库的完整实机流程尚未验收。

快速选择中，同一步的类型和品质必须同时匹配，物品才会进入这一步的出售范围。「全部」始终不选。一次结算内按步骤顺序各打开一次快速选择。有物品的步骤必须点完确认出售、确认弹窗并回到仓库，才开始下一步。没有命中物品时取消出售并回到仓库，也才开始下一步。任一步失败或确认未完成就停止，不继续后面的步骤，也不再入仓。操作每次重新读取所有选项，并取消该步未选的项目。清理流程不点击整理，也不自动转化货币。

**空箱结算只跳过出售。** 入仓操作确认安全箱原本为空时，清理节点跳过出售，但继续执行末尾的安全箱和仓库容量核验；不能直接结束结算。空箱时不清理已有库存，与清理开关和出售方案无关，正常局和失败收尾均适用。核验通过后仍返回原有空箱状态，沿用现有成功、空箱及失败计数规则。

#### 出售与结算核验

出售间隔、提前出售、残留再入仓和最终核验均见[出售与入仓重试](bagel_sale_interval.md)。本节只维护出售筛选方案和返回操作。

**返回入口。** 正常各局从结算仓库直接返回贝果主界面，不经过达塔对话。返回操作报告实际落点，后续入场按[快捷手册入口规则](bagel_speedup.md#快捷手册入口与局间返回)处理。黑屏和入口渐显期间继续等待；恢复触发条件和时限见[整体重试说明](bagel_failure_retry.md#页面阻挡恢复)。页面恢复不改变任务计数或首次清空资格。

**返回时的奖励提示。** 结算仓库点击「返回研究站」后，若同时识别到「撤离奖励提示」和奖励转移说明，返回操作只确认 1 次，再等待完整贝果主界面或大世界 HUD。

## 3. 配置（`BagelConfig`）

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `max_success_rounds` | 1 | 成功局数上限，范围为 0–1000。0 表示不限成功次数。非支持出生点和失败局不计数 |
| `max_failure_retries` | 5 | 累计整体重试次数上限，范围为 0–100。最多因失败额外重开 N 局，成功后不清零 |
| `blueprint_priority` | 开 | 蓝图独立为最高入箱分组；蓝图之间按品质比较，同品质不对换。旧配置缺项也开启；仅影响局内入箱 |
| `auto_clean_warehouse` | 开 | 关闭时只入仓，开启时按间隔或满仓/残留规则出售；空箱规则见上文 |
| `sell_interval` | 5 | 本任务非空入仓次数，范围为 1–999，包含失败局带回物资。1 表示每次都卖；正常结束补卖。关闭清理时不出售 |
| `clean_mode` | `default` | `default` 使用上表的两步默认方案。`custom` 按 `clean_steps` 顺序多次出售 |
| `clean_steps` | 空列表 | 自定义出售步骤。每步含 `types` 和 `qualities`，两者都不能空。没有步骤时，自定义清理不能启动 |

默认值用于新配置或缺少对应键的配置，已有显式配置优先。任务配置页位于主窗口内，可以滚动。设置自动保存，并绑定当前账号和应用组。进入页面加载配置时，页面不写回配置。

页面显示累计成功与累计失败两个结束条件，内部配置仍保存额外重开次数。自动出售的间隔、范围和自定义步骤归入同一父卡片；所有步骤下方共用一份总预览。显示换算、编辑规则与提示条件见[设置页说明](bagel_usage.md#设置)，实际计数和执行顺序不变。

### 开发工具与打点路线

`config/bagel/routes/` 下的路线文件是打点路线与点位的唯一来源，`config/bagel/route_settings.yml` 记录每个出生点开启的路线，规则见[贝果路线与出生点](bagel_route_storage.md)。`BagelApp` 用 `BagelRouteWalker` 识别出生点并执行开启的路线，外层应用负责入场、结算、清理和重开。

网页路线编辑器负责录制、试跑、编辑和开启选择，正式执行只读路线文件和开启选择。编辑器说明见[贝果开发工具](bagel_flow_editor.md)。地图资源和坐标规则见[分层小地图说明](bagel_fixed_map.md)。

### 执行与输入清理

正式应用和操作基类为每次执行分别包装暂停、恢复回调。执行结束时，清理按以下顺序进行：

1. 停用本次执行的订阅。
2. 等待已开始的回调完成。
3. 从运行总线解绑。

初始化或收尾异常也使用该清理流程，避免上一次执行的回调影响下一次执行。

局内执行器和开发试跑共用输入清理函数。暂停回调释放前进、交互的键盘输入及后台手柄输入，不重置鼠标，也不发送左键松开消息；映射到鼠标的定时输入由原动作自行结束。当前拖拽完成后，框架在下一轮检查暂停或停止状态。恢复后仍先核验原次搬运，不直接重拖。

打点路线执行还有一层自己的输入线程，见[输入线程与动作打断](#输入线程与动作打断)。暂停只把前进、后退意图置为松开，不打断即时动作；退出路径调 `shutdown()` 停掉三条通道并显式释放 W、S、F，避免线程残留导致按键一直按着。

执行结束后，业务线程重置持续按键，释放定时前进、交互和鼠标左键；后台再发送左键松开消息。开发工具关闭时沿用已有的异步等待线程收尾。暂停请求不代表鼠标已交还，用户应等当前动作结束后再接管；前后台暂停与停止的实机表现尚未验证。

## 5. 功能限制

- 入箱不按物品名称和等级筛选，也不记录按名单收集的进度。
- 收集操作不拾取金币，不将携带货币计入已入仓物资。货币退出保留规则见[玩法文档](../../../game/gameplay/贝果计划.md)。

## 6. 测试与验证范围

选图免重复点击、入场弹窗短间隔观察和仓库筛选等待的规则，见[等待优化](bagel_speedup.md)。不改变清理开关、出售范围或任务计数。

测试位于独立仓 `zzz-od-test/test/zzz_od/application/bagel/`。快测与完整回归命令见[贝果测试入口](../../testing/bagel.md)。

投资归零的离线流程测试使用实际 `500K` 投资页、归档零投资页，以及明确标注的合成金额帧。测试覆盖初始为零、非零归零、画面更新延迟、点击失败、MIN 未识别、画面不变和 OCR 不明。失败时，测试还检查未点击入场，并保留最后截图。

光圈解锁的离线回归范围见[容器交互与解锁](#容器交互与解锁)。安全箱容量和缩放测试的验证范围见[收集与对换](#收集与对换)。启动清空、整体重试、容器恢复和建图的验收要求分别见对应专项文档。

## 正式任务的提示

设置文案与运行提示由 `bagel_usage.py` 管理。正式应用校验通过后记录配置摘要；收尾结果与停止原因仍由原有操作返回。成功结束的位置来自返回操作的实际状态，未确认时不声称已返回入口。截图接口返回名称，提示层确认文件存在后才展示完整路径。

定位等待通过可选回调向正式应用报告。回调不改变导航的输入、等待时间或失败预算；开发试跑不传入该回调。出售规则、节点状态、计数和重试行为保持原样。

返回入口使用完整入口特征等待。判据、时限和不用全屏稳定检测的理由见[整体重试](bagel_failure_retry.md#为什么不用全屏稳定检测)。
