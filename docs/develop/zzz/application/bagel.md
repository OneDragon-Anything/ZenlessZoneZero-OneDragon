## 1. 脚本流程

`BagelApp` 从已识别且允许启动的画面进入研究站，循环执行到成功次数上限。默认上限为 1，设置为 0 时不限制成功次数。

1. 校验配置，并加载两个支持出生点的发布流程（`flow.yml`）。本次执行固定使用已加载的步骤和路点，称为流程快照。
2. 根据当前画面进入研究站入口或选图页。首次启动时若在贝果仓库，先转存携带物，再返回备战或研究站入口。该转存不主动出售；满仓或残留按一次出售重试处理，不增加任务计数。各起点的处理规则见[入场与携带核验](#入场与携带核验)。
3. 选择并核对雅努斯高危，进入备战页。
4. 核对当前画面的零携带状态。首次入场可以先清空非零携带，再复核零携带。后续各局发现非零携带时停止。
5. 核对零投资并入场。
6. 用小地图识别出生点，执行对应路线。
7. 主动退出到仓库，核对安全箱物资入仓，再按清理开关处理仓库。
8. 核对结算结果，更新成功局数，决定结束任务或开始下一局。

录像店路线依次执行：靠近武备箱、开箱、装入安全箱、靠近电子保险箱、交互开箱、完成光圈解锁、再次装入安全箱、主动退出、入仓和按开关清理。

白鸽工地地铁站路线依次执行：靠近武备箱、开箱、装入安全箱、主动退出、入仓和按开关清理。导航使用小地图匹配位置并沿路点移动，不提供遇敌恢复。

其他出生点退出并返回入口，不清理仓库，也不增加成功局数。出生点重选没有尝试次数上限。

寻路卡位、定位失败、局内步骤或操作超时、被敌人击杀、容器恢复失败，以及搜查或解锁中断，均进入失败收尾。正式应用释放输入、记录原因和截图，再根据新画面退出到仓库。核对安全箱入仓并按开关清理后，正式应用才决定是否消耗整体重试次数重开。次数耗尽时，应用仍先完成结算，再停在仓库。失败局不计成功。详细规则见[整体重试说明](bagel_failure_retry.md)。

| 结算结果或配置 | 计数和后续动作 |
| --- | --- |
| 安全箱有物，已确认入仓并完成清理 | 增加 1 个成功局数。清理关闭时，只需完成入仓和结算核验 |
| 安全箱为空 | 跳过出售，仍核对安全箱为空且容量可读，满仓也允许返回入口；不增加成功局数。连续 3 次空箱后停止 |
| 成功次数上限为正数，且已达到上限 | 任务成功结束 |
| 成功次数上限为 0 | 继续执行，仍受失败、异常和连续空箱停止条件限制 |
| 入仓失败、清理失败、再入仓后仍有残留或状态不明 | 停在当前画面，不开始下一局 |

## 2. 设计决策

### 入场与携带核验

先按[首次启动恢复](bagel_start_recovery.md)确定起点，再核对地图、难度、五项携带读数和投资金额。普通大世界、地图、菜单、快捷手册、普通仓库与达塔对话共用通用返回和地图传送。

音擎仓库和驱动仓库的全局识别失败时，入场操作用完整仓库标题补充识别。区域缺失时跳过该项，不将普通仓库当作贝果结算仓库。地图传送失败时停止。

首次清空资格、读取上限和后续局残留保护只在[启动清空](bagel_clear_loadout.md)维护。入场的选图与暂停规则见[等待规则](bagel_speedup.md)。

### 价值读取

按以下顺序读取武备、装备和道具价值：

1. 识别备战右侧完整面板，排除左侧库存。从结果中筛选三个标题条区域。对应标题完整匹配，且数值恰好是一段纯数字时，采用该结果。
2. 面板结果不满足条件时，裁出完整标题条重新识别。优先采用唯一一段纯数字。没有纯数字时，才从唯一一段「1–2 个非数字前缀 + 完整数值」中提取数字。
3. 裁图结果仍无法解析时，识别整屏。结果必须同时满足标题匹配和数值为唯一一段纯数字。
4. 所有读取方式均无法解析时，返回空字符串，按未知状态处理。

判为零前，识别函数核对该区域所有已获得的文字。任一结果包含非零数字时，函数返回空字符串，拒绝零携带入场。例如，`0` 与 `@500` 同时出现，或面板读到 `500` 而标题条裁图只剩 `0`，均不能放行。

标题条必须包含完整数值，不能只截末尾。价值读取不使用亮白过滤，避免道具价值 `0` 被读成 `O`。

背包、安全箱和投资金额分别裁出各自的完整区域读取。投资金额继续使用独立的颜色过滤和严格零值校验。

### 投资金额归零

识别到投资页后，先在完整金额区域定位唯一金币，并遮挡金币及其左侧，再按区域颜色过滤读取金额。遮挡保留原始输入尺寸，边界随金币位置移动，避免固定裁剪截断长金额。金币缺失、候选不唯一或金币左侧仍有白色数值时，返回未知，不按零放行。

操作读取完整金额后决定动作：

| 读数 | 动作与完成条件 |
| --- | --- |
| 正整数，或带 `K/M` 的正数，如 `500K`、`1.5M` | 点击 MIN。点击成功后等待 1 秒，下一轮重新截图读取金额 |
| 初始金额或复核金额精确为 `0` | 点击「前往空洞」。点击成功后，才记录投资已确认 |
| 空值、`O`、`00` 等不明确读数 | 只重新读取，不发送输入 |

点击 MIN 成功不表示金额已归零。非零归零和读数不明共用 3 次重试预算。MIN 未识别或点击失败也消耗 1 次。预算耗尽后，操作再读 1 帧。金额仍不是 `0` 时，操作停止并保存现场。

投资重试预算单独记录，避免节点等待重置框架重试次数。重复执行时，预算清零。点击入场后，操作不重复归零或确认。

### 出生识别与导航

**支持的出生点。** 正式应用只识别录像店和白鸽工地地铁站两条路线。其他出生点退出重开，不漫游寻找箱子。

**出生前确认局内。** 入场操作确认雅努斯高危后，出生检查再次识别普通攻击按钮。单帧模板漏识别时，最多复看 3 帧。持续不符时，出生检查结束并进入[失败收尾](bagel_failure_retry.md#失败收尾)，不计一次出生检查。已确认零投资的入场若在加载期间出现高危死亡结算，也由出生检查进入失败收尾。

**固定小地图定位。** 出生识别、正式导航和开发工具共用固定底图。同次执行使用同一份地图快照，详见[固定地图说明](bagel_fixed_map.md)。

定位失败时，导航停止移动。即使出现路边可拾取物的 F 提示，导航也不能继续前进。重新取得当前帧位置后，导航才允许忽略拾取提示继续移动。导航不提供自动绕障。

**导航等待截图与局内 HUD。** 局内 HUD 指游戏中的常驻状态和操作按钮。导航按以下规则等待：

| 条件 | 处理 |
| --- | --- |
| 动作后的截图尚未更新 | 每隔 0.15 秒等待新截图 |
| 局内 HUD 暂未识别，且未发现暂停菜单 | 先松开前进键，再每隔 0.25 秒检查 |
| 已确认暂停菜单 | 立即失败 |

两种等待均不消耗节点重试次数，但仍受当前导航步骤的整体时限限制。

**录像店复活点导航。** 正式应用先到武备箱，再经巷口、楼角和接近点靠近电子保险箱。路点坐标、切段范围和移动参数以[录像店发布流程](../../../../assets/game_data/bagel/janus_high_a/flow.yml)为准。

接近点允许提前松开按键。导航等待停稳后，用新截图核对位置。仍未到达时，导航在当前步骤内继续短步调整。提前松键本身不能作为到达依据。最终靠近步骤根据当前位置调整，并遵循下文的容器交互规则。导航参数见[开发工具的地图与参数](bagel_flow_editor.md#地图与参数)。

**白鸽工地地铁站复活点导航。** 白鸽路线与录像店共用路点导航。导航按当前位置到下一路点的方向转向，远处连续前进，近处短步调整。路点和移动参数以[白鸽发布流程](../../../../assets/game_data/bagel/janus_high_b/flow.yml)为准。最终靠近步骤使用相同的容器交互规则。

**贴墙卡位停止。** 在电子保险箱远段持续前进时，若匹配位置连续 3 秒未离开 2 像素范围，导航松开按键、报告失败并保留现场。该检查仅限制卡位耗时，不提供自动绕障。

暂停时，导航松开按键并清除卡位计时。恢复后，导航重新校准朝向。暂停时间不计入持续前进时间。

**步骤入口定位暂缺等待。** 出生检查、移动和靠近步骤共用以下规则。局内 HUD 已确认，但当前帧几何证据不足（`insufficient_geometry`）时，执行器每隔 0.3 秒重新截图，最多等待 5 次。

等待期间，执行器不发送移动或交互输入，不推进步骤，也不使用上一帧坐标替代本帧定位。定位恢复后，执行器才运行当前步骤，并清零等待次数。再次初始化也清零等待次数。

持续失配时，执行器结束当前局内步骤。正式应用按[整体重试](bagel_failure_retry.md)收尾，开发工具保留现场。位置冲突、超出底图覆盖范围、裁图错误、出生位置不符和其他画面前提错误，均立即结束步骤。等待不降低定位门槛。

**首次导航定位暂缺等待。** 步骤入口检查通过后，后续截图仍可能无法定位。进入子导航后，在首次取得导航位置前，若新截图仍为 `insufficient_geometry`，导航先松开前进键，再每隔 0.3 秒重新截图。最多等待 5 次，第 6 次仍失配时，导航保留原定位失败状态并停止。

等待期间，导航不移动、不转向、不交互、不切换路点，也不使用入口坐标。取得本帧可靠位置后，导航清零等待次数并继续。再次初始化也清零预算。

位置冲突、超出覆盖范围或非法裁图时，导航直接失败。已经取得导航位置后若连续失配，导航最多等待 3 次，每次间隔 0.15 秒。

### 容器交互与解锁

**交互提示识别。** 交互步骤使用右侧目标提示条，并用模板识别圆形 F 图标。箱子头顶名称不能作为交互依据。局内 HUD、目标提示和 F 图标必须同时出现。搜查面板仍在时，操作不按 F。

**局内判断复用普通攻击按钮。** 入场、出生识别、导航、容器交互、搜查中断和退出，均使用 `战斗画面/按键-普通攻击` 的既有模板和阈值，不读取左侧计分文字。

电子保险箱必须匹配对应交互提示，正式执行器还要求 F 图标。普通武备箱缺少攻击按钮时，操作等待。确认攻击按钮和交互提示后，操作才按 F。已处于解锁或搜查面板时，操作使用对应面板的判据，不补按 F。

**容器停稳确认与开箱恢复。** 武备箱和电子保险箱共用停稳确认、补按 F 和重新靠近规则。流程执行器按容器阶段管理预算。恢复失败后，正式应用进入既有失败结算。开发工具分步试跑仅执行已选动作。阶段边界、完成条件、参数上限和验证范围见[容器恢复说明](bagel_container_recovery.md)。

**电子保险箱光圈解锁。** 正式流程连续执行开箱 F 和光圈解锁。发送开箱输入后，操作立即观察界面，不等待独立步骤交接。确认解锁界面的同一张截图也用于观察光圈。界面出现时，操作记录交互完成并开始解锁。解锁失败归入解锁阶段，由整体失败重试收尾。

开发工具仍按勾选项独立执行交互和解锁。草稿格式和步骤标识保持原样。

光圈操作先观察小圈，再等待红圈或黄圈扩至候选半径。每轮只按 1 次，共 4 次。解锁提示消失时，操作停止输入。完成 4 次点按后，操作仍需等到搜查面板出现，才能确认解锁成功。搜查完成由逐件入箱流程确认。

连续执行消除了固定等待和重复观察造成的空档。开箱按键时长和光圈阈值由当前操作实现定义。当前实现没有首轮晚进入补偿，也不识别游戏进度。

**光圈验证范围。** 离线回归覆盖首张小圈只出现 1 次时参与判断、完整 4 轮解锁，以及中断后停止输入。连续开箱时首圈的命中率尚未确认。

### 收集与对换

**容量识别。** 安全箱有 5 个显示位置。识别函数先查找锁定格，再区分占用格和空闲格。仅开放格参与填空、对换和物品计数。开放格必须从左侧连续排列，数量必须符合[安全箱容量范围](../../../game/gameplay/贝果计划.md#备战物资与仓储)。

局内入箱、仓库入仓、启动转存、出售前空箱核验和后续局入场共用此规则。各画面使用各自的格心坐标。

**坐标与缩放。** 局内和仓库使用独立的格心坐标，见[安全箱格子](../../../game/screens/贝果计划.md#安全箱格子)。仓库共用计数入口和启动转存使用同一组仓库坐标。局内默认坐标不能用于仓库核验。

截图控制器默认将游戏窗口截图缩放到 1920×1080。安全箱识别只接收该标准图像，不另做缩放。识别函数拒绝未标准化图像，不表示游戏窗口必须为 1080p。

格子占用沿用灰度标准差至少 20 的判据。空格要求灰度标准差为 1–9，且平均亮度为 12–35。其余返回未知。搜查面板可操作性检查先于格子判断，不能通过放宽空格阈值来接受开关动画。仓库沿用自己的固定坐标和原有分类规则。

#### 搜查面板可操作性

容器标题、安全箱标题和搜查状态在开关动画期间仍可能被识别。文字条件通过后，收集与拖后回读还必须确认面板位置及连续画面稳定性，才允许读取格子、选择物品、报告完成或补拖。

| 条件 | 处理 |
| --- | --- |
| 已确认本局 DEFEAT | 报告本局失败，优先于面板和格子识别 |
| 容器标题与解锁提示消失，且已识别局内普通攻击按钮 | 报告搜查中断，不要求箱子名称或 F 提示；正式应用退出结算后按整体重试预算重开，不原地补开 |
| 文字条件不全、面板位置不符，或尚未取得两张稳定的新截图 | 等待 0.3 秒，不发送输入；连续第 6 轮仍不能确认时停止并保留现场 |
| 面板位置正确，连续两张新截图的静态区域稳定 | 继续当前步骤，清零连续面板等待次数 |
| 面板可操作，但安全箱仍未知 | 等待 0.3 秒，最多额外复查 3 次；第 4 次仍未知时停止并保留现场 |

位置检查使用左侧五个安全箱外框和右侧第一排五个结果外框。每排至少四个完整格框符合预期位置，允许一格被鼠标或揭示动画遮住。格框中心与既有格心偏差最多 4 像素，宽 85–105、高 100–120；轮廓使用 Canny 40/100 提取。锁定格也保留外框，参与位置检查。

稳定检查分别读取安全箱标题栏 `[210,800,715,837)` 和结果面板左侧边框 `[1250,195,1275,520)`，避开物品揭示动画。连续两张截图必须具有递增的截图时间，两块区域的灰度平均绝对差都须小于 4。重复同一张缓存截图不算新增证据；位置不符或文字不明时清除稳定基线。固定像素允许范围属于 1080p 画面基准，不调整拖拽坐标。

发送拖拽后重新建立两帧稳定基线。等待期间保留拖前截图、源格、目标格和动作类型；恢复后先核对原次搬运，不因等待直接重拖。搜查中的物品揭示稳定检查、填空与对换的前后核验仍独立执行。框架确认终止或中断后才丢弃待核对数据。

此方案保留固定坐标，通过面板检查排除不适合处理物品的画面。不使用固定延时作为唯一条件，也不动态跟随关闭动画搬运。格子分类优化只有在可操作面板上仍有实证误判时再评估。截图到输入之间仍可能受击，面板检查不能保证输入期间不会中断，因此必须保留拖后核验和失败收尾。

正常主动关闭由独立关闭步骤处理，不因预期的面板消失触发搜查失败。不同容器、小容量和非标准窗口缩放的完整自动操作仍需实机验收；离线图像与流程回归不能替代这些验证。

锁定格通过图标模板识别，不依赖文字识别（OCR）读取低对比度的 `LOCK`。截图不完整、模板缺失、格子外观不明或锁定位置不连续时，函数返回未知。操作不处理物品，也不报告清空成功。

启动转存使用[清空战备的重读上限](bagel_clear_loadout.md)。其他安全箱核验失败时，操作停止并保留现场。满箱后的物品选择见[满箱对换](#满箱对换)。

**验证范围。** 当前识别和流程测试的证据如下：

| 场景 | 测试素材或方式 | 验证限制 |
| --- | --- | --- |
| 四格安全箱的局内识别 | [原生截图](../../../game/screens/贝果计划.md#安全箱格子) | 用于核对局内识别 |
| 两格、三格安全箱和小容量仓库 | 合成测试画面 | 只能验证离线识别，不能证明相应画面的实机执行效果 |
| 1440p 抓图缩放 | 模拟抓图，经真实截图控制器的默认缩放入口后识别 | 对应分辨率尚未由这些测试完成实机验收 |
| 容量识别、入箱、对换、入仓和未知状态保护 | 离线回归 | 小容量安全箱的完整收集和入仓流程尚未完成实机验收 |

仓库合成图以仓库实拍为底，保留仓库格框和背景。测试只在未开放格移植局内实拍的锁图标和文字，不将局内整排格子平移后当作仓库画面。异常分类测试包含模板缺失、灰色遮挡和面板过渡的代表场景。流程测试仍检查未知结果不能继续操作。

**搜查中拾取。** 武备箱或电子保险箱进入「搜查中」后，收集操作开始观察结果格。物品格连续两帧外观稳定时，操作按品质和类型顺序拖入空安全箱。每件物品拖入后都重新读取结果核验。

安全箱满时，操作等待明确的「搜索结果」状态，再判断是否对换，避免误识别动画中的角标。没有可装物品时，操作继续等待。只有明确看到「搜索结果」后，操作才允许关闭面板或退出局内。安全箱满或暂时没有结果均不能作为提前结束依据。

#### 物品识别与优先级

识别函数用格子左右两侧底色判断品质，用左上角标判断类型。颜色和类型说明见[画面文档](../../../game/screens/贝果计划.md#格子)。入箱不按物品名单筛选，而是依次比较以下条件：

1. 非材料物品优先于材料。
2. 同为材料或同为非材料时，按品质排序：`Z > S > A > B > C > 未知`。
3. 非材料品质相同时，依次优先选择贵重物品、战术棱镜、装备、门禁卡、战术道具和其他。

品质和类型优先级均相同时，操作不对换。金币留在搜索结果中，不占安全箱。每次只拖 1 件，再重新读取结果核验。

#### 满箱对换

安全箱满时，操作只用优先级严格更高的搜索结果物品，替换箱内优先级最低的物品。材料可以参与对换。拖拽前后，两格必须确实发生变化。

对换后，原结果格会留下安全箱换出的物品。即使该格的品质和类型发生变化，操作也不再对换该格，避免来回交换。

没有可对换物品时，操作按搜查完成条件关闭面板，不将物品拖入背包，也不记为失败。

#### 搜查状态暂缺与拖拽核验

收集操作中的文字漏识别与面板过渡共用[面板等待上限](#搜查面板可操作性)。正式执行器在收集和关闭步骤入口另设搜查状态等待预算，最多额外等待 5 轮；入口规则如下：

| 条件 | 处理 |
| --- | --- |
| 对应容器标题仍在，搜查状态暂时漏识别 | 等待期间不发送输入。状态恢复后才运行子操作 |
| 容器标题不符 | 立即停止 |
| 拖拽后等待核验 | 保留原始前后对照，不补拖 |
| 拖拽核验时标题消失 | 已确认回到局内则报告中断；其他情况有界等待并保留拖前数据 |
| 状态持续漏识别 | 达到面板等待上限后停止并保留现场 |

#### 拖拽时序

首次入箱、满箱对换和失败后的重拖，统一使用 `duration=0.8`、`press_time=0.1`。鼠标按下后额外等待 0.1 秒，让游戏有时间抓起物品，避免操作变成结果列表滚动。

填空时，面板稳定且目标格由空变有就记为成功，源格占用仅作辅助，不能对已占用的目标再拖。源格有物、目标仍空时最多额外重拖三次（首次加重拖共四次），每次保持同一目标。对换维持额外重拖一次。两格都空时先等一帧，仍未入箱则停止；未知格、锁定格及面板中断沿用原有保护。

等待时间独立于移动时长。操作仍需核对拖拽前后两格的变化。完成等待不能作为入箱成功依据。控制器默认值和前后台行为见[拖拽按下等待](../../one_dragon/background_mode_design.md#拖拽按下等待)。

#### 品质与角标识别

品质识别取格子两侧底色的 HSV（色相、饱和度、亮度）中位数。色相范围如下：

| 品质 | 色相范围 |
| --- | --- |
| B | 90–119 |
| A | 120–160 |
| C | 50–85 |

饱和度或亮度低于 40，或色相未匹配色带时，识别函数返回未知，不默认归为 B 或 C。

**角标模板裁剪。** 角标模板按图案轮廓选择位置和尺寸。白色图案必须完整保留，上下左右留白接近。裁剪偏移应通过重新裁剪修正，不能通过降低匹配阈值弥补。

白色箱子的两张模板统一归为材料。未匹配的角标按其他处理。模板类型和尺寸见[贝果画面「格子」](../../../game/screens/贝果计划.md#格子)。

#### 收集与关闭的职责

正式应用和开发执行共用收集行为。搜查完成后，收集操作保留面板，由独立关闭步骤负责关闭。

搜查或搬运期间确认面板消失并回到局内后，子操作报告中断，无须识别实际攻击来源。正式应用按[搜查中断判据](#搜查中断处理)退出重开，开发工具保留现场。两者均不在原地补开容器。

### 搜查中断处理

收集、关闭搜查或光圈解锁发生可恢复业务失败或实际超时时，执行器读取新截图。只有同时满足以下条件，才判为搜查中断：

- 已回到贝果局内。
- 武备箱和电子保险箱的搜查面板均已消失。
- 解锁提示已消失。

步骤入口已被打断时，执行器使用同一判据。正式应用按[整体重试](bagel_failure_retry.md)退出到仓库，核对安全箱物资入仓后，再决定是否重开。中断局不计成功。

未知画面、面板仍在时的拖拽错误，以及退出或入仓失败，均停止。开发工具只返回中断状态，不自行退出或补开容器。

### 入仓核验

点击「放入仓库」后，操作同时核对安全箱和仓库占用。仓库「全部 N/M」中的 N 表示占用，M 表示当前界面显示的实际容量。M 不能固定取 280。下表中的占用变化均与点击前读数比较。

| 结果 | 判定与处理 |
| --- | --- |
| 安全箱清空，N 增加 | 入仓成功。包括占用从 `(M−1)/M` 增至 `M/M`，恰好满仓的情况 |
| 安全箱清空，N 不变，且 N<M | 入仓成功。允许物品合并到已有堆叠 |
| 安全箱清空，N 不变，且 N≥M | 正式结算允许满仓合并堆叠；独立入仓工具仍保留原保护 |
| 安全箱清空，但 N 下降或必要读数无法核对 | 停止，不计入仓成功 |
| 安全箱只减少部分格子 | 正式结算交给一次出售后再入仓；独立入仓工具仍停止 |
| 安全箱格子完全未变 | 允许有限重试或判满仓 |
| 安全箱仍占用，且 N≥M 连续 6 帧 | 记为仓满并停止 |

正式结算的满仓或残留处理见[出售间隔与残留处理](bagel_sale_interval.md)。独立入仓、独立清理工具默认仍保留原保护。入仓核验不按物品名称判断。

入仓成功后，正式应用按清理开关处理仓库，再执行[出售与结算核验](#出售与结算核验)。安全箱为空且容量可读即可结束结算并返回入口；仓库已满不再阻断。入仓后恰好满仓时，正式应用仍可按现有清理规则提前出售一次。

### 仓库清理与返回

#### 出售方案

清理开关默认开启。关闭时，正式应用只执行入仓。出售按以下方案选择：

| 方案 | 类型 | 品质 |
| --- | --- | --- |
| 默认 | 贵重物品、战术棱镜、其他。不选装备、战术道具和门禁卡 | C/B/A/S。不选 Z |
| 自定义 | 使用配置中选择的类型，不能为空 | 使用配置中选择的品质，不能为空 |

快速选择中的类型和品质必须同时匹配，物品才会进入出售范围。「全部」始终不选。操作每次重新读取所有选项，并取消方案未选的项目。清理流程不点击整理，也不自动转化货币。

**空箱结算只跳过出售。** 入仓操作确认安全箱原本为空时，清理节点跳过出售，但继续执行末尾的安全箱和仓库容量核验；不能直接结束结算。空箱时不清理已有库存，与清理开关和出售方案无关，正常局和失败收尾均适用。核验通过后仍返回原有空箱状态，沿用现有成功、空箱及失败计数规则。

#### 出售与结算核验

出售间隔、提前出售、残留再入仓和最终核验均见[出售与入仓重试](bagel_sale_interval.md)。本节只维护出售筛选方案和返回操作。

**返回时的页面阻挡。** 仓库返回时先等待加载结束，再核对达塔名称和可交互按钮，按 F 与达塔交互，打开贝果主界面。后续各局直接从主界面选图。返回加载和点击「出发出发」后的切换黑屏均继续等待；单凭连续未识别到 HUD 不触发恢复。恢复触发条件和等待上限见[整体重试说明](bagel_failure_retry.md#页面阻挡恢复)。确需通用恢复时，正式应用随后重新检查入场条件。页面恢复不改变任务计数或首次清空资格。

**返回时的奖励提示。** 结算仓库点击「返回研究站」后，若同时识别到「撤离奖励提示」和奖励转移说明，返回操作只确认 1 次，再等待研究站 HUD。

## 3. 配置（`BagelConfig`）

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `max_success_rounds` | 1 | 成功局数上限，范围为 0–1000。0 表示不限成功次数。非支持出生点和失败局不计数 |
| `max_failure_retries` | 5 | 累计整体重试次数上限，范围为 0–100。最多因失败额外重开 N 局，成功后不清零 |
| `auto_clean_warehouse` | 开 | 关闭时只入仓，开启时按间隔或满仓/残留规则出售；空箱规则见上文 |
| `sell_interval` | 1 | 本任务非空入仓次数，范围为 1–999，包含失败局带回物资。1 表示每次都卖；正常结束补卖。关闭清理时不出售 |
| `clean_mode` | `default` | `default` 使用固定组合。`custom` 使用下面两组选择 |
| `clean_types` | 空 | 自定义出售类型。可选贵重物品、战术棱镜、其他、装备、战术道具和门禁卡，不含「全部」 |
| `clean_qualities` | 空 | 自定义出售品质。可选 C/B/A/S/Z |

任务配置页位于主窗口内，可以滚动。设置自动保存，并绑定当前账号和应用组。进入页面加载配置时，页面不写回配置。

| 条件 | 显示的设置 |
| --- | --- |
| 始终 | “成功次数”“整体重试次数”“清理仓库” |
| 开启清理 | 出售方案 |
| 开启清理且选择自定义方案 | 出售类型和品质，两者均须非空 |

### 开发工具与发布流程

`flow.yml` 是正式业务步骤和路点的唯一来源。`BagelApp` 启动时加载不可变流程快照，并调用与开发工具相同的 `BagelRunFlow`。外层应用负责入场、结算、清理和重开。

开发草稿不影响正式任务。只有导出正式流程才会修改发布资源。

开发工具从源码独立启动，普通设置页不提供入口。启动命令、步骤编辑、参数、保存和文件导入说明见[贝果流程开发工具](bagel_flow_editor.md)。地图资源和坐标规则见[固定地图说明](bagel_fixed_map.md)。

### 执行与输入清理

正式应用和操作基类为每次执行分别包装暂停、恢复回调。执行结束时，清理按以下顺序进行：

1. 停用本次执行的订阅。
2. 等待已开始的回调完成。
3. 从运行总线解绑。

初始化或收尾异常也使用该清理流程，避免上一次执行的回调影响下一次执行。

局内执行器和开发试跑共用输入清理函数。暂停和收尾时，函数重置持续按键，并额外释放定时前进、交互和鼠标拖拽。后台拖拽还向游戏窗口发送左键松开消息。清理不会取消正在执行的拖拽循环。

## 5. 功能限制

- 入箱不按物品名称和等级筛选，也不记录按名单收集的进度。

## 6. 测试与验证范围

选图免重复点击、入场弹窗短间隔观察和仓库筛选等待的规则，见[等待优化](bagel_speedup.md)。不改变清理开关、出售范围或任务计数。

## 正式任务的提示

设置文案与运行提示由 `bagel_usage.py` 管理。正式应用校验通过后记录配置摘要；收尾结果与停止原因仍由原有操作返回。成功结束的位置来自返回操作的实际状态，未确认时不声称已返回入口。截图接口返回名称，提示层确认文件存在后才展示完整路径。

定位等待通过可选回调向正式应用报告。回调不改变导航的输入、等待时间或失败预算；开发试跑不传入该回调。配置、出售规则、节点状态、计数和重试行为保持原样。

返回入口使用完整入口特征等待。判据、时限和不用全屏稳定检测的理由见[整体重试](bagel_failure_retry.md#为什么不用全屏稳定检测)。
