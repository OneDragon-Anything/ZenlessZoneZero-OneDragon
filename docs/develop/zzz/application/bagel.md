# 贝果计划（自动化方案）

> 本文讲怎么自动化贝果计划（脚本流程、配置、前置、设计决策）。
> 玩法见 [gameplay/贝果计划.md](../../../game/gameplay/贝果计划.md)，画面见 [screens/贝果计划.md](../../../game/screens/贝果计划.md)。

**启动清空**：每次启动的首次入场允许清空携带物；背包与安全箱都为空时直接快速双击右侧槽位逐件卸装，否则先在仓库点击「放入仓库」批量转存内容物再卸装，包括处理仓库遗留物；同次运行后续局继续严格检查。范围、停止条件、识别方式与实机验证限制见[启动时自动清空战备](bagel_clear_loadout.md)。

**当前范围**：高危雅努斯、零携带、零投资。只跑两条短线：录像店复活点（武备箱后再开电子保险箱）、白鸽工地地铁站复活点（只开武备箱）。其它出生点退出重开，不清理仓库。不投资、不购买。出现在一条龙列表里，排在驱动盘拆解之后、通知之前；已经保存过的一条龙顺序不会被改掉。新加进列表时默认关闭，打开后才和其他日常一起排队。

## 1. 脚本流程

`BagelApp` 从已识别的安全画面进入研究站，循环到成功次数上限（默认 1；填 0 不限成功次数）：

1. 校验配置并读取两个出生地的发布流程快照（`flow.yml`）。是否可以开新局，以入场时当前画面的零携带核验为准。
2. 首次启动若在贝果仓库，先点击「放入仓库」批量转存携带物，再返回备战或研究站入口；不调用结算出售，不增加成功局数。已在入口或选图时继续；已在备战时先返回选图，重新选择并核对雅努斯高危；否则只从普通大世界、地图、菜单、快捷手册、普通仓库或达塔对话调用地图传送到奥蒙德研究站「迷宫诡域」。启动时已在达塔前或达塔对话中，也先走通用返回大世界与地图传送，不就地打开入口。传送落地后再识别达塔并交互打开入口。首次备战识别为非零时清空，复核零携带后再核对零投资；后续局非零则停止。未知画面及其他玩法局内停止留现场。
3. 用小地图认出生点。
4. 录像店复活点：到武备箱 → 开箱 → 装入安全箱 → 到电子保险箱 → 按光圈解锁 → 再装入 → 主动退出 → 入仓，并按开关清理。
5. 白鸽工地地铁站复活点：到武备箱 → 开箱 → 装入安全箱 → 主动退出 → 入仓，并按开关清理。按小地图路点配准导航，不做遇敌恢复。
6. 其它出生点：退出并返回入口，不清理也不计成功局数；没有尝试次数上限。
7. 导航、开箱、入箱、解锁途中出现整局失败结算，或搜查/解锁被打断且确认回到局内：退出到仓库，同样入仓并按开关清理，不计成功。结算核验通过后，前两次失败返回入口自动重开；连续第 3 次失败仍先完成仓库结算，再停在仓库。正常有物入仓的成功局将连续失败次数清零；空箱局和非支持出生点不清零。退出、入仓、清理或返回入口失败时直接停止，保留原始错误和现场，不继续重开。
8. 安全箱有物且确认入仓并完成清理（清理关闭时只入仓）后计成功一局；空箱局返回研究站入口但不计数，连续 3 次空箱后停止。正数上限达到后成功结束；填 0 时不按成功次数结束，仍受失败、异常和空箱停止条件约束。入仓、清理失败或清完仍满则停在现场，不继续下一局。

## 2. 设计决策

### 入场与携带核验

**多画面入场边界。** 已有贝果入口直接复用；首次启动的贝果仓库先按[启动清空流程](bagel_clear_loadout.md)核验转存再返回。普通大世界（包括达塔前）、达塔对话、菜单、快捷手册和普通仓库统一交给已存在的返回大世界与地图传送流程，传送失败立即停。达塔对话只作为允许传送的已知画面识别，不在启动时点击「出发出发」；达塔交互仅在本次传送后执行，避免为这两个起点保留另一套入场动作。音擎、驱动仓库属于其他应用的局部画面，贝果入口在全局识别失败时只按完整仓库标题补认，不能把普通仓库误当作贝果结算仓库。战斗、其他玩法内部和未识别画面不自动退出或盲点。

**入场只核对当前携带。** 备战页的武备、装备、道具价值必须明确为 0，背包和安全箱必须明确为零占用。识别不全最多读取五帧，期间不操作物品；持续不明则停止。仅正式应用每次启动的首次入场允许先清空非零携带。仓库可以有库存；自动收集须满足画面白名单与零投资条件，并完成本局结算核验。

**后续局遗留物资禁止开新局。** 首次启动可以恢复仓库携带物，但不计成功；同次运行后续入场前若仍在结算仓库且安全箱有物资，停止并保留现场。清空资格在第一次入场前消耗，不等出生识别或局数增加；暂停恢复不会重置。任何启动清空失败都直接停止，不自动出售腾位。

### 价值读取

按以下顺序读取武备、装备和道具价值：

1. 识别备战右侧完整面板，排除左侧库存。从识别结果中筛选三个标题条区域。只有对应标题完整匹配，且数值恰好是一段纯数字时，才采用该结果。
2. 面板结果不满足条件时，裁出完整标题条重新识别。优先采用唯一一段纯数字；没有纯数字时，才从唯一一段「1–2 个非数字前缀 + 完整数值」中提取数字。
3. 裁图仍无法解析时，识别整屏，并要求标题匹配且数值是唯一一段纯数字。各路径均无法解析时，返回空字符串，按未知处理。

判为零前，须核对该区域所有已获得的文字。任一结果包含非零数字，就返回空字符串，拒绝零携带入场。例如，`0` 与 `@500` 同时出现，或面板读到 `500` 而标题条裁图只剩 `0`，都不能放行。

标题条必须包含完整数值，不能只截末尾。不做亮白过滤，避免道具价值 `0` 被读成 `O`。背包、安全箱和投资金额分别裁出各自的完整区域读取；投资金额保留独立颜色过滤与严格零值校验。

### 投资金额归零

识别到投资页后，根据完整金额决定动作：

| 读数 | 动作与完成条件 |
| --- | --- |
| 正整数，或带 `K/M` 的正数，如 `500K`、`1.5M` | 点击 MIN。点击成功后等待 1 秒，下一轮重新截图读取金额 |
| 初始或复核金额精确为 `0` | 点击「前往空洞」；点击成功才记为已确认投资 |
| 空值、`O`、`00` 等不明确读数 | 只重新读取，不发送输入 |

点击 MIN 成功不代表金额已经归零。非零归零与读数不明共用三次重试预算，MIN 找不到或点击失败也占一次。预算耗尽后再读一帧；仍不是 `0` 时，停止并保存现场。

投资重试预算单独记录，避免节点等待重置框架重试次数。重复执行时清零预算；已点击入场后，不重复归零或确认。

### 出生识别与导航

**只认两条出生点。** 其它点退出重开，不漫游找箱。

**出生前确认局内。** 入场操作确认雅努斯高危后，出生识别再检查普通攻击按钮；单帧模板漏识别最多复看 3 帧，持续不符就停止留现场，不算一次出生检查。

**固定小地图定位。** 出生识别、正式导航和开发工具共用固定底图；同次执行使用同一份地图快照。定位失败时停止移动，即使出现路边可拾取物的 F 提示也不能继续前进；重新取得当前帧位置后才允许继续忽略拾取提示移动。不提供自动绕障。资源、坐标和匹配规则见[固定地图说明](bagel_fixed_map.md)。

**录像店复活点走路。** 先到武备箱，再经巷口、楼角和接近点靠近电子保险箱。路点坐标、切段范围和各步骤移动参数以 [录像店发布流程](../../../../assets/game_data/bagel/janus_high_a/flow.yml) 为准。接近点可提前松键，等待停稳后用新截图核对位置；未到达时继续当前步骤内的短步调整，不能把提前松键当作到达。最终靠近步骤按当前位置朝目的地调整，目标附近出现交互提示才完成；到点后停步等待两秒，仍无提示则失败。参数含义见[开发工具的地图与参数](bagel_flow_editor.md#地图与参数)。

**白鸽工地地铁站复活点走路。** 与录像店共用路点导航，按当前位置到下一路点的方向转向，远处连续前进、近处短步。路点与移动参数以 [白鸽发布流程](../../../../assets/game_data/bagel/janus_high_b/flow.yml) 为准。到达目标附近且出现武备箱提示才完成；到点后等待两秒仍无提示则失败，定位不足时松键。

**贴墙卡位停止。** 电子保险箱远段按住前进期间，若配准位置连续 3 秒没有离开 2 像素范围，松键并报告失败，保留现场。该防护只限制卡位耗时，不负责自动绕障。暂停时松键并清除卡位计时，恢复后重新校准朝向，暂停时间不计入持续前进时间。

**步骤入口定位暂缺等待。** 出生检查、移动和靠近步骤在局内 HUD 已确认、但当前帧几何证据不足（`insufficient_geometry`）时，每隔 0.3 秒重新截图检查，最多等待 5 次；期间不发送移动或交互输入，不推进步骤，也不用上一帧坐标代替本帧定位。恢复后才执行当前步骤，并清零等待次数；再次初始化也清零。持续失配停止并留现场，不按非支持出生点退出重开。位置冲突、超出底图覆盖范围、裁图错误、出生位置不符及其它画面前置错误仍立即停止，不降低定位门槛。正式任务与开发工具共用此规则。

**首次导航定位暂缺等待。** 步骤入口通过不等于后续截图都能定位。进入子导航后，在首次取得导航位置之前，若新截图仍为 `insufficient_geometry`，先松开前进键，每隔 0.3 秒重新截图，最多等待 5 次，第 6 次仍失配则保留原定位失败状态停止。等待不移动、不转向、不交互、不切换路点，也不借用入口坐标；取得本帧可靠位置后清零等待次数并继续导航。再次初始化清零预算；位置冲突、超出覆盖范围或非法裁图不等待。已经取得导航位置后若连续失配，最多等待 3 次，每次间隔 0.15 秒。

### 容器交互与解锁

**交互看提示条，不看头顶名字。** 右侧 F 图标用模板，不用字母识别。交互步骤要求局内 HUD、目标提示和 F 图标同时出现；搜查面板还在时不按。

**局内判断复用普通攻击按钮。** 入场、出生识别、导航、容器交互、搜查中断和退出统一使用 `战斗画面/按键-普通攻击` 的既有模板与阈值，不读取左侧计分文字。电子保险箱仍须命中对应交互提示，正式执行器还要求 F 图标；普通武备箱缺少攻击按钮时等待，确认攻击按钮和交互提示后才按 F。已在解锁或搜查面板时仍按对应面板判断，不补按 F。

**电子保险箱按光圈点。** 先看到小圈，再等红圈或黄圈扩到候选半径，每轮只按一次，共 4 次。提示消失就停。四次按完仍要等到搜查面板，不能按次数当成打开成功；搜查结束由逐件入箱流程确认。

### 收集与对换

**容量适配待验证。** 安全箱与仓库的容量范围见[备战物资与仓储](../../../game/gameplay/贝果计划.md#备战物资与仓储)。收集、对换与空箱核验须以当前安全箱的实际容量和可用格子为准，不能固定按五格判断。小容量安全箱的图片资源及识别验证尚待补充，见[图片资源待办](../../../game/screens/贝果计划.md#待补充的安全箱图片资源)；本文不将这些分支标为已支持或已验收。

**搜查中拾取。** 武备箱或电子保险箱进入「搜查中」后就观察结果格。物品格连续两帧外观稳定才按现有品质与类型顺序拖入空安全箱，每件仍回读核对；箱满时等明确看到「搜索结果」再判断是否对换，避免动画中的角标误判。无可装物品继续等待。只有明确看到「搜索结果」才允许关闭面板、退出局内，不能因安全箱满或暂时没有结果而提前结束。

#### 物品识别与优先级

用格子左右两侧底色判断品质，用左上角标判断类型。颜色与类型说明见[画面文档](../../../game/screens/贝果计划.md#格子)。入箱不按物品名单筛选，依次比较以下条件：

1. 所有非材料物品都优先于材料。
2. 同为材料，或同为非材料时，按品质排序：`Z > S > A > B > C > 未知`。
3. 非材料品质相同时，依次优先选择贵重物品、战术棱镜、装备、门禁卡、战术道具、其他。

品质与类型优先级都相同时，不对换。金币留在搜索结果，不占安全箱。每次只拖一件，再读取结果核验。

#### 满箱对换

箱满时，只用严格更优的结果对换箱内优先级最低的物品。材料也可以参与对换，但必须核对拖拽前后两格确实变化。

同一结果格对换后会留下安全箱换出的物品。即使品质和类型变了，也不再对换该格，避免来回交换。没有可对换物品时，按搜查完成条件关闭面板；不拖进背包，也不记失败。

#### 搜查状态暂缺与拖拽核验

搜查状态偶尔漏识别时，最多等待 5 帧。正式执行器的收集、关闭步骤入口也遵循以下规则：

| 条件 | 处理 |
| --- | --- |
| 对应容器标题仍在，搜查状态暂时漏识别 | 等待期间不发送输入；状态恢复后才运行子操作 |
| 容器标题不符 | 立即停止 |
| 拖拽后等待核验 | 保留原始前后对照，不补拖 |
| 拖拽核验时标题消失，或状态持续漏识别 | 停止 |

#### 拖拽时序

首次入箱、满箱对换和失败后的重拖统一使用 `duration=0.8`、`press_time=0.1`。按下后额外等待 0.1 秒，给游戏时间抓起物品，避免拖成结果列表滚动。

等待独立于移动时长。仍须核对拖拽前后两格的变化，不能因已等待就认定入箱成功。控制器默认值和前后台行为见[拖拽按下等待](../../one_dragon/background_mode_design.md#拖拽按下等待)。

#### 品质与角标识别

品质识别取两侧底色的 HSV 中位数。B 色相为 90–119，A 为 120–160，C 为 50–85。饱和度或亮度低于 40、未匹配色带时仍返回未知，不用 B、C 兜底。

**角标模板保留完整图案。** 角标模板按图案轮廓选择位置与尺寸；白色图案完整保留且上下左右留白接近，不通过降低匹配阈值弥补裁偏。白色箱子的两张模板统一归为材料，未匹配的角标仍按其他处理。模板类型与尺寸见 [贝果画面「格子」](../../../game/screens/贝果计划.md#格子)。

#### 收集与关闭的职责

正式任务与开发执行共用同一收集行为：搜查完成后保留面板，关闭由独立步骤负责。面板被打断后子操作停止；正式应用按[搜查中断判据](#搜查中断处理)退出重开，开发执行保留现场。不在原地补开容器。

### 搜查中断处理

收集、关闭搜查或光圈解锁步骤失败时，用新截图确认已回到贝果局内，且两种容器面板和解锁提示均消失，才记为搜查中断。步骤入口已经被打断时使用同一判据。正式应用退出到仓库，核对安全箱物资入仓后返回入口自动开新局；中断局不计成功，与撤离失败共用连续三局失败停止上限。未知画面、仍在面板上的拖拽错误和退出入仓失败仍停止。开发工具只返回中断状态，不自行退出或补开容器。

### 入仓核验

点击「放入仓库」后，同时核对安全箱和仓库占用。仓库「全部 N/M」中的 N 表示占用，M 表示当前界面显示的实际容量，不能固定取 280。下表中的占用变化均与点击前的读数比较。

| 结果 | 判定与处理 |
| --- | --- |
| 安全箱清空，N 增加 | 入仓成功；包括占用从 `(M−1)/M` 增至 `M/M` 后恰好满仓的情况 |
| 安全箱清空，N 不变，且 N<M | 入仓成功；允许物品合并到已有堆叠 |
| 安全箱清空，N 不变，且 N≥M | 停止；不能凭堆叠推测物资已入仓 |
| 安全箱清空，但 N 下降或必要读数无法核对 | 停止，不能记为入仓成功 |
| 安全箱只减少部分格子 | 立即停止，不重复点击，也不继续清理 |
| 安全箱格子完全未变 | 才允许有限重试或判满仓 |
| 安全箱仍占用，且 N≥M 连续 6 帧 | 记为仓满并停止 |

安全箱仍有物资时，禁止批量出售并保留现场。入仓核验不按物品名称判断。

入仓成功后，按清理开关处理仓库，再执行[出售与结算核验](#出售与结算核验)。仓库未满是结算结束、允许返回入口的条件；入仓后恰好满仓仍可进入清理流程。

### 仓库清理与返回

#### 出售方案

清理开关默认开启；关闭时只入仓。出售选择按以下方案执行：

| 方案 | 类型 | 品质 |
| --- | --- | --- |
| 默认 | 贵重物品、战术棱镜、其他；不选装备、战术道具、门禁卡 | C/B/A/S；不选 Z |
| 自定义 | 使用配置中选择的类型，不能为空 | 使用配置中选择的品质，不能为空 |

快速选择中，类型和品质两组同时勾选才出售对应物品。「全部」始终不选。每次回读所有选项，并取消方案未选的项目。不点击整理或自动转化货币。

#### 出售与结算核验

1. 在仓库主界面确认安全箱为空后，才进入批量出售。仓满且安全箱有物资时停止；出售范围与安全腾位方式仍待确认。
2. 筛选件数为 0 时，确认筛选后取消出售。有件数时，才进入出售预览并确认。
3. 出售后，确认安全箱仍空且仓库占用下降；否则不能报告清理成功。
4. 结算末尾，用新截图再次确认安全箱为空、仓库占用小于容量。清理关闭或没有可出售物品时，也必须完成这一步。仓库仍满时留在仓库，不计成功，也不返回入口。

**返回时的奖励提示。** 结算仓库点「返回研究站」后，若同时识别到「撤离奖励提示」和奖励转移说明，只确认一次，再等待研究站 HUD。

## 3. 配置（`BagelConfig`）

| 字段 | 默认 | 应用是否使用 |
|---|---|---|
| `max_success_rounds` | 1 | 0–1000 的成功局数上限；0 不限成功次数。非支持出生点和失败局不计数 |
| `auto_clean_warehouse` | 开 | 关闭时只入仓；开启时按方案出售 |
| `clean_mode` | `default` | `default` 使用固定组合；`custom` 使用下面两组选择 |
| `clean_types` | 空 | 自定义时的类型，可选贵重物品、战术棱镜、其他、装备、战术道具、门禁卡，不含「全部」 |
| `clean_qualities` | 空 | 自定义时的品质，可选 C/B/A/S/Z |

任务配置页使用主窗口内的可滚动设置页，设置自动保存，并绑定当前账号与应用组。“成功次数”和“清理仓库”始终显示；开启清理后显示出售方案，选择自定义后显示出售类型与品质，两者均须非空。进入页面加载配置时不写回。

### 开发工具与发布流程

`flow.yml` 是正式业务步骤和路点的唯一来源。`BagelApp` 启动时加载不可变流程快照，调用与开发工具相同的 `BagelRunFlow`；外层应用负责入场、结算、清理和重开。开发草稿不影响正式任务，只有导出正式流程才修改发布资源。

开发工具从源码独立启动，普通设置页不提供入口。启动命令、步骤编辑、参数、保存与文件导入说明见[贝果流程开发工具](bagel_flow_editor.md)；地图资源与坐标规则见[固定地图说明](bagel_fixed_map.md)。

### 执行与输入清理

贝果正式应用和操作基类为每次执行单独包装暂停、恢复回调。结束时停用订阅，等待已经开始的回调完成，再从运行总线解绑；初始化或收尾异常也走同一清理路径，防止上一次执行的回调影响下一次执行。

局内执行器与开发试跑共用输入清理函数：暂停和收尾时重置持续按键，并额外释放定时前进、交互及鼠标拖拽；后台拖拽另向游戏窗口发送左键松开消息。清理不取消正在执行的拖拽循环。

## 4. 使用前置

- 研究站及「迷宫诡域」传送点已解锁；从普通大世界、地图、菜单、快捷手册、普通仓库、达塔对话或贝果入口启动。
- 高危雅努斯可以零携带、零投资进入。
- 跑图角色和镜头设置会影响位移，换角色后需检查路线是否仍可通行。

## 5. 功能限制

- 不按物品名称和等级筛选入箱，也不记录按名单收集的进度。
- 不拾取金币，不把携带货币计入已入仓物资；货币退出保留规则见[玩法文档](../../../game/gameplay/贝果计划.md)。

测试位于独立仓 `zzz-od-test/test/zzz_od/application/bagel/`，运行方式见[测试文档](../../testing/README.md)。

投资归零的离线流程测试使用实际 `500K` 投资页、归档零投资页和明确标注的合成金额帧，覆盖初始为零、非零归零、画面更新延迟、点击失败、MIN 未识别、画面不变和 OCR 不明；失败还核对没有点击入场且保留最后截图。
