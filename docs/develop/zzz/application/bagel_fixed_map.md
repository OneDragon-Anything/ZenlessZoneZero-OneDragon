# 贝果固定小地图

## 用途与坐标

录像店（A）和白鸽工地地铁站（B）使用预先生成的压暗背景底图，供出生识别、正式导航和编辑器共用。应用流程见[自动化方案](bagel.md)，编辑操作见[流程开发工具](bagel_flow_editor.md)。

底图按源帧对齐后融合：取颜色通道最小值，再按像素取时间第 25 百分位。A、B 各自沿用出生参考图坐标；路线坐标等于底图像素坐标加 `origin_xy`。路点和移动参数由 `flow.yml` 管理，不从底图推导。

## 实现约束

- 特征提取与几何匹配分离。匹配结果必须满足双向匹配、内点数量和比例、空间分布、缩放、旋转及残差门槛。
- 固定地图加载、结构校验、特征缓存和坐标转换由定位模块负责。图像匹配不发送游戏输入；外层负责定位暂缺等待、停止与松键。
- 地图快照不可变。新执行读取最新资源；同一执行及其子导航共用已加载快照，不因磁盘资源变化中途切换。
- 有效像素遮罩仅表示像素来源，不能用玩家锚点处的一个遮罩像素来判定位置是否合法。需要足够的周边匹配证据，并拒绝覆盖范围外或有空间竞争结果的位置。
- 大图预处理必须与 201×201 实时小图单独核对；尤其不能假定相同 CLAHE 网格数在不同图像尺寸上等价。
- 底图只使用源素材中的有效像素，不用生成式补图或推测道路。底图可能保留白色图标，定位仍须经过几何匹配和竞争位置检查。
- 正式任务与开发试跑统一使用固定底图；普通任务不提供定位算法切换设置。

## 资源与定位

每张地图位于 `assets/game_data/bagel/<map_id>/`：

| 文件 | 用途 |
|---|---|
| `map.png` | 压暗背景底图，透明区表示没有有效来源 |
| `map_mask.png` | 与底图透明通道一致的二值有效像素遮罩 |
| `map.yml` | 地图身份、坐标版本、原点、识别参数和地标 |
| `flow.yml` | 正式流程、路点和移动参数 |

底图尺寸、原点和出生坐标以各地图的 `map.yml` 为准。

`BagelFixedMap` 校验资源后缓存底图特征，并将数组和识别参数设为只读。缓存按元数据及图片内容区分快照；新执行重新读取磁盘，已有执行继续持有原快照。快照编号仅在当前进程内标识一次加载，不用于跨运行内容比对。编辑器直接显示底图，试跑开始前重新加载并把同一快照交给执行器。

定位先取最小颜色通道抑制彩色背景，再匹配整图和重叠的 201×201 分区。A 优先使用 CLAHE，分区步长 100；B 优先使用高通处理，分区步长 80。两张地图均保留另一种表示，仅在当前表示没有合格匹配时尝试。整图特征只提取一次，分区复用描述子距离；反向最近邻也只计算一次。

任意合格位置相差超过 5 像素时直接拒绝；两张地图同时判为出生也拒绝。有效遮罩只填充封闭的内部孔洞用于判断位置范围，不向地图外扩张，也不表示道路可通行。定位失败时沿用停步、重试和最终松键处理。

## 新录像建图

建图工具从新录像抽取小地图（区域取画面配置中的“定位小地图”）、匹配静态特征并融合底图，不依赖旧录像或逐帧来源清单。输入采用原生 1080p：从对应出生点开始，角色先静止且小地图完整显示，再连续走完采集区域。首段稳定画面的玩家中心建立 `(100, 100)` 原点；出生身份由采集者确认，工具不能仅凭静止画面证明出生位置。

工具通过双向特征匹配、几何残差及运动范围校验计算相似变换。短暂识别失败可以跳帧，但必须在限定时间内重新建立与已接收帧的可靠关系，否则停止；不推测丢失期间的道路。累计旋转不得超过 2°、尺度须在出生画面的 98%–102% 内；融合使用同一累计变换，不能把旋转或缩放当作平移。中心和高亮动态标记不参与底图融合。输出只包含有效观测区域，不生成路线。

结果写入新的独立目录，拒绝覆盖已有目录。验收后停止使用地图的任务，再整组替换正式底图及元数据；新地图的流程坐标必须重新核对，不保证旧流程可直接复用。结构校验不能识别所有同尺寸资源混装。

在主仓根目录查看参数：

```powershell
uv run --env-file .env python tools/bagel/build_fixed_map.py --help
```

使用 `--map-id` 指定现有地图的识别参数，`--video` 指定新录像，`--output` 指定尚不存在的输出目录。使用 OpenCV 解码，默认每秒采样 5 帧，可通过 `--sampling-fps` 在 2–20 帧间调整。输入最多十分钟，开头至少静止三个采样帧；位移门槛为每秒 80 地图像素加 2 像素误差，连续匹配空段不得超过一秒。输出最大边长为 4096，融合暂存上限约 1 GiB，超过时需缩短录像或降低采样帧率。保留必要构建参数和接收/拒绝帧数，不将本机输入路径写入元数据。

## 测试与验证范围

主要测试入口为录像或受控帧序列到资源输出，再由运行加载器加载和定位。覆盖已知位移、坏帧拒绝、静止原点、输出保护、尺寸及遮罩一致性；现有定位与流程回归覆盖出生、导航、证据不足、位置冲突和范围边界。

受控位移样本只能证明算法和输入输出约束。新录像建图仍需独立真实录像及保留帧验收，不能以离线通过代替游戏内路线验收。重复纹理和累计漂移仍需人工核对。

相关测试位于独立测试仓 `zzz-od-test` 的 `test/zzz_od/application/bagel/bagel_fixed_map/` 和 `test/zzz_od/application/bagel/bagel_map_builder/`，运行方式见[测试文档](../../testing/README.md)。
