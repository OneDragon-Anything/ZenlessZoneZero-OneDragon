# 贝果固定小地图

## 用途与坐标

录像店（A）和白鸽工地地铁站（B）使用预先生成的压暗背景底图。出生识别、正式导航和编辑器共用这些底图。应用流程见[自动化方案](bagel.md)，编辑操作见[流程开发工具](bagel_flow_editor.md)。

源帧对齐后，建图工具取颜色通道最小值，再对每个像素取时间第 25 百分位，完成底图融合。

A、B 各自沿用出生参考图坐标。路线坐标等于底图像素坐标加 `origin_xy`。`flow.yml` 管理路点和移动参数，底图不提供这些数据。

## 实现约束

- 特征提取与几何匹配分别执行。匹配结果必须满足双向匹配、内点数量和比例、空间分布、缩放、旋转及残差门槛。
- 定位模块负责固定地图加载、结构校验、特征缓存和坐标转换。图像匹配不发送游戏输入。外层操作负责定位暂缺等待、停止和松键。
- 地图快照是一次加载后固定使用的地图资源。新执行读取最新资源。同一执行及其子导航共用已加载快照，磁盘资源变化不会使当前执行切换地图。
- 有效像素遮罩仅表示像素来源。一个玩家位置处的遮罩像素不足以判定位置合法。定位还需要足够的周边匹配证据，并拒绝覆盖范围外或存在竞争匹配的位置。
- 大图预处理与 201×201 实时小图的预处理分别核对。相同的 CLAHE 网格数在不同图像尺寸上可能产生不同效果。
- 底图只使用源素材中的有效像素，不使用生成式补图或推测道路。底图可能保留白色图标。定位仍需通过几何匹配和竞争位置检查。
- 正式应用与开发试跑共用固定底图。普通任务不提供定位算法切换设置。

## 资源与定位

每张地图的资源位于 `assets/game_data/bagel/<map_id>/`：

| 文件 | 用途 |
| --- | --- |
| `map.png` | 压暗背景底图。透明区表示没有有效来源 |
| `map_mask.png` | 二值有效像素遮罩，与底图透明通道一致 |
| `map.yml` | 地图身份、坐标版本、原点、识别参数和地标 |
| `flow.yml` | 正式流程、路点和移动参数 |

底图尺寸、原点和出生坐标以各地图的 `map.yml` 为准。

`BagelFixedMap` 校验资源后，缓存底图特征，并将数组和识别参数设为只读。模块根据元数据和图片内容区分地图快照。新执行重新读取磁盘资源，正在执行的任务继续使用已加载的快照。

快照编号仅在当前进程内标识一次加载，不能用于跨运行比较内容。编辑器直接显示底图。试跑开始前，编辑器重新加载资源，并将同一快照交给执行器。

定位先取最小颜色通道，抑制彩色背景，再匹配整图和重叠的 201×201 分区。

| 地图 | 优先预处理方式 | 分区步长 |
| --- | --- | --- |
| 录像店（A） | CLAHE | 100 |
| 白鸽工地地铁站（B） | 高通处理 | 80 |

每张地图均保留另一种预处理方式。只有优先方式没有合格匹配时，定位模块才尝试另一种方式。整图特征只提取一次，分区复用描述子距离。反向最近邻也只计算一次。

任意合格匹配位置相差超过 5 像素时，定位模块拒绝结果。两张地图同时被判为出生位置时，定位模块也拒绝结果。

用于判断位置范围的有效遮罩只填充封闭的内部孔洞，不向地图外扩张。遮罩不表示道路可通行。定位失败时，外层操作沿用停步、重试和最终松键处理。

## 当前发布资源的来源与限制

当前发布资源位于[录像店地图目录](../../../../assets/game_data/bagel/janus_high_a/)、[白鸽地图目录](../../../../assets/game_data/bagel/janus_high_b/)和[单廊双容器地图目录](../../../../assets/game_data/bagel/janus_high_c/)。`map.yml` 记录坐标和识别参数，不记录完整的源素材对应关系。

三张底图的 `(100, 100)` 各自是该图的出生点，坐标系之间没有共同原点，容器坐标不能跨图使用。新增底图后要确认它不会在其他底图上误判出生位置：离线校验工具见 `.workbuddy/tools/bagel_c_spawn_guard.py`（新底图能否认出留档出生点）与 `.workbuddy/tools/bagel_c_spawn_conflict.py`（已有底图的出生点是否被新底图抢走）。后者命中会触发「多张地图同时判为出生位置」的拒绝规则，使原有路线退化成非支持出生点。

当前底图的源素材对应关系未完整归档，因此无法按原采集过程重建。归档定位样本可用于核对识别结果，但不能替代整张底图的来源记录。

下节说明如何使用新录像生成新资源。该方法不表示当前发布底图已有完整来源记录。

## 新录像建图

建图工具从新录像中抽取小地图，匹配静态特征并融合底图。裁图区域取自画面配置中的“定位小地图”。工具运行不依赖旧录像或逐帧来源清单。

输入录像必须为原生 1080p。按以下顺序采集：

1. 从对应出生点开始，让角色保持静止，并完整显示小地图。
2. 连续走完采集区域。

工具将首段稳定画面的玩家中心设为 `(100, 100)` 原点。采集者负责确认出生身份。工具不能仅凭静止画面证明出生位置。

工具通过双向特征匹配、几何残差和运动范围校验，计算相似变换。短暂识别失败时，工具可以跳帧。在限定时间内，工具必须重新建立与已接收帧的可靠关系，否则停止。工具不推测定位丢失期间的道路。

累计旋转不得超过 2°，尺度必须在出生画面的 98%–102% 内。融合使用同一累计变换，保留旋转和缩放，不将其简化为平移。中心和高亮动态标记不参与底图融合。输出只包含有效观测区域，不生成路线。

工具将结果写入新的独立目录，拒绝覆盖已有目录。新资源验收后，按以下顺序替换正式资源：

1. 停止所有正在使用该地图的任务。
2. 整组替换正式底图和元数据。
3. 重新核对新地图的流程坐标。

旧流程不保证可直接用于新地图。结构校验不能识别所有同尺寸资源混装。

在主仓根目录查看参数：

```powershell
uv run --env-file .env python tools/bagel/build_fixed_map.py --help
```

| 参数 | 用途 |
| --- | --- |
| `--map-id` | 指定现有地图的识别参数 |
| `--video` | 指定新录像 |
| `--output` | 指定尚不存在的输出目录 |

工具使用 OpenCV 解码。采样与输出约束如下：

| 项目 | 限制 |
| --- | --- |
| 采样帧率 | 默认每秒 5 帧。`--sampling-fps` 可在 2–20 帧间调整 |
| 输入时长 | 最多十分钟 |
| 开头静止画面 | 至少三个采样帧 |
| 位移门槛 | 每秒 80 地图像素，加 2 像素误差 |
| 连续匹配空段 | 不超过一秒 |
| 输出最大边长 | 4096 像素 |
| 融合暂存 | 上限约 1 GiB。超过时，缩短录像或降低采样帧率 |

输出保留必要构建参数和接收、拒绝帧数。本机输入路径不写入元数据。

## 测试与验证范围

主要测试从录像或受控帧序列开始，生成地图资源，再由运行加载器加载和定位。

| 测试范围 | 覆盖内容 |
| --- | --- |
| 建图和资源加载 | 已知位移、坏帧拒绝、静止原点、输出保护、尺寸和遮罩一致性 |
| 定位和流程回归 | 出生、导航、证据不足、位置冲突和范围边界 |

受控位移样本的验证范围仅包括算法和输入输出约束。使用新录像建图后，还需使用独立的真实录像和保留帧验收建图结果。游戏内路线也需要验收，离线测试通过不能代替这项验收。重复纹理和累计漂移仍需人工核对。

相关测试位于独立测试仓 `zzz-od-test` 的 `test/zzz_od/application/bagel/bagel_fixed_map/` 和 `test/zzz_od/application/bagel/bagel_map_builder/`。运行方式见[测试文档](../../testing/README.md)。
