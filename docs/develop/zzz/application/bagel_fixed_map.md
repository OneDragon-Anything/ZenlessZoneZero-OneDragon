# 贝果固定小地图

## 用途与坐标

录像店（A）和白鸽工地地铁站（B）使用预先生成的压暗背景底图，供出生识别、正式导航和编辑器共用。应用流程见[自动化方案](bagel.md)，编辑操作见[流程开发工具](bagel_flow_editor.md)。

底图按源帧对齐后融合：取颜色通道最小值，再按像素取时间第 25 百分位。采样参数与源帧变换以 `map_sources.json` 为准。A、B 各自沿用出生参考图坐标；路线坐标等于底图像素坐标加 `origin_xy`。路点和移动参数由 `flow.yml` 管理，不从底图推导。

## 实现约束

- 特征提取与几何匹配分离。匹配结果必须满足双向匹配、内点数量和比例、空间分布、缩放、旋转及残差门槛。
- 固定地图加载、摘要校验、特征缓存和坐标转换由定位模块负责。图像匹配不发送游戏输入；外层负责定位暂缺等待、停止与松键。
- 地图快照不可变。新执行读取最新资源；同一执行及其子导航共用已加载快照，不因磁盘资源变化中途切换。
- 有效像素遮罩仅表示像素来源，不能用玩家锚点处的一个遮罩像素来判定位置是否合法。需要足够的周边匹配证据，并拒绝覆盖范围外或有空间竞争结果的位置。
- 大图预处理必须与 201×201 实时小图单独核对；尤其不能假定相同 CLAHE 网格数在不同图像尺寸上等价。
- 底图只使用源素材中的有效像素，不用生成式补图或推测道路。底图可能保留白色图标，定位仍须经过几何匹配和竞争位置检查。
- 正式任务与开发试跑统一使用固定底图；普通任务不提供定位算法切换设置。

## 资源与定位

每张地图位于 `assets/game_data/bagel/<map_id>/`：

| 文件 | 用途 |
|---|---|
| `map.png` | 压暗背景底图，透明区表示没有有效来源 |
| `map_mask.png` | 与底图透明通道一致的二值有效像素遮罩 |
| `map.yml` | 地图身份、坐标版本、原点、识别参数和资源 SHA-256 |
| `map_sources.json` | 源录像摘要、采样参数、逐帧 PNG 摘要及已核验的平移坐标 |
| `flow.yml` | 正式流程、路点和移动参数 |
| `route.yml` | 参考图变换与路线导入资料；运行识别参数由 `map.yml` 管理 |

底图尺寸、原点和出生坐标以各地图的 `map.yml` 为准，源帧选择与变换以 `map_sources.json` 为准。

`BagelFixedMap` 校验资源后缓存底图特征，并将数组和识别参数设为只读。缓存按元数据及图片内容区分版本；新执行重新读取磁盘，已有执行继续持有原快照。地图来源清单供重建工具校验，不参与运行时定位。编辑器直接显示底图，试跑开始前重新加载并把同一快照交给执行器。

定位先取最小颜色通道抑制彩色背景，再匹配整图和重叠的 201×201 分区。A 优先使用 CLAHE，分区步长 100；B 优先使用高通处理，分区步长 80。两张地图均保留另一种表示，仅在当前表示没有合格匹配时尝试。整图特征只提取一次，分区复用描述子距离；反向最近邻也只计算一次。

任意合格位置相差超过 5 像素时直接拒绝；两张地图同时判为出生也拒绝。有效遮罩只填充封闭的内部孔洞用于判断位置范围，不向地图外扩张，也不表示道路可通行。定位失败时沿用停步、重试和最终松键处理。

## 重建底图

制图工具用于复现已发布素材，需要与来源清单匹配的原始录像、项目依赖和 PATH 中的 FFmpeg。在主仓根目录查看参数：

```powershell
uv run --env-file .env python tools/bagel/build_fixed_map.py --help
```

运行时用 `--map-id` 指定地图，`--video` 指定源录像，`--output` 指定输出目录。工具先验证源录像和每个解码帧，再按冻结坐标融合。输出图片必须与发布摘要一致，解码回读也必须通过；全部核验后才写入输出目录，元数据最后替换。它不是给任意新录像自动配准的入口；源录像或解码结果不匹配时会失败。

## 测试

定位测试应覆盖出生识别、导航位置、证据不足、位置冲突和覆盖范围边界。性能测试应将图像匹配耗时与游戏运行时的端到端延迟分开，不能相互替代。

相关测试位于 `zzz-od-test/test/zzz_od/application/bagel/bagel_fixed_map/`，运行方式见[测试文档](../../testing/README.md)。
