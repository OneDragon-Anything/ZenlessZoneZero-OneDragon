# 贝果固定小地图

关联：[Cora093/ZenlessZoneZero-OneDragon#18](https://github.com/Cora093/ZenlessZoneZero-OneDragon/issues/18)。

## 范围与验收状态

用户已选择 A、B 均使用 04「压暗背景」底图。按用户明确要求，固定底图已设为出生识别、正式导航及编辑器默认实现；本轮只做历史截图对照与离线回归，不操作实机。离线结果不代表实机已验收。

候选图来自 2026-10-01 的 A/B 录像，每秒采样 20 帧，取颜色通道最小值，再按对齐后的像素取时间第 25 百分位。A、B 各自沿用出生参考图坐标；路线坐标等于底图像素坐标加 `origin_xy`。不修改 `flow.yml` 路点和转向、停步参数。

## 实现约束

- 特征提取与几何匹配分离。测试仓保留原算法与多参考图缓存算法作为性能对照，正式代码没有旧算法回退。双向匹配、内点数量和比例、空间分布、缩放、旋转及残差门槛保持不变。
- 固定地图加载、摘要校验、特征缓存和坐标转换由定位模块负责。图像匹配不发送游戏输入；外层沿用定位暂缺、停止与松键规则。
- 地图快照不可变。新执行读取最新资源；同一执行及其子导航共用已加载快照，不因磁盘资源变化中途切换。
- 有效像素遮罩仅表示像素来源，不能用玩家锚点处的一个遮罩像素来判定位置是否合法。需要足够的周边匹配证据，并拒绝覆盖范围外或有空间竞争结果的位置。
- 大图预处理必须与 201×201 实时小图单独核对；尤其不能假定相同 CLAHE 网格数在不同图像尺寸上等价。
- 原始素材及其他效果保留，不用生成式补图或推测道路。B 白色图标残留在现有回归样本中未导致失败，其他位置仍待实机验证。
- 正式任务与开发试跑统一使用固定底图；定位失败不静默换回多参考图，不增加普通任务切换设置。

## 资源与定位

每张地图位于 `assets/game_data/bagel/<map_id>/`：

| 文件 | 用途 |
|---|---|
| `map.png` | 选定的 04 底图，透明区表示没有有效来源 |
| `map_mask.png` | 与底图透明通道一致的二值有效像素遮罩 |
| `map.yml` | 地图身份、坐标版本、原点、识别参数和资源 SHA-256 |
| `map_sources.json` | 源录像摘要、采样参数、逐帧 PNG 摘要及已核验的平移坐标 |
| `flow.yml` | 正式流程和路点，此次切换未修改 |
| `route.yml` | 保留原参考图变换和旧格式导入资料，不再保存运行识别参数 |

A 底图为 305×405，原点 `(-9,-94)`，使用全部 1068 帧；B 为 450×373，原点 `(-119,-16)`，使用 1067 帧，排除未配准的第 10 帧（从 0 开始计数）。两个出生地各自保留 `(100,100)` 出生坐标。

`BagelFixedMap` 校验资源后缓存底图特征，并将数组和识别参数设为只读。缓存按元数据及图片内容区分版本；新执行重新读取磁盘，已有执行继续持有原快照。地图来源清单供重建工具校验，不参与运行时定位。编辑器直接显示底图，试跑开始前重新加载并把同一快照交给执行器。

定位先取最小颜色通道抑制彩色背景，再匹配整图和重叠的 201×201 分区。A 优先使用 CLAHE，分区步长 100；B 优先使用高通处理，分区步长 80。两张地图均保留另一种表示，仅在当前表示没有合格匹配时尝试。参数由历史截图回归选定：B 改成步长 100 会漏掉出生样本，因此保留 80。整图特征只提取一次，分区复用描述子距离；反向最近邻也只计算一次。

任意合格位置相差超过 5 像素时直接拒绝；两张地图同时判为出生也拒绝。有效遮罩只填充封闭的内部孔洞用于判断位置范围，不向地图外扩张，也不表示道路可通行。导航事件记录地图版本、失败原因、耗时、内点数与残差，丢图时沿用原有停步、重试和最终松键处理。

## 重建底图

需要原始 A/B 录像、项目依赖和 PATH 中的 FFmpeg。以下命令在主仓根目录运行，输出到开发目录：

```powershell
uv run --env-file .env python tools/bagel/build_fixed_map.py --map-id janus_high_a --video 'C:\Users\Cora\Videos\A.flv' --output .debug/bagel-fixed-map/rebuilt/janus_high_a
uv run --env-file .env python tools/bagel/build_fixed_map.py --map-id janus_high_b --video 'C:\Users\Cora\Videos\B.flv' --output .debug/bagel-fixed-map/rebuilt/janus_high_b
```

工具先验证源录像和每个解码帧，再按冻结坐标融合。输出图片必须与发布摘要一致，解码回读也必须通过；全部核验后才写入输出目录，元数据最后替换。它用于复现已发布素材，不是给任意新录像自动配准的入口。源录像不进 Git；使用不同录像或解码结果时会明确失败。A/B 均已实际重建，图片与选定 04 逐字节一致。

## 离线证据（2026-10-01）

37 个历史样本取自独立测试仓，使用既有测试中冻结的位置与逐轴 1–3 像素容差，包含未知出生、错误地图和小地图不可见的拒绝样本。这是开发中使用过的回归集，不是新的盲测集或独立人工精密坐标标注；旧算法输出只用于对照，不作为新增真值。制图录像不计入独立验收集。

对比原实现、多参考图缓存、固定底图缓存三组，OpenCV 4.13.0、NumPy 2.4.6、OpenCV 单线程。预热后每组运行 5 轮，共 185 次，耗时包含预处理、特征提取、匹配和坐标核验，也包括失败帧；测试期间未并行运行其他测试或重建任务。

| 方案 | 中位耗时 | P95 | 符合历史预期 | 误定位 / 漏定位 |
|---|---:|---:|---:|---:|
| 原多参考图 | 159.23 ms | 320.35 ms | 37/37 | 0 / 0 |
| 多参考图缓存 | 18.83 ms | 34.03 ms | 37/37 | 0 / 0 |
| 固定地图缓存（默认） | 19.45 ms | 26.96 ms | 37/37 | 0 / 0 |

固定地图 A/B 首次加载分别为 83.94/87.55 ms，首次定位为 18.45/10.78 ms；加载在移动前完成。固定地图的中位耗时与缓存参考图相近，P95 更低；这些数值是本机对照结果，不代表游戏运行时的端到端延迟。
