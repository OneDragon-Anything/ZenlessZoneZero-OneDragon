# 迷失之地第一层防卡

## 范围与原因

`LostVoidMoveByDet` 原来按目标图标的位置变化判断卡住，并按次数执行后退、左右横移。图标抖动、镜头转动会影响判断，重新创建寻路操作也无法知道哪些方向已经失败。

本次只实现中心画面帧差、一次攻击清障和方向记忆。不引入光流、里程碑或全局坐标。玩法与画面依据见 [玩法](../../../../game/gameplay/迷失之地.md) 和 [画面](../../../../game/screens/迷失之地.md)。

## 检测与恢复

- 只在持续发出前进指令期间采样。中心区域由 `迷失之地-大世界 / 区域-运动检测` 定义，缩小为 160×90 灰度图并模糊。下方中央一半宽度留给角色，使用上方四个分区和左右各两个分区观察场景，每个分区计算亮度变化超过 12 的像素占比。
- 默认每 0.5 秒比较一次，至少三个分区的变化比例都达到 3% 才认为场景移动，否则累计静止时间；累计 2 秒才判定受阻。采用多个分区是因为宽翼角色的待机动画会越过窄遮罩，单处旗帜和特效也不能证明场景在前进。
- 转镜头后等待 0.3 秒重新取基准帧，比较期间保持镜头不动。暂停、停止移动、丢失目标和离开大世界时丢弃旧帧，等待时间不计入受阻时间。每两秒记录一次防卡采样状态、各分区变化比例和静止累计时间，便于核对未触发原因。
- 帧差只表示画面变化，不能证明角色接近目标。飞行角色、相机跟随和特效可能同时影响多个分区，因此额外限制一次连续前进最多 8 秒：仍未到达目标就停止前进并进入脱困，帧差再大也不能延长这段时间。该时限是有意安排的试探，长距离正常移动也可能多做一次脱困动作，可按需调大。
- 受阻后先停止前进并重新确认画面。可正常交互时交还原有交互流程；目标图标可见且普攻按钮可用时尝试一次普通攻击，等待动画后重新确认画面。已经到达或进入战斗、交互画面时交还原流程，否则换方向。没有目标图标时直接换方向。
- 一次脱困最多攻击一次。进入脱困后，不能仅因帧差变大就清空次数与攻击记录，必须等实际到达目标、进入交互或战斗后再结束此次脱困；重新创建寻路操作仍保留记录，防止起飞动画导致每次都重复攻击而不换方向。
- 当前 YOLO 模型不识别障碍物和敌人，普攻按钮只能说明允许攻击，不能证明面前有可破坏物。因此攻击是有上限的清障尝试，不能把感叹号当成可攻击物的证据。
- 攻击后仍受阻，或按钮不可用时，按八个相对镜头方向选择失败惩罚最小的扇区，短距离试走。试走前后比较场景帧差，没有进展就增加该方向的惩罚；再次受阻也惩罚上次尝试方向。
- 方向记忆由楼层的 `LostVoidStuckState` 共享，重新创建寻路操作不清空。镜头转动会改变相对方向，因此这是一层内的短期经验，不代表地图坐标。新楼层和重开挑战使用新状态。连续受阻超过 12 次仍交给原有失败流程处理；脱困中的计数等实际到达目标后才重置。
- 脱困后重新识别目标；出现交互画面或战斗时交回原有节点。所有结束与暂停路径释放前进键。

## 配置与验证

`LostVoidConfig` 提供以下 YAML 字段，无需增加设置界面：

| 字段 | 默认值 | 含义 |
|---|---|---|
| `stuck_sample_interval` | 0.5 | 帧差采样间隔，秒 |
| `stuck_static_seconds` | 2.0 | 连续低变化的有效移动时间，秒 |
| `stuck_motion_threshold` | 0.03 | 至少三个场景分区各自需要达到的变化像素占比 |
| `stuck_max_forward_seconds` | 8.0 | 一次连续前进的最长时间，到达前到时就尝试脱困 |
| `stuck_escape_seconds` | 0.8 | 每次方向试走的持续时间，秒 |

测试放在独立测试仓对应的 `lost_void_stuck`、`lost_void_move_by_det` 目录，覆盖静止、场景移动、角色动画、镜头稳定等待、攻击次数限制、失败方向记忆，以及移动到脱困再恢复寻路的多帧流程。动画回归使用 `screens/迷失之地-大世界/护栏前-角色动画-a.webp` 与 `护栏前-角色动画-b.webp`，两帧来自同一静止卡点；起飞状态归档为 `护栏前-起飞.webp`。持续大帧差的流程测试验证时限仍会触发，并且攻击后确实发送横移指令。真实关卡仍需验证不同地图、角色和特效下的阈值。
