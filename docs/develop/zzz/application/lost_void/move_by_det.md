# 迷失之地识别寻路(LostVoidMoveByDet)

迷失之地大世界里「朝识别目标移动」的操作单元,源码 `src/zzz_od/application/hollow_zero/lost_void/operation/lost_void_move_by_det.py`。
由 `LostVoidRunLevel`(层间移动)按目标类别(感叹号 / 距离白点 / 下层入口)创建,依赖[检测模型](det_model.md)的识别结果转向 + 前进,到达目标或目标消失时结束。
转向的换算与校准见 [转向与灵敏度配置](../../turn_sensitivity.md)。

## 节点结构

```
移动前转向 ──开始移动──> 移动 ──(到达/目标消失)──> 结束
    │                     │
    │未识别到目标          │判定卡住
    ▼                     ▼
 无目标处理 <──继续识别── 脱困
```

- `移动前转向`:静止状态把目标转到画面中心附近,期间做转向比例校准。
- `移动`:按住前进,移动中小幅跟随转向;每帧做交互停下判断与卡住判定。
- `无目标处理`:目标丢失时停下转圈重新找;累计 7 次进入脱困。
- `脱困`:见下文。

## 卡住判定(check_stuck)

**原理**:持续前进时,画面上可见目标(YOLO 识别框)的位置和大小应当不断变化;
如果当前帧的可见目标与「足够久之前、且期间确实在前进」的某个快照整体保持不动,说明角色实际没有位移。

**实现**:
- 每帧记录全部可见目标的 `(中心x, 中心y, 宽度)` 快照(`移动前转向` 与 `移动` 节点都记录),保留最近 10 秒。
- `移动` 节点每帧把当前帧与满足条件的旧快照逐个对比:
  - 快照时间 ≥ 3.5 秒前;
  - 期间累计前进时长 ≥ 2.5 秒(帧间隔 ≥1 秒的时间段不计入前进时长,排除站立转圈等阶段);
  - 整体保持不动(`is_same_box_constellation`:数量一致,且每个目标能一一配对——中心距离 <15px、宽度比在 0.8~1.25)。
- 命中一次记一个时间点,2.5 秒窗口内命中 ≥2 次判定卡住,停止前进并进入脱困。

**为什么不用逐帧对比**:旧版按「连续帧全部目标静止」累计、任何一帧不满足就清零。
识别框单帧抖动、类别抖动(同一图标在鸣徽/武备/限时之间跳变导致的目标切换)、目标被障碍物半遮挡时的周期性丢失,都会把累计清零。
2026-08-20 实机日志里三次卡住(事件房卡障碍、入口层被铁栅栏挡、入口层卡进 NPC 与栅栏之间的口袋)均因此 3 分钟内几乎不触发脱困,最终 180 秒超时作废整层。
时间窗快照对比只要求「存在一个足够久之前的快照与当前一致」,中间帧怎么抖动、丢失都不影响,正常情况下约 4 秒即可判定。

**误判防线**:正常靠近目标时识别框宽度增长会超出 0.8~1.25 区间(游戏房间尺度下 3.5 秒的位移足以让框明显变大)、位置也会漂移,不会与旧快照配对成功;
「期间累计前进 ≥2.5 秒」排除了站立扫描时相机转回原角度造成的假命中。

## 脱困策略(get_out_of_stuck)

按本层累计卡住次数 `stuck_times` 走 6 阶段循环,同一侧连续尝试两次(旧版每次换边,左右横跳原地抵消):

| 阶段 | 动作 | 目的 |
|---|---|---|
| 0 / 1 | 向优先侧贴墙横滑 1.5 秒 / 2.5 秒(按住前进+横向) | 斜向顶住障碍物沿表面滑动,绕过栅栏类横向障碍 |
| 2 / 3 | 向另一侧贴墙横滑 1.5 秒 / 2.5 秒 | 换边再试 |
| 4 | 后撤 2.5 秒 + 向优先侧平移 2 秒 | 脱离口袋状地形 |
| 5 | 后撤 1 秒 + 大幅转向(约90度) + 前进 2 秒,之后返回 `需要重新识别` | 物理绕行,换个位置重新选目标 |

一轮走完翻转优先侧重新循环。每次脱困后清除 `last_target_result`(重新选目标,避免沿原路线撞回同一障碍)、重置转向校准与卡住快照。
识别到普攻按钮时会先攻击一次(部分障碍可破坏)。

**放弃与重开**:`stuck_times` 超过上限(12)时脱困节点返回失败、状态为 `执行超时`,
`LostVoidRunLevel` 三类移动分支都把该状态转为寻路失败,走「重开挑战」流程(每层最多 3 次),
避免原地挣扎到 op 的 180 秒超时。重开成功后 `stuck_state` 重建(角色位置已重置,累计不应带入新一轮)。

## 本层共享的 stuck_state

`LostVoidStuckState` 由 `LostVoidRunLevel` 每层创建,传给本层所有移动 op,让脱困阶段跨 op 递进。除卡住判定外,以下情况也计入 `stuck_times`(不执行脱困动作,只推进阶段):

- 移动中多次丢失目标(`移动前转向` 每 5 次 / `移动` 每 10 次,直接调用脱困动作);
- `无目标处理` 连续 7 次找不到目标;
- `尝试交互` 反复走到目标附近都无法交互(节点重试耗尽),或反复走回本层已交互过的对象——这两类对应「图标看着近但实际有障碍相隔」的场景,移动 op 会快速以到达结束,卡住只能在交互失败侧体现。
