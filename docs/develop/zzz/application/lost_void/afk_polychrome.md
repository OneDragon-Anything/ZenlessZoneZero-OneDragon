# 挑战配置预设「无脑挂机刷菲林」

`config/lost_void_challenge/无脑挂机刷菲林.sample.yml` 是一份挑战配置预设，用来挂机辅助推进探究勋证和图鉴（菲林奖励）。它按速通图鉴的打法设置：开局武备同派系抱团，路线优先 战斗-武备 > 挑战-限时 > 战斗-硬币。

使用方法：在「迷失之地配置」里副本选「战线肃清」，挑战配置选「无脑挂机刷菲林」。不能代表全部菲林奖励都完成了；作战潜能加点、战地邂逅、勘破迷踪等奖励仍需手动完成。

## 新增的挑战配置字段

下面的字段都在 `LostVoidChallengeConfig` 里，**默认关闭**，原有配置的行为不变。界面上没有开关，只能在 yml 里设置；预设把它们全部打开。字段说明也写在 `parameter_template.sample.yml` 里。

| 字段 | 作用 |
|---|---|
| `smart_escape` | 寻路用新的卡住判断、脱困和转向，见「寻路脱困」 |
| `same_faction_first` | 同派系抱团，见「同派系抱团」 |
| `store_save_coin` | 邦布商店留硬币，见「邦布商店留硬币」 |
| `route_plan_by_map` | 按 Tab 地图规划路线，见「路线规划」 |
| `difficulty` | 进入战线肃清前切到指定难度（预设为「难度五」）；空值沿用游戏当前难度 |
| `stop_when_no_strategy` | 追新模式看完整个调查战略列表也没有可刷的战略时，返回大世界并以失败结束本次运行（不触发完成后的关机等动作）；关闭时按原来的回退点第一个战略 |

## 本局记录

`LostVoidRunMemory`（`config/{实例}/lost_void_run_memory.yml`）记录本局依次进入的区域类型、拿到的藏品、每次进商店的刷新次数和购买记录。每次更新都写文件，程序中途重启后从大世界接着跑时还能用；每局开始（`reset_for_new_challenge`）和本局结束（通关或失败退出，`on_challenge_end`）时清除。它不受开关控制，下面几项规则都要用：同派系抱团统计局内拿到的武备派系；商店和路线规划用挚交会谈次数认出最后一个休息区。

## 同派系抱团（`same_faction_first`）

- 「派系」指通用武备的分类：终结、异常·击破、机敏、绝境、携游（`lost_void_const.GENERAL_GEAR_CATEGORY_LIST`）。同派系鸣徽的分类名与派系名相同，鸣徽只能升级同派系的武备。
- 本局已有的派系（`LostVoidContext.get_owned_gear_faction_list`）：开局选中的通用武备排最前，再加上本局记录里局内拿到的通用武备。开关关闭时，开局武备按原来的方式加入战斗组优先级。
- 选择顺序：`get_artifact_by_priority` 在主选、次选每组里先排「第0级(已有武备派系)」，再排 NEW 和第 1～4 级；通用选择（`LostVoidChooseCommon.select_by_layers`）按 同派系 → NEW → 优先级 合并。
- 选鸣徽时刷新：候选全是已对上藏品数据的鸣徽、又没有同派系的时候，点右上角「刷新」（新增区域「文本-刷新次数」读剩余次数）；次数用完或刷新后次数没变少，才按原来的顺序选。
- 「请选择1项」这类画面认不出「已选择」标记时，用最后点过的几个候选记进本局记录。

## 邦布商店留硬币（`store_save_coin`）

刷新费用依次 50 → 100 → 200 → 300 硬币。开启后不再按「x次内只买高优先级」（`buy_only_priority_2`），改为：

- 普通商店最多刷新 3 次（`STORE_MAX_REFRESH_TIMES`，花到 200 硬币那次为止）；第三层终结之役前的最后一个休息区（第 3 次挚交会谈，`LostVoidContext.is_last_rest_area`）不限次数，货架买空了也刷新再看。
- 每次刷新前 OCR 硬币数和刷新费用（新增区域「区域-硬币数量」「区域-刷新费用」），刷新后剩下的硬币少于 600（`STORE_MIN_ARTIFACT_PRICE`）就不刷新；识别失败时按次数规则。
- 还能刷新时只买第0级、NEW、第 1、2 级；普通商店不能再刷新后只买同派系鸣徽，没有就离开，硬币留到最后一个休息区；最后一个休息区什么都买。
- 货架一次拖到最右边（原来只拖 400 像素，经商友好战略等增加槽位时会漏掉最右边的商品），刷新后拖回最左边。

## 路线规划（`route_plan_by_map`）

- 什么时候规划：感叹号 NPC 处理完、看到下层入口准备过去时，如果需要规划（`LostVoidContext.need_route_plan`），就打开菜单（默认是地图页）规划（`plan_route_by_map`）；正好要更新动态优先级时在同一次打开菜单里规划。需要规划的情况：每层开头（入口、第 1、2 次挚交会谈）、没按规划走、规划的路线走完。每个区域最多规划一次；第 3 次挚交会谈后面直接是终结之役，不规划。
- 识别地图（`context/lost_void_map_reader.py`，画面特征见 [迷失之地画面·藏品面板(地图页)](../../../../game/screens/迷失之地.md)）：只看右边 MAP 一栏；彩色图标连成一块算一个节点，亮的是还能走到的；亮的节点用 `assets/template/lost_void/map_icon_*` 模板匹配类型，先按一个大图标匹配，匹配不上按几个小图标匹配（混合节点）；发光圆圈里的是当前位置；最上面的 THRONE 是终点；节点之间的灰色虚线一段段串成整条线，线两头指向的节点就是连到的节点。识别结果按文字写进日志（`LostVoidMap.describe`）。
- 选路线（`LostVoidMap.find_best_route`）：从当前位置往上列出每条路线，按挑战配置的 `region_type_priority` 比较：先比路线上最优先那种区域的个数，多的更好；一样多再比第二优先的，依次类推。混合节点按里面最优先的类型算。
- 转成寻路要找的入口（`_route_to_region_type`）：混合节点选一个同一步其它门上没有的类型，避免走错门；同一步还有别的门是同一种类型时，路线停在这一步，进去后再看地图重新规划。当前房间寻路会忽略的类型（`LostVoidRunLevel.had_been_list`）第一步不走。
- 选门（`get_entry_by_priority`）：先找规划的下一个区域，画面里没有时按 `region_type_priority`。
- 锁定规划的入口（`LostVoidMoveByDet.locked_entry_name`）：去下层入口时锁定规划的下一个区域，当前画面里看不到也锁定。寻路全程只认这种入口，不与相邻入口合并；判断到达时只看锁定入口的图标，站在别的门旁边不算到达。连续 10 次无目标处理（约转一圈）没看到，或锁定后卡住 6 次，就解除锁定，按画面里的入口选。
- 进入的区域与规划第一步一致就往前推一步；不一致就清空，下个区域去入口前重新规划（`on_enter_region`）。
- debug 模式下规划时把地图截图存到 `.debug/lost_void_map/`，用来核对识别结果。

## 寻路脱困（`smart_escape`）

开启后 `LostVoidMoveByDet` 换用下面的做法，关闭时完全是原来的逻辑（含脱困时普攻、切移动最优角色）：

- 卡住判断：除了原来的「目标图标长时间不动」，按住前进时画面中部（排除角色、头像、小地图、技能按钮）连续 1.5 秒几乎不变（`check_scene_static`），也判定被挡住。
- 脱困动作：后退 → 横移 → 前进。横移期间不断识别目标、转镜头让目标保持在画面中心，相当于贴着障碍边缘绕。同一侧连续绕 2 次还卡住才换边。第一次脱困往目标图标偏的一侧绕。后退、前进时长随本层卡住次数增长，横移时长随本段移动卡住次数增长。不普攻、不切人。
- 丢目标后往横移的反方向转着找。
- 转向比例：用一个跨移动保留的比例（`LostVoidContext.move_turn_ratio`，初值 0.6，来自实测中位数），只在原地转向后用实际转动校准，单次样本超出 0.3～1.2 的丢掉；原地每次最多转 600。原来每段移动都从 0.2 重新起步、滑动平均校准。
