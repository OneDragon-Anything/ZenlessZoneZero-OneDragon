# 迷失之地战斗结束与挑战结果识别

本文记录层间移动（`LostVoidRunLevel`）里几处识别规则：战斗什么时候算结束、怎么认出挑战结果画面、业绩点是否刷满怎么判断、混合入口怎么处理。

## 战斗结束

节点「战斗中」除了原来的判断（YOLO 认出交互 / 距离 / 入口、OCR 认出「前往下一个区域」），还会用 OCR 读白点下面的距离文字（如「23.5m」，`AutoBattleContext.check_battle_distance`）。这条只在没认出「前往下一个区域」时才读，读到就算这场战斗结束，停止自动战斗。

- 道中危机、终结之役不用这条规则，它们打完是挑战结果画面。
- 为什么：怪清完后会出现指向下一处的白点，但战斗中镜头晃动，YOLO 很难连续多次高置信度认出白点。复杂区域打完第一个房间后会一直对着空气攻击。
- 每 2 秒在 debug 日志输出一行「战斗诊断」（区域、脱战计数、YOLO 结果、提示文字、距离、阵亡计数），用于排查迟迟不脱战。

## 挑战结果画面

`is_challenge_result` 先认「标题-挑战结果」，认不到再认「文本-总计用时」（`迷失之地-挑战结果` 画面新增的区域）。顶部的关卡进度条有时会盖住标题。

- 「交互后处理」里先判断挑战结果，再尝试对话：挑战结果的奖励数字会落在对话角色名称的区域里，原来会被当成对话一直点。
- 「战斗中」判断是否脱战时也算上挑战结果画面。

## 业绩点是否刷满

「挑战结果处理完成」里没看到「奖励-零号业绩」时，要求挑战结果画面和「按钮-完成」连续 3 帧都在，才按「本周业绩点已刷满」处理。原来过渡画面里奖励还没显示出来就点完成，会误判业绩点已满。

## 混合入口

一扇门上方有多个区域图标时，交互文本只有「复杂区域」，看不出具体区域类型（`MIXED_ENTRY_NAME`）。现在把它认成入口，并沿用寻路时识别到的入口图标，用来推测下一层的类型。

## YOLO 检测前涂黑的区域

`LostVoidDetector.HUD_MASK_RECT_LIST` 列出推理前涂黑的区域：

- 左上角色头像；
- 右上通知列前两条的圆形图标（「战斗·鸣徽」「侦测到新的敌人」），会被认成感叹号或距离白点。第三条附近（y≈270）会有真实的感叹号，所以不涂。
