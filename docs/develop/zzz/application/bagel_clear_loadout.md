# 启动时清空携带物

正式应用每次启动只在第一次入场前允许清空携带物。清空包括背包、安全箱和已装备物品，不更换代理人。独立入场工具默认只核验，不自动卸装。

## 资格与起点

首次调用入场操作前，应用即消耗清空资格。出生检查次数不能代替这项资格。暂停、恢复、失败重开和节点重试均不恢复资格；停止任务后重新启动才重新初始化。

| 当前状态 | 操作 |
| --- | --- |
| 备战五项全零 | 不搬运，继续原有入场核验 |
| 备战背包和安全箱为空，但仍有装备 | 跳过仓库往返，逐格卸下已装备物品 |
| 备战背包或安全箱有物品 | 先打开仓库转存内容物，检查余量，再返回备战卸装 |
| 首次从贝果仓库启动 | 按[首次启动恢复](bagel_start_recovery.md)转存遗留物，返回入口后重新选图 |
| 读数缺失或非法 | 限次读取，不当作空容器 |
| 后续局仍有携带物 | 停止并保留现场 |

零携带要求武备、装备、道具价值为0，且背包和安全箱零占用。备战五项不完整时，最多读取5帧，期间不搬运。完整价值读取规则见[价值读取](bagel.md#价值读取)。

仓库不显示完整五项，不能补猜武备、装备或道具价值。仓库先核验可见数量，回备战后必须重新核验五项。

## 仓库转存

仅在仓库主画面明确，背包、安全箱及仓库数量可读时，点击「放入仓库」。启动入口、返回节点和每轮转存都先排除出售底栏、快速选择、出售预览和获得硬币弹窗。出现出售状态时停止，不转存、不确认、不返回；空箱也不能越过此检查。

转存核对两个容器的总占用。可见页为空但背包总数非零时，仍使用一次批量按钮，不滚动寻找物品。撤离奖励上方物品不属于背包。固定区域读数失败时，只接受左侧唯一的背包标题及其下方格子。

点击前与结果确认时，连续两帧必须同时满足：

- 背包、安全箱和仓库的数量、容量一致。
- 背包可见格子位置一致。
- 所有可见格的占用状态一致。

未知格、缺失读数、可见占用超过总数、行定位失败或离开主画面，都会清除稳定记录。滚动或重排后重新收集两帧。零读数也必须有完整、明确为空的可见格，不能只凭文字识别（OCR）结果确认转存完成。

完成要求两个容器全部清空、容量不变且仓库占用不下降。允许合并堆叠后占用不变。稳定的部分转存记录已转出数量后停止，不反复补点。

启动仓库使用同一结算操作，但不按间隔主动出售。满仓、残留和一次出售重试见[出售与入仓重试](bagel_sale_interval.md)。启动转存不增加任何任务计数。

## 备战卸装

依次处理三位代理人的武备、三格队伍装备和四格道具。仅双击明确占用的装备槽；空槽跳过，未知槽重新识别。代理人头像、替换角色按钮和左侧仓储候选列表都不是卸装目标。

背包内容清空后才卸背包装备。卸下后容量可以由50变20，最终使用实际容量，不要求保持原容量。

每件物品按以下顺序操作：

1. 在备战主画面核对源槽和价值，等待0.5秒。
2. 点击槽心，按住0.08秒。
3. 松开后等待0.11秒，再向同一槽心点击，按住0.08秒。
4. 等待0.5秒，重新识别源槽和价值。
5. 连续两帧确认源槽为空、对应价值下降、其他价值不变，且背包和安全箱仍为空。

两次按下的实际间隔约0.20秒，包含控制器开销。详情菜单不是转存入口。点击返回成功或短暂的“已放入仓储枢纽”提示也不是完成依据。

五项读数和全部槽位占用连续两帧一致即可判为稳定，不要求图标像素静止。灰色空槽和物品图标都有动画。未知槽、缺失读数或离开备战页时，重新收集两帧。

当前物品核验通过后，可直接从同一稳定观察选择下一件。最后一件完成后，重新检查完整五项；只有 `zero_loadout()` 通过，才设置入场资格。仍非零时报告具体项，不循环清空。

## 重试、暂停与停止

首次双击超时后，仅当连续两帧确认原槽仍有物、五项读数未变且所有槽位占用未变，才允许重试一次。每格最多两次双击。详情未关闭、去向异常、读数不明或第二次未生效时停止。

| 条件 | 行为 |
| --- | --- |
| 点击前等待期间暂停或停止 | 不输入。即使已经恢复，也重新识别后再选择物品 |
| 两次点击之间暂停或停止 | 结束本次卸装，不续发第二次点击 |
| 双击或批量按钮之后暂停恢复 | 只核验结果，不重复输入 |
| 任一点击返回失败 | 停止，不重试输入 |
| 要转存内容物但仓库已满 | 独立转存停止；正式启动仓库按结算的一次出售重试处理 |
| 内容物转存后，仓位不足以容纳待卸装备 | 停止。按每个占用槽最多一个新仓位保守计算 |
| 两个容器原本为空 | 不专门进入仓库预查，每格仍需核验；未生效按上述上限停止 |

| 预算 | 上限 |
| --- | --- |
| 未知状态 | 5帧，每帧间隔0.5秒 |
| 双击或批量入仓后的核验 | 5秒或10次检查，先达到者为准 |
| 单个批量转存或清空操作 | 180秒 |
| 允许首次清空的入场操作 | 660秒，含恢复、转存、返回、卸装和加载 |
| 仅核验的入场操作 | 240秒 |

框架在轮次之间检查超时。执行子操作时由子操作计时。清空独立执行，不占15秒的零携带检查节点预算。

失败日志应报告阶段、容器或槽位、原因、可读数值、已转存数量和截图名。已经转存的物品不回滚；下次启动只处理剩余携带物。

## 实现与验证边界

`BagelApp` 管理首次资格；`BagelEnter` 核验并调用清空；`BagelClearLoadout` 编排卸装；`BagelStoreCarried` 处理背包和安全箱批量转存。`BagelDeposit` 只处理结算安全箱。共用转存基类管理双击、稳定观察、暂停和失败记录。

按钮和数值复用现有画面区域。前往仓库使用整屏精确文字匹配；文字缺失时点击已核对的背包数量区域切回背包视图。装备槽使用1080p槽心，背包行按边框定位。素材与尚未建模的区域见[启动清空画面](../../../game/screens/贝果计划.md#启动清空相关画面)。

离线回归覆盖完整清空、仓位不足、读数未知、结果异常、稳定观察、有限重试和暂停后禁止重发。其他容量与容器组合不逐项验证，具体范围见测试仓[覆盖说明](../../../../zzz-od-test/BAGEL_COVERAGE.md)。共用控制器与合成帧在测试仓辅助模块维护，测试按业务行为组织。命令见[测试入口](../../testing/bagel.md)。

离线控制器切换画面不证明游戏接受了输入。批量同时清空背包和安全箱、各类堆叠整格转出、满仓与部分转存、后台双击时序仍需实机验证。验收时核对点击位置、源槽变空、对应价值下降、两个容器为空及最终五项全零。游戏内部采样和冷却机制尚未明确，不能把单个时序参数当作未转存的确定根因。
