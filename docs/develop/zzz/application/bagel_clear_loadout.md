# 启动时清空携带物

正式应用每次启动只在第一次入场前允许清空携带物。清空包括背包、安全箱和已装备物品，不更换代理人。独立入场工具默认只核验，不自动卸装。

## 资格与起点

首次调用入场操作前，应用即消耗清空资格。出生检查次数不能代替这项资格。暂停、恢复、失败重开和节点重试均不恢复资格；停止任务后重新启动才重新初始化。

| 当前状态 | 操作 |
| --- | --- |
| 备战五项全零 | 不搬运，继续原有入场核验 |
| 备战背包和安全箱为空，但仍有装备 | 跳过仓库往返，逐格卸下已装备物品 |
| 备战背包或安全箱有物品 | 先打开仓库转存内容物，检查余量，再返回备战卸装 |
| 首次从贝果仓库启动 | 按[首次启动恢复](bagel_start_recovery.md)转存遗留物，返回入口后重新选图 |
| 读数缺失或非法 | 限次读取，不当作空容器 |
| 后续局仍有携带物 | 停止并保留现场 |

零携带要求武备、装备、道具价值为0，且背包和安全箱零占用。备战五项不完整时，最多读取5帧，期间不搬运。完整价值读取规则见[价值读取](bagel.md#价值读取)。

仓库只核验可见数量，不推断三个价值。返回备战后核验槽位和容器，卸装结束再核验完整五项。

## 仓库转存

仅在仓库主画面明确，背包、安全箱及仓库数量可读时，点击「放入仓库」。启动入口、返回节点和每轮转存都先排除出售底栏、快速选择、出售预览和获得硬币弹窗。出现出售状态时停止，不转存、不确认、不返回；空箱也不能越过此检查。

转存核对两个容器的总占用。可见页为空但背包总数非零时，仍使用一次批量按钮，不滚动寻找物品。撤离奖励上方物品不属于背包。固定区域读数失败时，只接受左侧唯一的背包标题及其下方格子。

点击前与结果确认时，连续两帧必须同时满足：

- 背包、安全箱和仓库的数量、容量一致。
- 背包可见格子位置一致。
- 所有可见格的占用状态一致。

未知格、缺失读数、可见占用超过总数、行定位失败或离开主画面，都会清除稳定记录。滚动或重排后重新收集两帧。零读数也必须有完整、明确为空的可见格，不能只凭文字识别（OCR）结果确认转存完成。

转存完成要求背包和安全箱全部清空、容量不变且仓库占用不下降。合并堆叠后，仓库占用可以不变。

点击「放入仓库」后，若携带数量未变且仓库仍有空位，只继续核验，不重复点击。达到[核验上限](#重试暂停与停止)仍未确认结果时停止，不报告满仓，也不进入出售流程。

独立转存只完成部分物资时，程序记录已转出数量并停止。正式启动流程的满仓、残留和一次出售重试见[出售与入仓重试](bagel_sale_interval.md)。启动转存不按间隔主动出售，也不增加任务计数。

## 备战卸装

依次检查 3 个代理人武备槽、3 格队伍装备和 4 格道具。仅双击明确占用的槽位；空槽跳过，未知槽重新识别。代理人头像、替换角色按钮和左侧仓储候选列表都不是卸装目标。

背包内容清空后才卸背包装备。仅此槽位允许背包容量下降，其他槽位要求容量不变；安全箱容量始终不得改变。

每件物品按以下顺序操作：

1. 确认备战无遮挡，连续两帧核对槽位占用、背包和安全箱数量与容量，等待0.5秒。
2. 点击槽心，按住0.08秒。
3. 松开后等待0.11秒，再向同一槽心点击，按住0.08秒。
4. 等待0.5秒。若出现详情，点击空白处 `(950, 540)` 关闭，每次双击后最多点击2次；清空子操作开始时已有详情也最多关闭2次。
5. 确认无遮挡后，连续两帧核验源槽为空、其他槽位占用未变、两个容器零占用，且容量符合上述规则，再处理下一格。

无遮挡要求「预设组合」「前往空洞」和三个分区标题在原位置可识别，且没有详情操作文字。关闭点击位于候选列表与备战面板之间，不点击详情内的搬运或出售按钮。

稳定判据使用容器数量、容量和槽位占用，不要求图标像素静止。未知槽、缺失读数、详情或非备战画面会清除稳定记录，但保留双击前的基准状态。

逐格不读取三个价值，以免价值识别阻断重试；点击成功和转存浮字均不算卸装成功。全部10槽为空后，连续两帧核验三个价值为0、两个容器零占用。返回入场操作后再核验 `zero_loadout()`，通过才允许入场；非零则停止，不循环清空。

## 重试、暂停与停止

核验达到上限后，仅当连续两帧确认原槽仍有物、全部槽位占用及容器数量和容量均未变，才允许重试。每格最多重试3次，连同首次共4次双击；换格时清零。

关闭详情和等待恢复计入本次核验预算。只有实际重试双击才重置该预算。重试耗尽、详情关闭失败或状态异常时停止；状态不明只限次重读，不补发双击。总时限优先，不保证用完每格重试次数。

| 条件 | 行为 |
| --- | --- |
| 点击前等待期间暂停或停止 | 不输入。即使已经恢复，也重新识别后再选择物品 |
| 两次点击之间暂停或停止 | 结束本次卸装，不续发第二次点击 |
| 双击或批量按钮之后暂停恢复 | 只核验结果，不重复输入；卸装详情仍在时不补点空白处 |
| 任一点击返回失败 | 停止，不重试输入 |
| 要转存内容物但仓库已满 | 独立转存停止；正式启动仓库按结算的一次出售重试处理 |
| 内容物转存后，仓位不足以容纳待卸装备 | 停止。按每个占用槽最多一个新仓位保守计算 |
| 两个容器原本为空 | 不专门进入仓库预查，每格仍需核验；未生效按上述上限停止 |

| 预算 | 上限 |
| --- | --- |
| 未知状态 | 5帧，每帧间隔0.5秒 |
| 双击或批量入仓后的核验 | 5秒或10次检查，先达到者为准 |
| 单个批量转存或清空操作 | 180秒 |
| 允许首次清空的入场操作 | 660秒，含恢复、转存、返回、卸装和加载 |
| 仅核验的入场操作 | 240秒 |

时限在轮次之间检查，截图和识别耗时可能使实际停止晚于预算。子操作独立计时；清空不占15秒的零携带检查节点预算。

失败日志应报告阶段、容器或槽位、原因、可读数值、已转存数量和截图名。已经转存的物品不回滚；下次启动只处理剩余携带物。

## 实现与验证边界

`BagelApp` 管理首次资格；`BagelEnter` 核验并调用清空；`BagelClearLoadout` 编排卸装；`BagelStoreCarried` 处理背包和安全箱批量转存。`BagelDeposit` 只处理结算安全箱。共用转存基类管理双击、稳定观察、暂停和失败记录。

按钮和数值复用现有画面区域。前往仓库使用整屏精确文字匹配；文字缺失时点击已核对的背包数量区域切回背包视图。装备槽使用1080p槽心，背包行按边框定位。素材与尚未建模的区域见[启动清空画面](../../../game/screens/贝果计划.md#启动清空相关画面)。

测试范围见独立测试仓[覆盖说明](../../../../zzz-od-test/BAGEL_COVERAGE.md)，命令见[测试入口](../../testing/bagel.md)。重试耗尽、暂停中断等异常分支的实机覆盖范围尚未明确；离线分支验证不能证明实际识别和点击效果。
