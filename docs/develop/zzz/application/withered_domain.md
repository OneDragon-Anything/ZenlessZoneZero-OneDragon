# 枯萎之都门扉处理

玩法条件见[玩法参考](../../../game/gameplay/withered_domain.md)，入口坐标和截图来源见[画面参考](../../../game/screens/hollow_zero_event.md)。

## 执行与访问记录

`HollowRunner.try_move_by_map` 先选择目标格，再点击路径上的下一格，更新访问记录，然后调用格子入口操作。
善战门和侵蚀门由 `DoorBattle` 处理。它沿用事件文本区域的白色筛选 OCR，匹配“开门”及侵蚀门的兼容选项。
未知选项仍返回重试，处理失败仍向 runner 返回失败；点击成功只表示动作已发出，不证明门已开启。

`WitheredDomainContext.try_target_node` 对财富、善战、侵蚀三类仍关闭的门遵守原有访问次数上限。
关门目标不执行“重复目标改点相邻格”的纠偏：点空白格不能开门，且会让访问计数记到空白格。
统一在目标校验处检查访问记录，使一步、途经、方向及兜底选择都不能重复选取已经达到上限的关门目标。
当前数据默认允许两次尝试，保留一次移动或识别延迟的容错。
判断仍按位置和格子类型进行；同位置变成“开启的门”后不受原关门记录限制。

## 边界

没有调整通用 OCR、文字阈值或 screen_info。给定截图在 ppocrv5/ppocrv6 下都可识别开门，
不能复现历史截图中每一次“未匹配合适的处理方法”的具体输入帧。
测试仓回归覆盖真实截图识别、入口失败和点击后仍关闭的反复选门、正常点击、侵蚀选项及开启态路径。
地图识别仍依赖模型；此处不把无法通行的门设为永久障碍，也不改变以其他格子为终点时的既有寻路规则。
