# 出售间隔与入仓重试

应用按本次任务内非空且完整入仓的次数累计出售间隔，失败局带回物资也计入；空箱、未支持出生点和启动遗留物资不计入。默认间隔1，范围1–999；关闭自动清理时不出售。新任务归零，暂停和局内失败重开不归零。

每次结算创建独立操作，计数必须由应用持有。结算接收本次是否到期的决定，完成出售流程（包括筛选0件并正常取消）后通过结果数据告知应用清零。只在结算最终核验通过后更新计数，不能因筛选失败提前清零。

正常达到成功局数上限的最后一个非空局补卖，即使未到间隔；同一结算最多出售一次。手动停止和异常结束不追加补卖，失败局仍按正常间隔处理。空箱只核验，不因到期或结束标志而出售。

首次入仓后有残留，或完整入仓后仓库已满时，允许在自动清理开启的前提下提前出售。出售仍使用用户的类型和品质筛选，范围包含已有库存；该操作也可能出售安全箱内符合筛选的物品，范围与证据限制见[玩法说明](../../../game/gameplay/贝果计划.md#退出与仓库)。只对状态明确的安全箱执行，未知不当作空。

残留处理顺序：首次入仓 → 按方案出售一次 → 再点击入仓一次 → 核验安全箱和仓库容量。第二次入仓后仍有物资或状态不明，停止并保留现场，不循环出售或反复入仓。安全箱明确为空且容量可读时，即使仓库已满，也允许结算成功并返回下一局。常规完整入仓后出售不需要额外重试入仓。

## 最终核验

结算成功必须同时看到仓库主界面、安全箱为空和可读容量。原本空箱、关闭清理和出售后再入仓都执行此核验。满仓本身不构成失败。

- 正式结算允许满仓合并堆叠后安全箱清空、仓库占用不变；占用下降或读数未知则停止。
- 允许残留出售时，仓库占用或安全箱占用必须减少。不能出现新增安全箱占用格。后续结算仍须清空残留。
- 独立入仓工具保留满仓堆叠保护。独立出售工具默认要求安全箱为空，只有正式结算允许残留出售。

启动恢复复用同一结算操作，但不按间隔主动出售；仅在满仓或残留时尝试出售腾位，不改变本次任务的计数。恢复入口行为由对应启动恢复流程负责。

## 验证边界

离线测试覆盖满仓、残留、未知容量和筛选 0 件后取消，范围见测试仓[覆盖说明](../../../../zzz-od-test/BAGEL_COVERAGE.md)。这些分支尚未完成实机验证。失败局非空入仓及手动停止不补卖也尚未完成实机验证。

间隔出售和结束补卖缺少已归档的连续验收证据。实机验收必须核对入仓、计数、实际出售范围及最终返回结果，不能仅以启动运行作为完成依据。
