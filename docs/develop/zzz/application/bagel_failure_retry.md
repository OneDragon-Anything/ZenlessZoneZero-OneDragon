# 贝果任务整体重试

## 次数与适用范围

“整体重试次数”（`max_failure_retries`）表示正式任务因局内失败最多额外入场多少次。默认值和取值范围见[贝果配置表](bagel.md#3-配置bagelconfig)。首次入场、成功后的下一局、非支持出生点重选和容器局部恢复成功不消耗次数。

正式应用在新任务开始时初始化累计次数。成功入仓、子操作重建、暂停和恢复均不清零。共享局内执行器与开发试跑只返回当前结果，不自动结算或开启下一局。

次数在失败收尾和返回完成、准备调用额外入场时增加。额外入场失败后停止，已用次数不返还。日志与运行记录保留失败原因、已用次数、配置上限和停止原因。

## 失败收尾

寻路卡位、定位失败、被敌人击杀、局内节点或操作超时、容器恢复失败及搜查或解锁中断共用以下流程：

1. 释放本流程持有的前进、交互和拖拽输入，记录原始原因和截图。
2. 读取新画面，执行局内退出、死亡结算或已到仓库的核验。
3. 核对安全箱物资确实入仓，再按现有清理开关和筛选设置处理仓库。失败局不增加成功局数，也不改变连续空箱次数。
4. 仓库结算完成后比较累计次数与上限。次数耗尽时停在仓库；仍有次数时返回入口，再开始一次额外入场。

退出、入仓、清理或返回失败时，正式任务在当前现场停止，同时报告原始失败和收尾失败。正常收集流程末尾的退出失败也直接停止。

业务操作显式标记可恢复失败；实际节点或操作超时使用框架的超时状态。人工结束、初始化失败、资源或配置缺失及程序异常直接停止，不按错误文字将其改写成可恢复超时。

## 页面阻挡恢复

正式入场遇到未识别画面且未发现战斗 HUD 时，调用通用返回大世界，再读取新画面重新检查入场。独立入场工具默认不启用此恢复。

仓库返回三次未识别研究站入口或大世界 HUD，或打开入口时遇到页面阻挡，也调用通用返回大世界。通用返回完成后，返回操作报告“已返回大世界”，由正式任务重新检查入场。

每次入场操作最多调用一次阻挡恢复，最长 30 秒；每次仓库返回操作最多调用一次，最长 20 秒。两者还受所属操作的剩余有效时间限制。通用返回失败，或恢复后仍不能继续时，当前操作停止并保留现场。

贝果复用通用返回的既有识别与点击，不增加签到页专用逻辑。页面恢复不消耗失败重试次数，也不重置首次清空资格或任务计数。

## 验证范围

离线回归以正式应用完整节点链为主，检查额外入场次数、结算顺序、成功计数、最终画面和原始错误。配置持久化和设置范围另行检查。测试代码位于独立仓 `zzz-od-test/test/zzz_od/application/bagel/`；阻挡画面使用该仓已归档的 `screens/画面-通用/贝果返回阻挡页.webp`。

运行离线回归时使用 `pytest --import-mode=importlib`，避免不同目录的同名测试文件发生导入冲突；环境准备见[测试文档](../../testing/README.md)。完整失败收尾、返回、额外入场与页面恢复的连续流程尚未完成实机验收，离线回归不能证明真实游戏中的整段流程成功。
