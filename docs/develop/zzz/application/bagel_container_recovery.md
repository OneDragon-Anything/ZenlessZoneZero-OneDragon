# 贝果容器停稳确认与开箱恢复

本说明适用于武备箱和电子保险箱。各模块分别承担以下职责：

| 模块 | 职责 |
| --- | --- |
| 导航 | 确认停稳，使用短步重新靠近 |
| 开箱操作 | 发送交互输入，确认目标面板 |
| 流程执行器 | 管理同一容器阶段共用的时间和次数上限 |

玩法和识别区域见[贝果画面](../../../game/screens/贝果计划.md)。发布流程的目标坐标保持不变。

## 容器阶段与预算

一个容器阶段包括靠近步骤，以及紧接其后的交互步骤。流程执行器用靠近步骤的 ID 区分阶段。例如，流程包含两个武备箱时，两组靠近步骤使用不同 ID，各自拥有独立预算。

预算指该阶段可用的运行时间、重新靠近次数和开箱 F 次数。流程执行器先确定当前阶段，再检查预算。切换到另一阶段时，执行器建立新预算。同一阶段切换子操作、补按 F 或重新靠近时，执行器保留原预算。

只勾选交互步骤时，该步骤仍属于对应的容器阶段，但不能调用未勾选的靠近步骤。

| 限制 | 计入范围 | 上限 |
| --- | --- | --- |
| 有效运行时间 | 从首次识别目标提示或进入目标交互距离开始，累计靠近确认和开箱耗时。人工暂停时间不计入 | 30 秒 |
| 重新靠近次数 | 首次靠近后的额外恢复。短步输入次数不单独计数 | 2 次 |
| 开箱 F 次数 | 首次开箱和所有补按。发送前占用次数，发送后报错不退回 | 3 次 |

长距离导航沿用原导航时限。电子保险箱的光圈点按属于后续解锁阶段，不占开箱 F 次数。

发送任何恢复输入前，执行器都检查预算。预算耗尽时，执行器松开按键并返回失败。

## 靠近与停稳确认

导航按以下顺序确认靠近完成：

1. 首次识别目标交互提示和 F 图标后，松开前进键。
2. 等待 0.5 秒。
3. 读取松键后的新截图。
4. 核对局内常驻界面（HUD）、当前可靠位置、目标交互提示和 F 图标。
5. 确认当前位置处于目标的交互提示识别范围内，再报告靠近完成。

动作前的截图不能用于确认到达。停稳后目标提示消失时，导航先核对当前可靠位置，再申请重新靠近。恢复只使用短步。提示再次出现后，导航重复停稳确认。

位置与目标提示冲突时，导航立即失败。定位证据暂缺时，导航先松开按键，再按既有定位规则有限等待。定位恢复后才允许短步移动。等待期间不使用历史坐标继续移动。

重新靠近时，到达半径取原到达半径与 0.5 像素中的较小值。这可以避免角色处于原到达范围内，却无法继续短步靠近。达到该范围后，导航停止移动并等待提示。等待 2 秒仍无提示时，导航返回失败。

## 开箱观察与恢复

发送开箱 F 后，开箱操作先观察 2 秒，再根据当前截图处理：

| 当前画面 | 开箱操作与流程执行器的处理 |
| --- | --- |
| 正确搜查面板或电子保险箱解锁界面 | 报告开箱完成，交给对应后续步骤。停止移动和开箱 F 输入 |
| 面板特征不完整或画面不明 | 松开按键并继续观察。不发送开箱输入，仍受阶段时限约束 |
| 局内 HUD、目标提示和 F 图标均存在 | 预算允许时补按 F |
| 局内 HUD 存在，目标提示或 F 图标消失 | 持续消失 0.5 秒后，申请重新靠近 |
| 已确认整局失败结算 | 返回既有撤离失败状态 |

任何容器面板特征出现后，执行器都禁止恢复移动和重复开箱。另一类容器的面板不能作为当前目标的成功结果。

## 正式应用与分步执行

开发工具按勾选范围执行：

| 勾选范围或当前状态 | 允许的行为 |
| --- | --- |
| 只选靠近 | 在靠近步骤内重新靠近并确认停稳。不自动开箱 |
| 当前阶段的靠近步骤已选中且成功完成 | 交互步骤可以调用该靠近步骤恢复 |
| 只选交互 | 允许补按 F。提示消失时返回失败，不补做未选移动 |
| 已有正确目标面板 | 靠近和交互步骤直接完成 |

恢复失败时，操作返回独立的业务失败状态，并报告定位、交互或预算耗尽原因。操作基类保存失败截图。

正式应用随后进入既有失败局退出和仓库结算流程。开发工具返回失败并保留现场，不自行开启新局。局部恢复成功不增加整体失败次数。

## 参数依据与验证范围

| 参数 | 依据或用途 |
| --- | --- |
| 停稳等待 | 沿用已有保险箱提前松键参数 |
| F 后观察间隔 | 沿用武备箱补按间隔 |
| 提示消失等待 | 区分短暂识别缺失和持续丢失 |
| 恢复到达范围 | 避免原到达范围阻止短步恢复 |

离线测试使用真实存档、文字识别（OCR）、画面区域和完整节点执行。模拟控制器根据输入切换画面，测试通过推进模拟时间验证等待、暂停和预算边界。子操作使用独立的超时保护，即使业务时限失效，测试也能结束。

测试位于独立仓 `zzz-od-test`：

- [恢复测试](../../../../zzz-od-test/test/zzz_od/application/bagel/bagel_run_flow/test_container_recovery.py)：检查执行器恢复行为。
- [阶段边界测试](../../../../zzz-od-test/test/zzz_od/application/bagel/bagel_run_flow/test_container_boundaries.py)：检查容器阶段边界。
- [应用测试](../../../../zzz-od-test/test/zzz_od/application/bagel/bagel_app/test_execute_screens.py)：检查正式应用的失败处理。

位移和跨阶段场景包含受控合成数据，用于验证执行逻辑。

不同角色的实际停步位移，以及这些参数对不同角色的适用范围，尚未完成连续实机验证。离线回归不能替代实机验收。
