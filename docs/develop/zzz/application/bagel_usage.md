# 贝果计划使用说明与问题反馈

本说明用于正式贝果任务。设置页采用顶部集中提醒，下面保留次数、清理开关和出售方案。流程编辑器和开发试跑不在本说明范围内。

## 启动前

- 请尽量不要使用有特殊移动方式的角色（如星见雅、叶瞬光等）。这类移动可能影响导航与定位的稳定性。角色示例是使用建议，不是已经实机验证的故障名单。
- 先解锁奥蒙德研究站的「迷宫诡域」传送点。请预留仓库空位。
- 这些设置只用于当前账号和应用组。切换账号或应用组后，请检查次数、清理开关和出售方案。

### 支持的启动画面

可从普通大世界、勘域大世界、达塔前、达塔对话、贝果研究站入口、贝果选图页、贝果备战页，以及已支持的地图、快捷手册、菜单和普通仓库（材料道具、音擎、驱动）启动。

也可从贝果结算仓库或备战仓库恢复首次清空，但必须能读取携带物和仓库数量。处于批量出售、筛选或出售确认状态时，程序会停止。请先人工核对现场。

程序会对未知页面进行有限恢复。恢复后仍无法确认画面时停止，不保证从任意画面都能启动。已经在局内时，不支持直接接管本局收集。

### 首次入场会卸下背包物品身上装备

首次入场前，程序会将背包和安全箱内的物品放入仓库，再卸下已装备物品。

每次任务仅首次入场允许自动清空携带物。后续局发现非零携带时停止。暂停再恢复不会重新获得首次清空资格。首次清空失败时，程序不会自动出售物品腾出空位。

“零携带”表示武备、装备和道具的价值均为 0，背包和安全箱的占用均为 0。“零投资”表示入场投资金额为 0。程序会核对完整读数。读数未知、确认提示未知或无法核对时，程序停止，不按 0 放行。

## 设置

“入仓”指将携带物放入研究站仓库。“清理仓库”指按出售方案自动出售仓库物品。

| 设置 | 默认值与范围 | 含义 |
| --- | --- | --- |
| 成功次数 | 默认 1；0–1000 | 安全箱有物、成功入仓且结算检查通过后计数。失败局和空箱局不计成功。0 表示不限成功次数，异常时仍可能停止。 |
| 整体重试次数 | 默认 5；0–100 | 因局内失败最多额外入场的次数。成功或暂停恢复后不清零。0 表示失败后只执行退出和结算，不再重开；收尾失败仍会立即停止。 |
| 清理仓库 | 默认开启 | 开启后，程序在入仓后按方案出售物品。关闭后，不自动出售清理仓库。失败局入仓后也按此开关处理。 |

出生点重选不消耗整体重试次数，也没有次数上限。抽到录像店或白鸽工地地铁站出生点后，程序开始收集。如需结束任务，请使用程序的停止操作。

### 出售范围

清理仓库时，程序会按出售方案自动出售物品。出售范围包含已有库存，不限于本局所得。

默认出售贵重物品、战术棱镜和其他物品中的 C/B/A/S 品质。默认不出售 Z 品质、装备、战术道具和门禁卡。

自定义时，请至少选择一种类型和一种品质。物品同时符合两项条件时，程序才会出售。选择 Z 品质或装备等类型后，相应物品也可能被出售。清理开启且类型或品质未选择时，任务无法启动。

关闭清理后，程序只将物品放入仓库，不出售物品。首次入场仍会清空携带物。结算后仓库仍满时，任务会停止。

## 运行时

启动日志显示本次成功次数上限、整体重试次数上限、清理开关及实际出售范围。首次清空无需额外点击确认。

收集不按物品名称筛选，不拾取金币。程序优先选择非材料，再按品质和类型排序。安全箱满时，只用优先级更高的物品替换箱内物品。详细排序见[收集与对换](bagel.md#收集与对换)。

小地图暂时无法定位时，程序停止移动并读取新截图。持续失败后，本局才转入失败收尾。程序不承诺自动绕障。

路线结束后会主动退出。游戏提示仅保留安全箱内物资，不保证保留安全箱外物资。游戏显示 DEFEAT 不直接等同于本任务未成功入仓。携带货币退出后的保留规则尚未确认。

局内失败后，程序先退出，再入仓和按开关清理。本局不计成功。完成结算后，程序才决定是否重开。退出、入仓、清理或返回失败时，程序停止并保留真实原因，不继续声称正在重开。

## 结束与停止

| 结果 | 程序行为 | 下一步 |
| --- | --- | --- |
| 达到成功次数上限 | 完成结算检查和返回后结束，报告成功次数及实际返回位置；通常为贝果入口，通用恢复后可能为大世界 | 核对日志中的次数和返回位置 |
| 仓满且安全箱仍有物品 | 停止入仓，不计成功，不出售腾位，也不开下一局 | 核对安全箱与仓库，人工腾出空位 |
| 部分入仓 | 停止重复点击「放入仓库」，不计成功，不继续清理或入场 | 核对剩余携带物和仓库中已收到的物品 |
| 成功入仓后恰好满仓 | 可按清理开关出售，再检查容量；最终仍满则停止，不计本局成功 | 核对物品，人工腾出空位 |
| 整体重试次数耗尽 | 仅在失败局完成结算后停在结算仓库，不再重开 | 查看失败原因、日志和截图，再决定是否重新启动 |
| 连续 3 次空箱结算 | 空箱局不计成功，完成返回后停止重开 | 检查收集过程和安全箱状态 |
| 未知画面、未知入场提示、配置或资源错误、程序异常 | 保留真实原因并停止；既有有限页面恢复不等于所有异常都能自动重试 | 按停止原因检查现场 |

成功次数为 0 时，不会因为成功次数达到上限而结束。返回失败时，不显示正常完成。

## 使用说明与问题反馈

反馈时，请提供停止原因、发生时间、所用角色、次数设置、清理开关、出售方案和相关日志。如果程序保存了现场截图，请一并提供。

截图默认位于程序运行目录的 `.debug/images/`。日志默认位于 `.log/`；如配置了其他路径，请以该路径为准。程序只展示已经确认保存的截图路径；没有截图或保存失败时，请提供日志与停止时的画面描述。

[前往 fork 的问题反馈页面](https://github.com/Cora093/ZenlessZoneZero-OneDragon/issues)。已有同类问题时，请先查看其说明。

程序按缩放后的 1920×1080 截图识别画面。这不表示游戏窗口必须为 1080p。当前资源使用中文文字。其他语言、不同角色及部分分辨率的实机适用性尚未确认。离线测试不能代替游戏或 GUI 的实机验收。
