# 贝果计划使用说明

本说明用于正式贝果任务。设置页按结束条件、蓝图优先、自动出售依次排列；首次清空提示和详细规则集中在右上角「使用说明」。设置页不显示实时运行状态。流程编辑器和开发试跑不在本说明范围内。

## 界面内的使用说明

「使用说明」先显示 4 项启动检查：解锁入口、预留空位、选择角色、核对设置。检查项用有序列表显示。

其余规则默认收起，分为「何时结束」「蓝图优先」「出售哪些物品」「何时出售」「首次入场会清空背包并卸下装备」「满仓或异常」。每条先用短标题标明条件或设置，再说明动作与结果。计数规则和异常处理分开，避免一段文字同时解释多个分支。入箱、入仓、空箱在正文前给出定义。

中文文案借鉴 ASD-STE100 的简明写作原则，不声明符合该英语标准。简化只改变说明的组织和措辞，不删减数值范围、计数条件、出售风险、停止条件或重试上限，也不改变任务行为。

## 启动前

- 尽量不用有特殊移动方式的角色，如星见雅、叶瞬光。这类移动可能影响导航和定位。角色示例是使用建议，不是已经实机验证的故障名单。
- 解锁贝果计划快捷手册入口及「录像店－房间」传送点。
- 给研究站仓库预留空位。
- 这些设置只用于当前账号和应用组。切换账号或应用组后，请检查次数、蓝图优先、清理开关和出售方案。

### 支持的启动画面

可从普通大世界、勘域大世界、达塔前、达塔对话、贝果研究站入口、贝果选图页、贝果备战页，以及已支持的地图、快捷手册、菜单和普通仓库（材料道具、音擎、驱动）启动。

也可从出现 DEFEAT 的失败结算、贝果退出确认或正在进行的贝果局内启动。局内会正常退出，丢弃安全箱外物资，不继续原路线。遗留物资转存不计成功次数、出售间隔和失败重试。

也可从贝果结算仓库或备战仓库恢复首次清空，但必须能读取携带物和仓库数量。处于批量出售、筛选或出售确认状态时，程序会停止。请先人工核对现场。

程序会对未知页面进行有限恢复。恢复后仍无法确认画面时停止，不保证从任意画面都能启动。已经在局内时，不支持直接接管本局收集。

### 快捷手册入场

首次入场时，程序先处理遗留局和仓库物资，再传送到「录像店－房间」。传送成功后，程序从快捷手册打开贝果主界面。该流程保留物资核验，不会直接跳过遗留物资处理。

- 首次启动时，即使已在贝果主界面、选图页或备战页，程序仍会重新传送。这些页面不能确定入场前位置。
- 后续各轮正常返回贝果主界面时，程序不重复传送。
- 返回大世界时，程序在下一次入场前重新传送，并从快捷手册进入。

游戏返回位置见[玩法入口](../../../game/gameplay/贝果计划.md#入口与单局)。自动化流程的待验证范围见[实机验证范围](bagel_speedup.md#实机验证范围)。

### 首次入场会清空背包并卸下装备

首次入场前，程序会将背包和安全箱内的物品转存到仓库，再卸下已装备物品。

每次任务仅首次入场允许自动清空携带物。后续局发现非零携带时停止。暂停再恢复不会重新获得首次清空资格。

启动转存通常不出售。仓满或有残留时，开启清理才允许出售一次，然后再入仓一次。仍未清空或状态不明时停止；清空后满仓也可继续。

“零携带”表示武备、装备和道具的价值均为 0，背包和安全箱的占用均为 0。“零投资”表示入场投资金额为 0。程序会核对完整读数。读数未知、确认提示未知或无法核对时，程序停止，不按 0 放行。

## 设置

“入箱”指将物品装入局内安全箱。“入仓”指将携带物放入研究站仓库。“自动出售”指按出售方案出售物品，对应原配置中的清理仓库开关。

| 设置 | 默认值与范围 | 含义 |
| --- | --- | --- |
| 累计成功次数 | 默认 1；0–1000 | 安全箱有物、成功入仓且结算检查通过后计数。失败局和空箱局不计成功。0 表示不限成功次数，异常时仍可能停止。 |
| 累计失败次数 | 默认 6；1–101 | 达到上限时，失败局仍先退出并完成结算，再停止重开。1 表示首次失败结算后停止。成功或暂停恢复后不清零。收尾失败会立即停止。 |
| 蓝图优先 | 默认开启；旧配置缺项也开启 | 开启时所有已识别蓝图优先于非蓝图，蓝图之间按品质选择，同品质不对换。关闭时蓝图与其他非材料物品先比品质，再比类型。只影响局内安全箱。 |
| 自动出售 | 默认开启 | 开启后，有物入仓按间隔出售，正常达到成功次数时补卖；空箱跳过出售，仍检查容量。关闭后不出售。正常局和失败收尾遵循同一规则。 |

页面用一句话显示结束条件：「累计成功 [1] 次 或 累计失败 [6] 次后结束任务」。失败上限只作显示换算：读取 `max_failure_retries` 后加 1，保存时减 1。内部仍保存额外重开次数，默认 5、范围 0–100，不迁移 YAML，也不改变计数与收尾流程。

出生点重选不计失败，也没有次数上限。抽到录像店或白鸽工地地铁站出生点后，程序开始收集。如需结束任务，请使用程序的停止操作。

出售间隔默认为 1，范围 1–999。本任务内按非空完整入仓次数累计，失败局带回物资也计入；空箱和不支持的出生点不计。暂停和失败重开不清零。出售流程完成（包括筛选 0 件正常取消）后归零，不跨任务保存。

正常达到成功次数上限时，末局不足间隔也补卖。手动或异常结束不追加补卖。同一结算最多出售一次。

满仓或入仓后安全箱有残留时，允许提前出售。有残留则再入仓一次；仍残留或状态不明时停止。安全箱清空后满仓也可继续。**安全箱中符合筛选的物品也可能被出售。**

### 蓝图优先

设置卡片显示「开启时优先拾取蓝图。建议开启」。开关只调整装入局内安全箱的顺序，详细规则如下。

| 开关与条件 | 行为 |
| --- | --- |
| 开启，安全箱有空位 | 优先装入当前可选择的蓝图，多张蓝图先选高品质；没有蓝图时仍装普通物品 |
| 开启，满箱且含非蓝图 | 蓝图换出最低优先级非蓝图，不受品质限制；非蓝图不能换出蓝图 |
| 开启，满箱且全是蓝图 | 只用更高品质蓝图换出最低品质蓝图；同品质或更低品质不换 |
| 关闭 | 蓝图与其他非材料物品先比品质，再比类型；高品质非蓝图可以换出低品质蓝图 |

「特殊奖励」专指菲林／零号业绩，与贵重物品使用不同钻石角标。同品质时，特殊奖励高于贵重物品，但不跨品质优先。开启蓝图优先时，特殊奖励仍低于蓝图。完整品质和类型顺序见[优先级表](bagel.md#物品识别与优先级)。

两种状态下，非材料均优先于材料，金币均不入箱，同优先级不对换。开关不按蓝图名称、用途或账号解锁状态区分，也不因获得蓝图停止任务。

蓝图必须被角标识别。角标未识别时按其他处理，无法保证优先；已识别为蓝图但品质未知时，仍按蓝图处理，在蓝图内部排最后。

**这不是仓库防出售开关。** 特殊奖励只用于入箱分类，不新增出售筛选项。结算入仓、自动出售和已有库存的处理规则均不改变。安全箱装不下全部蓝图时，也不保证全部带走。实机适用范围见[入箱识别与执行限制](bagel.md#入箱识别与执行限制)。

### 出售范围

清理仓库时，程序会按出售方案自动出售物品。出售范围包含已有库存，不限于本局所得。

结算开始时安全箱已空，则本次不出售已有库存。程序仍用新截图检查安全箱为空且仓库容量可读；满仓也可返回入口，有残留物或无法核实时停止。空箱局仍不计成功。

默认出售贵重物品、战术棱镜和其他物品中的 C/B/A/S 品质。默认不出售 Z 品质、装备、战术道具和门禁卡。

自定义时，每一步都请至少选择一种类型和一种品质。同一步里同时符合两项条件时，程序才会在这一步出售。多步按设置页从上到下的顺序各出售一次，上一步结束后才开始下一步。选择 Z 品质或装备等类型后，相应物品也可能被出售。清理开启且某一步未选全，或一步都没有时，任务无法启动。

关闭自动出售后，页面收起间隔与范围，只显示「只入仓，不出售。」。已保存的方案与步骤不清空。首次入场仍会清空携带物。安全箱清空且仓库容量可读时，即使满仓也可继续；仍有物资或状态不明则停止。

### 设置页的编辑与预览

- 自动出售是一张父卡片。出售间隔和出售范围缩进显示；间隔下方常驻已有库存与安全箱风险。
- 「默认／自定义」切换紧邻出售范围标题。默认方案按物品类型、品质显示标签。默认范围与总预览的品质标签使用加大的粗体字母、对应底色和边框；明暗主题分别配色，不只靠字色识别品质。物品类型标签和多选下拉保持原样。
- 自定义步骤复用多选下拉，勾选后保持菜单打开。标签可移除，数量多时换行；步骤支持新增、删除和上下移动。
- 全部步骤下方只显示一份「出售范围总预览」。预览先按类型汇总该类型在各步选中的品质并去重，再把品质集合相同的类型合并为一行。例如「装备 C」与「其他 S」仍为两行，不显示成两类都出售 C/S。预览不读取库存、不合并实际执行步骤，也不改变执行顺序。
- 未填完整的步骤不进入总预览。页面保留配置不完整提示；存在任何未填完整的步骤或没有步骤时，任务仍不能启动。
- 自定义步骤中任一步选中 Z 品质时，显示「已选择 Z 品质或装备类型。红色物品会被出售，请注意确认。」。只选择装备类型不触发该提醒；取消全部 Z 选择后隐藏。该条件仅控制界面提示，不改变筛选规则。
- 设置按当前账号和应用组即时保存。进入页面、切换账号或应用组只载入配置，不写回默认值。主题沿用主程序，不固定为原型的亮色。

正式 Qt 界面的窗口缩放、连续多选、滚动位置和主题切换仍需 GUI 验收；静态检查不代替界面验收。

## 运行时

启动日志显示本次成功次数上限、整体重试次数上限、蓝图优先状态、清理开关及实际出售范围。首次清空无需额外点击确认。

收集不按物品名称筛选，不拾取金币。程序按蓝图开关确定分组，再比较品质和类型。安全箱满时，只用优先级更高的物品替换箱内物品。详细排序见[收集与对换](bagel.md#收集与对换)。

小地图暂时无法定位时，程序停止移动并读取新截图。持续失败后，本局才转入失败收尾。程序不承诺自动绕障。

路线结束后会主动退出。游戏提示仅保留安全箱内物资，不保证保留安全箱外物资。游戏显示 DEFEAT 不直接等同于本任务未成功入仓。携带货币退出后的保留规则尚未确认。

局内失败后，程序先退出，再入仓并按上述清理规则处理：有物入仓按开关和间隔出售，空箱只跳过出售，结算核验始终执行。本局不计成功。完成结算后，程序才决定是否重开。退出、入仓、清理或返回失败时，程序停止并保留真实原因，不继续声称正在重开。

## 结束与停止

| 结果 | 程序行为 | 下一步 |
| --- | --- | --- |
| 达到成功次数上限 | 完成结算检查和返回后结束，报告成功次数及实际返回位置；通常为贝果入口，通用恢复后可能为大世界 | 核对日志中的次数和返回位置 |
| 仓满且安全箱仍有物品 | 开启清理时出售一次，再入仓一次；仍残留或状态不明则停止，不计成功 | 停止后核对安全箱与仓库，人工腾出空位 |
| 部分入仓 | 正式结算开启清理时出售一次，再入仓一次；关闭清理或重试后仍残留则停止 | 核对剩余携带物和仓库中已收到的物品 |
| 成功入仓后恰好满仓 | 可按清理开关出售；安全箱为空且容量可读就完成结算，计成功并返回入口 | 不必仅因满仓手动恢复；下一局残留仍按一次出售重试处理 |
| 整体重试次数耗尽 | 仅在失败局完成结算后停在结算仓库，不再重开 | 查看失败原因、日志和截图，再决定是否重新启动 |
| 连续 3 次空箱结算 | 每次跳过出售，容量核验通过才返回；不计成功，连续三次后停止重开 | 检查收集过程和安全箱状态 |
| 未知画面、未知入场提示、配置或资源错误、程序异常 | 保留真实原因并停止；既有有限页面恢复不等于所有异常都能自动重试 | 按停止原因检查现场 |

成功次数为 0 时，不会因为成功次数达到上限而结束。返回失败时，不显示正常完成。

## 查看日志与截图

停止日志直接提供处理建议、反馈所需信息和日志位置，不再附带外部使用说明链接。

截图默认位于程序运行目录的 `.debug/images/`。日志默认位于 `.log/`；如配置了其他路径，请以该路径为准。程序只展示已经确认保存的截图路径；没有截图或保存失败时，请结合日志与停止时的画面检查原因。
