# 贝果流程开发工具

本文说明源码开发工具的操作方式、流程格式和执行边界。

玩法、画面和正式应用行为见 [贝果自动化方案](bagel.md)。

## 范围与入口

工具从源码独立启动，普通贝果设置不提供入口：

```shell
uv run --env-file .env python -m zzz_od.gui.view.bagel.bagel_route_editor --instance 1
```

账号编号用于读取游戏控制配置；草稿独立于账号。打开界面不连接游戏，第一次执行在工作线程中初始化控制器、画面资源和 OCR，后续复用上下文。

## 步骤各做一件事

### 步骤分类与创建

新增窗口和右侧编辑共用“大类 → 具体操作”的选择方式：移动、箱子操作、检查与退出。箱子操作包含按交互键、完成光圈解锁、装入安全箱、关闭搜查界面；检查与退出包含检查出生位置、退出本局。移动类第二项显示为“完成条件”，可选“到达目的地”或“靠近交互目标”。它们仍是独立步骤，不合并后续交互、解锁和收集。

所有移动必须指定一个目的地，可在新增窗口填写 X / Y，添加后拖动地图点修改。移动方式有“正常移动”和“碎步接近”，与完成条件独立组合：正常移动在远处持续前进，近处短步调整；碎步每次短按后重新定位并朝目的地调整，不提供独立方向输入。

选择“到达目的地”时不指定交互目标；选择“靠近交互目标”时显示交互目标和识别范围。目标附近出现对应交互提示即可完成；到达目的地范围但没有提示时停下，最多等待两秒后失败。等待期间即使定位漂移或暂时丢失也不再起步。地图范围只控制提示采信，不代表游戏实际可交互距离。

新增不读取正式模板、不从前一步推测箱子。位置初值取前一个移动目的地，没有则取出生位置；该值可以修改，不代表路径已验证。目标初值为武备箱，移动方式初值为正常移动。已有步骤可以改大类、具体操作或完成条件，保留标识、名称和适用设置；不适用设置通过撤销恢复。更换交互目标保留目的地、移动方式和实际有效参数。

每个移动步骤只包含一个目的地，完成后松开按键，下一步重新检查当前画面。添加移动步骤可插入转折点，步骤顺序在列表中调整。

| 分类 | 动作 | 完成条件 |
| --- | --- | --- |
| 检查 | 检查出生位置 | 当前画面可定位，且站在所选出生点 |
| 移动 | 移动到指定位置 | 到达唯一目的地，或满足该点允许越过的范围；不等待交互提示 |
| 移动 | 靠近交互目标 | 在目标附近看到对应的交互提示；不按交互键 |
| 交互 | 按交互键 | 武备箱打开搜查界面；电子保险箱打开光圈界面，不执行光圈解锁 |
| 解锁 | 完成光圈解锁 | 完成光圈点按并等待搜查界面；若已是电子保险箱搜查界面，核对后直接完成 |
| 收集 | 装入安全箱 | 搜查完成，合适物品已处理；保留搜查界面，不代做重新交互 |
| 界面 | 关闭搜查界面 | 等待搜查完成，关闭面板并确认回到局内；不收集物品 |
| 退出 | 退出本局 | 主动退出并到达仓库界面，不执行入仓、出售或重新开局 |

正式任务与开发执行共用 `BagelRunFlow` 和相同业务操作；正式应用的外层流程负责入场、结算、入仓、清理及重开，见[自动化方案](bagel.md)。

电子保险箱交互后若直接出现搜查界面，“完成光圈解锁”会核对保险箱标题、安全箱和搜查状态，确认已解锁后完成，不重复按 F。只有标题或武备箱搜查界面不能通过。

完整流程从出生检查开始、以退出结束。交互前必须先靠近；电子保险箱交互之后必须解锁；容器打开后必须收集并显式关闭面板，才能继续移动或退出。显示名称不决定行为，动作类型决定行为，稳定标识用于勾选和记录。

## 勾选哪些，就执行哪些

点击一行只查看或编辑，左侧勾选框才决定是否执行。点击“执行勾选步骤”后，严格按列表顺序执行勾选项；没有勾选的步骤全部跳过。可以勾选不连续的步骤，也可以用“全选”“清空勾选”“只勾当前”设置清单。底部显示数量与执行编号，悬停可看完整名称。勾选只影响本次开发执行，不修改流程或正式任务。

要单步执行，勾选一项即可。

例如只勾选“按交互键”和“装入安全箱”，工具不会先走到箱子旁。需要用户先把游戏停在第一项要求的画面。每一步重新截图检查条件，不满足时说明原因并停止；跳过必要步骤可能导致后续画面检查失败，不会自动补做。

空清单不能启动。开始时冻结完整流程与勾选清单；运行期间锁定编辑与勾选，地图仍可缩放和平移。实际定位失败在轨迹中保留空段，不跨空段连线。暂停／恢复与停止沿用一条龙主程序的全局快捷键配置（默认 F9／F10），不另设快捷键。“停止”按钮显示当前配置的停止键，切到游戏后仍可按下；上下文创建后的初始化与切窗等待阶段也能取消。停止按钮与停止键都结束本次执行，不保留步骤间断点。

## 地图与参数

### 普通移动与容器解耦

普通移动只表达走到一个坐标，不选择容器。`move` 不保存 `target`，位置只保存名称、坐标和可选的到达、越点半径；导航参数可指定两种移动方式。普通移动默认 45 秒、到达与越点半径均为 2 地图像素，不提前松开移动键。靠近、交互等动作继续指定容器以识别正确提示和画面。

横屏三栏：地图、中间步骤列表、右侧当前步骤属性。浅色背景与主 GUI 一致，默认窗口为 1680 × 960，三栏初始宽度约 860 / 340 / 430。窗口加宽时优先扩展地图，也可拖动分隔线。

地图直接读取与定位共用的发布 `map.png` 与 `map_mask.png`，不在打开工具时拼接参考图。每次开始测试运行重新加载资源，地图显示与执行器冻结同一版本；每步导航复用该快照。资源缺失、版本未知或遮罩不一致时不启动测试运行。

地图显示副本反转 RGB，让游戏的深色底图以浅色显示，路线和轨迹使用深色。转换保留透明区，不修改参考图文件、定位输入或坐标。默认缩放排除外围透明留白；滚轮缩放，拖动空白处平移，拖动圆点修改位置，“显示完整地图”重新适应路线。

地图绘制出生位置、移动目的地及连线。出生位置是不可拖动的固定参照，常驻文字标注；点击它选择检查步骤，选中时显示半径 5 地图像素的检查范围。其余非移动步骤不画点、编号或文字。路线从出生位置依次连接移动目的地，不因中间交互、收集而断开。普通移动为蓝色，靠近武备箱为橙色，靠近保险箱为紫色。

只有选中的移动步骤显示范围圈和可拖动目的地。绿色虚线表示本次测试运行实际定位轨迹，可通过“显示实际测试运行轨迹”开关显示；定位失败处保留断线，没有运行数据时不生成轨迹。

右侧显示步骤名称、位置名称、X / Y、范围圈、完整运行记录和操作按钮。顶部显示完成条件摘要，详细规则与拖点说明集中在默认收起的“查看说明”。地图下方显示颜色图例。

位置名称与同一行 X / Y 归为一组，所有移动统一标题“目的地 · 地图像素”。数值输入和拖动地图点编辑同一个位置。

到达范围与移动方式始终显示，交互提示识别范围只在靠近交互目标时显示。超时、越点与提前松开移动键放在默认收起的“高级移动参数”；有显式覆盖值时入口标注“有单独设置”。展开、收起和选择步骤不改配置；展开状态在窗口内保持。取消“使用默认”后可编辑数值：

| 参数 | 含义 |
| --- | --- |
| 到达目的地的范围 | 两种方式都使用此范围；普通移动在范围内完成，靠近交互目标则停步等待提示 |
| 最长移动时间 | 普通移动默认 45 秒；靠近武备箱默认 45 秒、靠近电子保险箱默认 75 秒；超时仍未完成则停止 |
| 提前松开移动键距离 | 普通移动的可选设置，勾选“不提前松开移动键”即禁用；启用后，进入所设距离且纵向偏差不超过 2 像素时松键，等待 0.5 秒后用新截图核对位置。仍未到达就继续当前步骤，以短步调整，满足到达或允许越过的范围后才完成。每次执行只提前停车一次；提前松键距离与完成范围分别设置 |
| 越过目的地的允许范围 | 普通移动默认跟随到达范围；可独立设置 |
| 移动方式 | 正常移动／碎步接近，行为见“步骤分类与创建” |
| 识别交互提示的范围 | 默认 10 地图像素；进入此范围且出现对应交互提示才完成靠近，避免误认前一个同类容器 |

每次移动输入后必须用新截图重新定位。到点后等待提示期间不再发送移动输入，直到识别成功或两秒超时。

### 常见疑问

- **碎步接近如何指定方向？** 填写目的地即可，方向规则见“步骤分类与创建”。
- **移动还要选目标吗？** 必须选地图目的地；只有完成条件为“靠近交互目标”时才选择武备箱或电子保险箱，普通走位不需要。更换交互目标保留目的地和实际参数。
- **如何选择新增步骤类型？** 点击“新增步骤”，先选大类，再选具体操作；移动类选择完成条件，并填写目的地和移动方式。已有步骤右侧采用相同选择方式，不依赖正式模板。
- **实心点与圈分别是什么？** 出生位置是固定参照；其余实心点表示移动目的地。选中的移动点显示实线到达圈、普通移动的虚线越点圈、靠近交互目标的点线提示识别圈；范围相同时不重复画。两种移动方式都使用到达圈。

`navigation: {}` 表示默认参数。默认正常移动，`final_mode: small_steps` 表示碎步接近，`coordinate` 表示正常移动。`name` 只供显示，`action` 决定业务完成条件，`id` 是稳定标识。`waypoints` 只含一个目的地，其 `xy` 为地图坐标；普通移动不保存容器用途字段。各参数默认值见右侧实际显示与上表。

新增时填写的目的地可在添加后继续通过地图或 X / Y 修改；不要求前面有移动步骤，也不读取前一步的方向。

地图显示可用于核对位置与范围，但地图有效像素不等于可通行，不提供碰撞检测或自动绕障。所有距离均为地图像素，不受窗口缩放影响。

## 文件与格式

| 文件 | 作用 |
| --- | --- |
| `assets/game_data/bagel/<地图>/flow.yml` | 正式步骤与执行位置的唯一来源 |
| `config/devtools/bagel/<地图>.yml` | 开发草稿，正式任务不读取 |
| `assets/game_data/bagel/<地图>/map.png`、`map_mask.png`、`map.yml` | 定位与编辑共用底图、有效遮罩、坐标和运行参数 |

流程文件使用 `version: 4`。所有移动都只有一个目的地，移动方式与完成条件独立。读取文件不修改磁盘内容，只有保存操作才写入文件。

工具优先读取开发草稿，草稿不存在才读取正式流程。修改正式执行步骤应编辑 `flow.yml` 或通过工具导出。

校验拒绝未知版本、动作或字段、重复标识、非法数值和不合顺序的操作。移动规则见上文“步骤分类与创建”。编辑时允许顺序暂时不完整，保存与执行要求完整流程有效。

“保存草稿”只写开发目录。“保存为正式流程”经过确认后修改仓库资源，下次启动正式任务时生效。两者均完整校验、原子替换并回读，不自动提交或发布。运行中使用不可变快照，保存不会改变正在执行的内容。

### 读取已有流程

工具可读取版本 1–4 的流程文件；读取后应核对步骤名称、顺序和目的地，再保存或执行。账号旧路线文件不再读取，也不会被自动删除。

## 失败、停止与输入清理

手动测试运行会自动激活游戏窗口。切窗前要求鼠标左键连续松开 300 毫秒，按住或再次点击会重新计时，避免启动点击跟随焦点进入游戏；持续按住超过 5 秒则取消启动并提示松键。等待期间可以停止，不发送模拟点击或强制松键，也不占用运行状态。

独立移动使用三秒位置未变化保护与 100 次计次动作上限。普通动作失败停止并保留现场。正式任务识别到整局失败时，交给外层结算和连续失败规则处理；开发执行直接停止。正常退出操作会经过结算到达仓库主界面，但开发执行不会调用放入仓库、出售或重开。

工具只防止当前窗口重复测试运行，不与主程序、MCP 或其他工具进程自动互斥。测试运行前须停止其他控制端的任务，并等待其结束。停止及窗口关闭会等待工作线程清理；暂停、异常和完成均清理按键及拖拽，贝果操作还在执行返回前等待已经开始的暂停回调结束并停用本次执行的订阅，详见[执行与输入清理](bagel.md#执行与输入清理)。

启动快照或执行过程中的记录写入失败会中止本次执行。执行结束后，若仅最后一条结束记录写入失败，界面保留原执行结果，并追加“结束记录写入失败，请查看日志”的提示；此时记录不完整，不能作为完整验收依据。

制图重建方法与定位测试范围见[固定地图说明](bagel_fixed_map.md)。

## 测试

界面回归位于 `zzz-od-test/test/zzz_od/gui/view/bagel/`，按被测模块分为 `bagel_route_editor/`（流程编辑器）、`bagel_step_editor/`（步骤对话框）和 `bagel_flow_trial/`（试跑线程），各文件聚焦一个主要被测方法。交互测试保留真实鼠标、对话框及撤销保存路径；业务执行器测试仍在应用对应目录。

业务和界面测试共用文件隔离 fixture：配置、草稿、运行记录与失败截图写入临时目录，发布流程和识别资源只读主仓。单独验证界面时运行：

```powershell
uv run --env-file .env pytest zzz-od-test/test/zzz_od/gui/view/bagel/ -q
```
