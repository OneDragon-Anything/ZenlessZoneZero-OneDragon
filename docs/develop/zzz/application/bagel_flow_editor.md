# 贝果流程开发工具

**开发状态：路线可视化工具仍处于早期 demo 阶段，仅供开发试用，尚不是成熟稳定的工具。本文的功能说明和离线测试结果不代表已完成实机验收。**

关联设计：[fork Issue #17](https://github.com/Cora093/ZenlessZoneZero-OneDragon/issues/17)。玩法、画面和正式应用行为见 [贝果自动化方案](bagel.md)。

## 范围与入口

工具从源码独立启动，普通贝果设置不提供入口：

```shell
uv run --env-file .env python -m zzz_od.gui.view.bagel.bagel_route_editor --instance 1
```

账号编号只用于读取游戏控制配置和导入旧路线；草稿独立于账号。打开界面不连接游戏，第一次执行在工作线程中初始化控制器、画面资源和 OCR，后续复用上下文。

## 步骤各做一件事

原来录像店第 5 步中的多个路点已拆成到巷口、到楼角、到接近点、靠近到交互提示四步。每个移动步骤完成后松开按键，下一步重新检查当前画面。新增路点通过添加“移动到路点”步骤完成，直接在步骤列表中删除或调整顺序。

| 分类 | 动作 | 完成条件 |
| --- | --- | --- |
| 检查 | 检查出生位置 | 当前画面可定位，且站在所选出生点 |
| 移动 | 移动到路点 | 到达唯一目的地，或满足该点允许越过的范围；不等待交互提示 |
| 移动 | 靠近交互目标 | 在目标附近看到对应的交互提示；不按交互键 |
| 交互 | 按交互键 | 武备箱打开搜查面板；电子保险箱打开光圈界面，不执行光圈解锁 |
| 解锁 | 完成光圈解锁 | 从已有光圈界面完成点按，直到出现电子保险箱搜查面板 |
| 收集 | 装入安全箱 | 搜查完成，合适物品已处理；保留搜查面板，不代做重新交互 |
| 界面 | 关闭搜查面板 | 等待搜查完成，关闭面板并确认回到局内；不收集物品 |
| 退出 | 退出本局 | 主动退出并到达仓库界面，不执行入仓、出售或重新开局 |

发布流程中录像店有 15 步，白鸽有 6 步。正式任务与开发执行共用 `BagelRunFlow` 和相同业务操作，外层应用继续处理入场、结算、入仓、清理及重开。

完整流程从出生检查开始、以退出结束。交互前必须先靠近；电子保险箱交互之后必须解锁；容器打开后必须收集并显式关闭面板，才能继续移动或退出。显示名称不决定行为，动作类型决定行为，稳定标识用于勾选和记录。

## 勾选哪些，就执行哪些

点击一行只查看或编辑，左侧勾选框才决定是否执行。点击“执行勾选步骤”后，严格按列表顺序执行勾选项；没有勾选的步骤全部跳过。可以勾选不连续的步骤，也可以用“全选”“清空勾选”“只勾当前”设置清单。底部显示数量与执行编号，悬停可看完整名称。勾选只影响本次开发执行，不修改流程或正式任务。

不再提供勾选暂停、断点继续、起止范围和另一个单步执行按钮。要单步执行，勾一项即可。

例如只勾选“按交互键”和“装入安全箱”，工具不会先走到箱子旁。需要用户先把游戏停在第一项要求的画面。每一步重新截图检查条件，不满足时说明原因并停止；跳过必要步骤可能导致后续画面检查失败，不会自动补做。

空清单不能启动。开始时冻结完整流程与勾选清单；运行期间锁定编辑与勾选，地图仍可缩放和平移。实际定位失败在轨迹中保留空段，不跨空段连线。框架暂停快捷键仍可用；界面的停止按钮结束本次执行，不保留步骤间断点。

## 地图与参数

横屏三栏：地图、中间步骤列表、右侧当前步骤属性。浅色背景与主 GUI 一致，默认窗口为 1680 × 960，三栏初始宽度约 860 / 340 / 430。窗口加宽时优先扩展地图，也可拖动分隔线。

地图显示副本反转 RGB，让游戏的深色底图以浅色显示，路线和轨迹使用深色。转换保留透明区，不修改参考图文件、定位输入或坐标。默认缩放排除外围透明留白；滚轮缩放，拖动空白处平移，拖动圆点修改路点，“显示完整地图”重新适应路线。

右侧只显示当前动作相关的设置：

| 参数 | 含义 |
| --- | --- |
| 到达范围 | 地图坐标距离，未覆盖时使用导航默认值；修改后同时影响到达与越过节点的判断 |
| 移动时限 | 默认武备箱相关移动 45 秒、电子保险箱相关移动 75 秒；每步可覆盖 |
| 提前停步 | 只在保险箱接近点使用，默认沿用原来的 6 像素提前松键及停稳等待 |
| 靠近方式 | 按地图坐标接近，或沿指定方向小步前进；只在靠近交互目标时显示 |
| 交互范围 | 默认 10 像素；在目标附近才根据交互提示确认到达，避免误认前一个同类容器 |

普通移动只有一个路点。小步靠近使用“方向起点”和“目的地”两点定义方向，方向起点仅用于计算朝向，不会先走回该点。沿方向靠近仍由交互提示决定完成，不因越过参考坐标而回头。

新增靠近步骤优先使用发布流程中的同类模板。发布流程合法删掉模板后，根据已有前置路点生成可编辑的目标，小步模式生成方向起点与目标两个点，并提示先调整坐标再开发执行；这些初始坐标不代表已验证可通行。

地图实线圆表示到达范围，虚线圆表示走过路点后仍可完成该步的范围。参考图覆盖不等于可通行，不提供碰撞检测或自动绕障。停止距离、路点半径均使用地图坐标，不是桌面显示缩放后的像素距离。

## 文件与兼容

| 文件 | 作用 |
| --- | --- |
| `assets/game_data/bagel/<地图>/flow.yml` | 正式步骤与执行路点的唯一来源 |
| `config/devtools/bagel/<地图>.yml` | 开发草稿，正式任务不读取 |
| `assets/game_data/bagel/<地图>/route.yml` | 参考图、配准参数及旧路线资料 |
| `config/<账号>/bagel_routes.yml` | 旧账号路线，只通过显式导入读取 |
| `.log/bagel_trials/<时间与随机标识>.jsonl` | 完整快照、实际选中步骤标识、观察、耗时及结束原因 |

新版格式为版本 2。版本 1 文件先按旧规则严格校验，再在内存拆分路点、交互与解锁、收集与关闭，保留坐标、到达范围和导航参数，并稳定生成新增步骤标识。拆分后每步结束都会停步。读取不会改写旧文件；保存草稿或确认导出时才写新版。旧账号路线导入也只生成内存草稿，不改源文件。只有朝向和移动时长的旧 B 路线无法还原坐标，拒绝猜测转换。

校验拒绝未知版本、动作或字段、重复标识、非法数值和不合顺序的操作。每个坐标移动只允许一个目的地；坐标靠近只存终点，小步靠近必须有两个不同的位置。编辑时允许动作顺序暂时不完整，保存、导出和执行要求完整流程有效，选执行其中几步也不例外。

“保存草稿”只写开发目录。“导出为正式流程”经过确认后修改仓库资源，下次启动正式任务时生效。两者均完整校验、原子替换并回读，不自动提交或发布。运行中使用不可变快照，保存不会改变正在执行的内容。

## 失败、停止与输入清理

普通动作失败停止并保留现场。正式任务识别到整局失败时，交给外层结算和连续失败规则处理；开发执行直接停止。正常退出操作会经过结算到达仓库主界面，但开发执行不会调用放入仓库、出售或重开。

工具只防止当前窗口重复试跑，不与主程序、MCP 或其他工具进程自动互斥。试跑前须停止其他控制端的任务，并等待其结束。停止及窗口关闭会等待工作线程清理；暂停、异常和完成均清理按键及拖拽，贝果操作还在执行返回前等待已经开始的暂停回调结束并停用旧订阅，详见[贝果操作收尾约束](bagel.md#独立流程开发工具与局部地图)。

记录写入失败会停止，不报告没有记录的成功执行。一次动作成功不等于整条路线已经验收。

## 验证范围

离线回归覆盖旧格式迁移与源文件保护、不连续勾选、执行顺序、真实 Qt 拖点与撤销、保存隔离、画面前置条件、保险箱交互与解锁边界、收集保留面板、关闭等待搜索完成、失败传播及输入清理。

本次没有操作真实游戏。拆分后每步重新定位和校准方向，仍需分别实机核对录像店与白鸽路线，尤其是录像店转角、贴墙、接近点提前停步与最终靠近，不能用离线通过代替通行验收。
