# 贝果流程开发工具

本文说明源码开发工具的操作方式、流程格式和执行边界。玩法、画面和正式应用行为见[贝果自动化方案](bagel.md)。

## 范围与入口

工具从源码独立启动。普通贝果设置页不提供入口。

```shell
uv run --env-file .env python -m zzz_od.gui.view.bagel.bagel_route_editor --instance 1
```

账号编号用于读取游戏控制配置。开发草稿独立于账号。

打开工具界面不会连接游戏。第一次执行时，工作线程初始化控制器、画面资源和文字识别（OCR）。后续执行复用已创建的上下文。

## 步骤各做一件事

### 步骤分类与创建

新增窗口和右侧编辑区共用“大类 → 具体操作”的选择方式：

| 大类 | 具体操作或完成条件 |
| --- | --- |
| 移动 | 到达目的地、靠近交互目标 |
| 箱子操作 | 按交互键、完成光圈解锁、装入安全箱、关闭搜查界面 |
| 检查与退出 | 检查出生位置、退出本局 |

移动类的第二项显示为“完成条件”。移动、交互、解锁和收集各自使用独立步骤。

每个移动步骤必须指定一个目的地。新增时填写 X / Y，添加后可以拖动地图点修改位置。

移动方式与完成条件分别选择：

| 移动方式 | 行为 |
| --- | --- |
| 正常移动 | 远处持续前进，近处短步调整 |
| 碎步接近 | 每次短按后重新定位，并朝目的地调整。不提供独立方向输入 |

选择“到达目的地”时，无需指定交互目标。选择“靠近交互目标”时，界面显示交互目标和识别范围，按以下条件判断完成：

| 条件 | 动作或结果 |
| --- | --- |
| 目标附近出现对应交互提示 | 完成当前步骤 |
| 已进入目的地范围，但没有提示 | 停止移动，最多等待 2 秒。仍无提示时失败 |
| 等待时定位漂移或暂时丢失 | 保持停步，不重新移动 |

地图上的提示识别范围仅决定是否采用交互提示，不能代表游戏实际可交互距离。

新增步骤不读取正式模板，也不根据前一步推测箱子。初始设置如下：

| 设置 | 初值 |
| --- | --- |
| 目的地 | 前一个移动目的地。没有前一个移动步骤时，使用出生位置 |
| 交互目标 | 武备箱 |
| 移动方式 | 正常移动 |

目的地初值可以修改，不表示路径已验证。已有步骤可以修改大类、具体操作或完成条件。修改时保留标识、名称和适用设置，不适用设置可通过撤销恢复。更换交互目标时，工具保留目的地、移动方式和实际有效参数。

移动步骤完成后松开按键，下一步重新检查当前画面。添加移动步骤可以插入转折点，步骤顺序在列表中调整。

| 分类 | 动作 | 完成条件 |
| --- | --- | --- |
| 检查 | 检查出生位置 | 当前画面可定位，且站在所选出生点 |
| 移动 | 移动到指定位置 | 到达唯一目的地，或满足允许越过该点的范围。不等待交互提示 |
| 移动 | 靠近交互目标 | 在目标附近看到对应交互提示。不按交互键 |
| 交互 | 按交互键 | 武备箱打开搜查界面，电子保险箱打开光圈界面。不执行光圈解锁 |
| 解锁 | 完成光圈解锁 | 完成光圈点按，并等待搜查界面。已在电子保险箱搜查界面时，核对后直接完成 |
| 收集 | 装入安全箱 | 搜查完成，合适物品已处理。保留搜查界面，不重新交互 |
| 界面 | 关闭搜查界面 | 等待搜查完成，关闭面板，并确认回到局内。不收集物品 |
| 退出 | 退出本局 | 主动退出并到达仓库。不执行入仓、出售或重新开局 |

正式应用和开发执行共用 `BagelRunFlow` 及业务操作。正式应用的外层流程负责入场、结算、入仓、清理和重开，见[自动化方案](bagel.md)。

电子保险箱交互后若直接出现搜查界面，“完成光圈解锁”步骤核对保险箱标题、安全箱和搜查状态。确认已解锁后，步骤直接完成，不重复按 F。仅识别到标题，或识别到武备箱搜查界面时，步骤不能通过。

完整流程从出生检查开始，以退出结束。步骤顺序必须满足以下条件：

- 交互前先靠近目标。
- 电子保险箱交互后执行解锁。
- 容器打开后执行收集，并显式关闭面板，再继续移动或退出。

动作类型决定行为，显示名称仅供阅读。稳定标识用于勾选和记录。正式应用连续执行相邻的电子保险箱交互和解锁，消除首圈观察前的步骤交接等待。开发工具仍逐项试跑，勾选交互时只打开界面。草稿格式和步骤标识保持原样。

## 勾选哪些，就执行哪些

点击步骤行只查看或编辑。左侧勾选框决定步骤是否参与执行。

点击“执行勾选步骤”后，工具严格按列表顺序执行勾选项，跳过未勾选项。勾选只影响本次开发执行，不修改流程或正式任务。

可以勾选不连续的步骤，也可以使用“全选”“清空勾选”或“只勾当前”设置清单。单步执行时，只勾选一项即可。底部显示勾选数量和执行编号，悬停可查看完整名称。

如果只勾选“按交互键”和“装入安全箱”，工具只执行这两项操作。执行前，将角色移动到箱子旁，并使游戏画面满足“按交互键”的执行条件。

每个步骤开始前，工具重新截图并检查执行条件。条件不满足时，工具说明原因并停止。工具不会补做未勾选的步骤。

空清单不能启动。执行开始时，工具冻结完整流程和勾选清单。运行期间，编辑和勾选被锁定，地图仍可缩放和平移。实际定位失败时，轨迹保留空段，不跨空段连线。

暂停、恢复和停止使用一条龙主程序的全局快捷键配置，默认 F9／F10，不另设快捷键。“停止”按钮显示当前停止键，切到游戏后仍可使用。

上下文创建后的初始化和切窗等待阶段也可以取消。停止按钮和停止键均结束本次执行，不保留步骤间断点。

## 地图与参数

### 普通移动与容器解耦

普通移动只要求走到指定坐标，无需选择容器。`move` 不保存 `target`。位置只保存名称、坐标，以及可选的到达半径和越点半径。越点半径表示允许越过目的地的范围。导航参数可指定正常移动或碎步接近。

普通移动默认最长 45 秒，到达半径和越点半径均为 2 地图像素，不提前松开移动键。靠近和交互等动作仍需指定容器，以识别对应提示和画面。

工具采用横屏三栏布局：左侧地图、中间步骤列表、右侧当前步骤属性。浅色背景与主图形界面（GUI）一致。默认窗口为 1680 × 960，三栏初始宽度约为 860 / 340 / 430。窗口加宽时，工具优先扩展地图区域。分隔线也可以拖动。

地图直接读取与定位共用的发布 `map.png` 和 `map_mask.png`。打开工具时不拼接参考图。每次试跑前，工具重新加载资源。地图显示和执行器使用同一份固定资源快照，各步导航复用该快照。资源缺失、版本未知或遮罩不一致时，工具不启动试跑。

地图显示副本反转红、绿、蓝（RGB）通道值，使游戏深色底图以浅色显示，路线和轨迹使用深色。转换保留透明区，不修改参考图文件、定位输入或坐标。默认缩放排除外围透明留白。

| 地图操作 | 效果 |
| --- | --- |
| 滚动滚轮 | 缩放地图 |
| 拖动空白处 | 平移地图 |
| 拖动圆点 | 修改目的地位置 |
| 点击“显示完整地图” | 重新缩放地图，使路线适应显示区域 |

地图绘制出生位置、移动目的地和连线。出生位置是固定参照，不能拖动，并始终显示文字标注。点击出生位置可选择检查步骤。选中时，地图显示半径 5 地图像素的出生检查范围。其他非移动步骤不绘制点、编号或文字。

路线从出生位置依次连接移动目的地，中间的交互和收集步骤不打断连线。

| 路线类型 | 颜色 |
| --- | --- |
| 普通移动 | 蓝色 |
| 靠近武备箱 | 橙色 |
| 靠近电子保险箱 | 紫色 |

只有选中的移动步骤显示范围圈和可拖动目的地。绿色虚线表示本次试跑的实际定位轨迹，可通过“显示实际测试运行轨迹”开关控制显示。定位失败处保留断线。没有运行数据时，工具不生成轨迹。

右侧属性区显示步骤名称、位置名称、X / Y、范围圈、完整运行记录和操作按钮。顶部显示完成条件摘要。“查看说明”默认收起，包含详细规则和拖点说明。地图下方显示颜色图例。

位置名称与同一行 X / Y 归为一组，所有移动统一使用标题“目的地 · 地图像素”。数值输入和拖动地图点修改同一个位置。

到达范围和移动方式始终显示。交互提示识别范围仅在靠近交互目标时显示。超时、越点和提前松开移动键设置位于默认收起的“高级移动参数”中。有显式覆盖值时，入口标注“有单独设置”。

展开、收起和选择步骤均不修改配置。展开状态在当前窗口内保持。取消“使用默认”后，可以编辑对应数值。

| 参数 | 含义 |
| --- | --- |
| 到达目的地的范围 | 两种移动方式均使用该范围。普通移动进入范围后完成。靠近交互目标进入范围后，停步等待提示 |
| 最长移动时间 | 普通移动和靠近武备箱默认 45 秒，靠近电子保险箱默认 75 秒。超时仍未完成时停止 |
| 提前松开移动键距离 | 普通移动的可选设置。勾选“不提前松开移动键”时禁用。提前松键不代表步骤完成，规则见下文 |
| 越过目的地的允许范围 | 普通移动默认跟随到达范围，也可独立设置 |
| 移动方式 | 正常移动／碎步接近，行为见[步骤分类与创建](#步骤分类与创建) |
| 识别交互提示的范围 | 默认 10 地图像素。进入范围且出现对应提示时，才完成靠近，避免误认前一个同类容器 |

启用提前松键后，导航进入设定距离，且纵向偏差不超过 2 像素时，松开移动键。等待 0.5 秒后，导航用新截图核对位置。仍未到达时，导航继续当前步骤，以短步调整。满足到达范围或允许越过的范围后，步骤才完成。每次执行只提前停车一次。提前松键距离与完成范围分别设置。

每次移动输入后，导航必须用新截图重新定位。到点后等待提示期间，导航不再发送移动输入，直到识别成功或等待 2 秒超时。

### 常见疑问

| 操作需求 | 方法或说明 |
| --- | --- |
| 指定碎步接近方向 | 填写目的地即可。方向规则见[步骤分类与创建](#步骤分类与创建) |
| 选择移动目标 | 必须选择地图目的地。仅“靠近交互目标”需要选择武备箱或电子保险箱。更换交互目标时，工具保留目的地和实际参数 |
| 新增步骤 | 点击“新增步骤”，选择大类和具体操作。移动类还需选择完成条件，填写目的地和移动方式。已有步骤使用相同选择方式，不依赖正式模板 |
| 查看地图实心点 | 出生点是固定参照，其余实心点表示移动目的地 |
| 查看地图范围圈 | 选中移动点后，显示实线到达圈、普通移动的虚线越点圈，以及靠近交互目标的点线提示识别圈。范围相同时不重复绘制。两种移动方式均使用到达圈 |

| 字段或值 | 含义 |
| --- | --- |
| `navigation: {}` | 使用默认导航参数，默认正常移动 |
| `final_mode: small_steps` | 碎步接近 |
| `coordinate` | 正常移动 |
| `name` | 仅供显示 |
| `action` | 决定业务完成条件 |
| `id` | 稳定标识 |
| `waypoints` | 仅包含一个目的地 |
| `xy` | 目的地的地图坐标 |

普通移动不保存容器用途字段。各参数默认值见右侧实际显示和上表。

新增时填写的目的地，可以在添加后通过地图或 X / Y 修改。新增移动步骤不要求前面已有移动步骤，也不读取前一步的方向。

地图显示可用于核对位置和范围。有效像素不表示道路可通行。工具不提供碰撞检测或自动绕障。所有距离均为地图像素，不受窗口缩放影响。

## 文件与格式

| 文件 | 作用 |
| --- | --- |
| `assets/game_data/bagel/<地图>/flow.yml` | 正式步骤和执行位置的唯一来源 |
| `config/devtools/bagel/<地图>.yml` | 开发草稿，正式应用不读取 |
| `assets/game_data/bagel/<地图>/map.png`、`map_mask.png`、`map.yml` | 定位和编辑共用的底图、有效遮罩、坐标和运行参数 |

流程文件使用 `version: 4`。每个移动步骤仅有一个目的地，移动方式与完成条件分别设置。读取文件不修改磁盘内容，保存操作才写入文件。

工具优先读取开发草稿。草稿不存在时，工具读取正式流程。修改正式执行步骤时，可以编辑 `flow.yml`，或通过工具导出。

校验拒绝未知版本、动作或字段，以及重复标识、非法数值和顺序错误。移动规则见[步骤分类与创建](#步骤分类与创建)。编辑时允许顺序暂时不完整，保存和执行时则要求完整流程有效。

| 保存操作 | 写入位置和生效时间 |
| --- | --- |
| “保存草稿” | 只写开发目录 |
| “保存为正式流程” | 确认后修改仓库资源，下次启动正式应用时生效 |

两种保存均执行完整校验、原子替换和回读，不自动提交或发布。运行中的流程使用不可变快照，保存不会改变当前执行内容。

### 读取已有流程

工具可读取版本 1–4 的流程文件。读取后，先核对步骤名称、顺序和目的地，再保存或执行。工具不再读取账号旧路线文件，也不会自动删除这些文件。

## 失败、停止与输入清理

手动试跑会自动激活游戏窗口。切窗前，鼠标左键必须连续松开 300 毫秒。按住或再次点击时，工具重新计时，避免启动点击在切窗后进入游戏。持续按住超过 5 秒时，工具取消启动并提示松键。

等待期间可以停止。工具不发送模拟点击，也不强制松开鼠标左键。该等待不占用运行状态。

独立移动使用连续 3 秒位置未变化保护，以及 100 次计次动作上限。普通动作失败时，开发工具停止并保留现场。

正式应用识别到整局失败时，由外层执行结算和连续失败处理。开发执行则直接停止。正常退出操作会经过结算并到达仓库主界面。开发执行不点击「放入仓库」，也不出售或重开。

工具只防止当前窗口重复试跑，不与主程序、模型上下文协议（MCP）服务或其他工具进程自动互斥。试跑前，先停止其他控制端的任务，并等待任务结束。

停止或关闭窗口时，工具等待工作线程清理。暂停、异常和完成时，工具均清理按键和拖拽。贝果操作在返回前，还会停用本次执行的订阅，并等待已开始的暂停回调结束。详细规则见[执行与输入清理](bagel.md#执行与输入清理)。

启动快照或执行过程中的记录写入失败时，工具中止本次执行。执行结束后，若仅最后一条结束记录写入失败，界面保留原执行结果，并追加“结束记录写入失败，请查看日志”的提示。

制图重建方法和定位测试范围见[固定地图说明](bagel_fixed_map.md)。

## 测试

界面回归位于独立测试仓 `zzz-od-test/test/zzz_od/gui/view/bagel/`，按被测模块划分：

| 目录 | 被测模块 |
| --- | --- |
| `bagel_route_editor/` | 流程编辑器 |
| `bagel_flow_trial/` | 试跑线程 |

界面测试按编辑动作和试跑行为组织。步骤对话框的全部创建方式及显示细节没有独立的逐项保护。交互测试使用Qt事件、对话框和撤销保存路径，不向真实游戏发送鼠标输入。业务执行器测试仍位于应用目录。

业务和界面测试共用文件隔离夹具，即为测试准备临时文件并在结束后清理的辅助函数。配置、草稿、运行记录和失败截图写入临时目录。发布流程和识别资源只从主仓读取。统一日常与完整回归见[贝果测试入口](../../testing/bagel.md)。单独验证界面时运行：

```powershell
uv run --env-file .env pytest zzz-od-test/test/zzz_od/gui/view/bagel/ -q
```
