# 机械硬盘战斗加载等待

## 问题与范围

游戏装在机械硬盘时，冷启动后的副本加载可能超过原节点的重试额度。
issue #2797 的同机对照记录中，约 52 秒的加载成功，约 65 秒的加载被提前放弃；
本机等待插件的后续日志还记录过约 111 秒的成功加载。

游戏设置提供默认关闭的「机械硬盘模式」，以及默认 180 秒、范围 60–600 秒的
「战斗加载等待上限」。只有开启机械硬盘模式时，等待上限才生效。
它是最多等待多久，画面一旦被原识别逻辑确认，就立即继续流程。

本配置只用于等待战斗画面出现的节点：区域巡防、实战模拟室、专业挑战室、
恶名狩猎、式舆防卫战、旧零号空洞、情报板、真·拿命验收以及通用战斗操作。
迷失之地的战斗遭遇检测并非副本加载，保持原重试额度；邮件、咖啡店、
随便观、返回大世界、OCR 阈值和其他节点也不属于本次改动。

画面与玩法依据见 [战斗画面](../../game/screens/战斗画面.md)、
[实战模拟室](../../game/screens/实战模拟室.md)和
[加载画面](../../game/screens/加载画面.md)。本次复用已有识别区域和成功条件。

## 等待机制

关闭时，保留各节点原有的重试次数及轮询间隔，包括原本每轮 0.5 秒的节点。
开启时，只有原节点返回重试，才按当前节点开始时间判断剩余等待时间：
额度内转换为等待，耗尽后转换为失败，保留原失败状态，继续原有失败路由。
原有成功结果和配置缺失等失败结果直接透传。

计时使用框架的当前节点开始时间；框架恢复暂停时会补偿这段时间。
进入新节点或重新执行操作时重新计时，重试结果不会重置计时。
识别和轮询会产生少量时间误差，因此等待上限不保证毫秒级截止。
不修改装饰器上的共享节点对象，配置仍按账号实例保存。

## 验证要求

- 同一帧序列分别运行关闭、开启模式，验证 65 秒加载只在开启时通过。
- 验证 52 秒加载在两种模式下都通过，180 秒未加载仍失败。
- 验证自定义上限、暂停补偿、重复运行和不同实例不会串用等待额度。
- 验证成功、失败状态，以及迷失之地和普通节点保持原行为。
- GUI 验证开关、上限范围、配置保存和实例切换。
- 实机对照需停用旧的全局等待插件；旧插件日志只能证明延长等待的方向有效，
  不能代替本次源码实现的实机验证。
