# 游戏素材归档规范

素材用于离线识别、流程回归和画面溯源。归档放在独立测试仓 `zzz-od-test/screens/`；运行模板留在主仓资源目录。本文维护规范，测试仓的索引和来源文件维护逐份素材事实。

## 按用途选择格式

| 类型 | 格式与尺寸要求 | 可证明的内容 |
| --- | --- | --- |
| 整屏状态图 | 整屏坐标测试默认原生1920×1080。普通画面可在识别复测通过后使用有损WebP q90 | 该状态的识别结果 |
| 精度敏感样本 | 定位、细文字、物品格变化等保留可验证像素，使用PNG或无损WebP | 对应识别精度与故障表现 |
| 局部参考图 | 保留实际尺寸，记录裁剪矩形与颜色空间（像素颜色的表示方式，如 RGB） | 指定局部识别，不能代替整屏坐标测试 |
| 录像与连续帧 | 记录录像标识、尺寸、帧率、帧号或时间、抽帧方法 | 已记录的时序，不能凭散帧证明完整实机流程 |
| 合成数据 | 明确底图、修改区域、生成步骤及参数 | 受控逻辑或识别边界，不能称为实拍 |
| 带框说明图 | 可缩放和加标记，保留源图引用 | 人工阅读，不直接作为原始识别输入 |
| 运行模板 | 记录源图、裁剪矩形、缩放、掩码、居中和颜色处理 | 能按记录重建并核对像素的模板 |

编码无损只表示编码没有继续改变输入像素。录像或有损图片解码后转为PNG、无损WebP，不会恢复原始采集精度。识别结果不变也不等于像素不变。

历史缩放图、局部图和说明图可以保留，但必须记录用途与尺寸例外。不能将缩放后的1080p图称为原生1080p。不得对精度敏感样本统一有损压缩。模板来源不限定PNG；关键是可验证的像素与完整处理记录。

## 来源记录

新增或更新素材时，在已有索引或同目录来源文件记录：

- 用途、来源类型、源文件或录像标识。
- 原始尺寸、当前尺寸；录像帧记录帧号或时间。
- 裁剪、缩放、压缩、标记、遮挡等处理步骤。
- 账号标识（UID）的遮挡位置与方法，是否已人工核对。
- 当前文件的 SHA-256 摘要（用于核对文件是否相同）；有原始文件时另记原始摘要。摘要只用于身份和完整性核对，不证明来源真实性。
- 模板的全部重建参数及像素核对结果。

已有来源事实保留在原清单，通过链接引用。不能从文件名猜出采集分辨率或帧号。历史无法恢复的信息明确标为缺口，不得推测补全。需要重建或更新素材时，再补齐所需来源。

贝果索引见测试仓[素材README](../../../zzz-od-test/screens/README.md)与[历史来源清单](../../../zzz-od-test/screens/bagel_archive.json)。角标和地图来源缺口见[贝果画面](../../game/screens/贝果计划.md#角标来源与裁剪缺口)及[固定地图](application/bagel_fixed_map.md#当前发布资源的来源与限制)。

## 新增、转换与迁移

1. 确定素材类型和用途，保留原始来源标识。
2. 遮挡UID，人工核对其他可识别信息；处理记录中注明修改。
3. 需要转换时，先另存新文件，再比较像素或运行受影响识别测试。不得先覆盖唯一来源。
4. 更新画面文档、测试引用、素材清单与摘要。
5. 移动、改名或删除前，核对代码、文档、动态索引及生成脚本。完成受影响验证后才清理旧文件。

相似图可能分别覆盖压缩差异、历史故障或连续帧，不能只凭外观认定重复。静态未搜到引用也不能证明未使用。外部链接、页面锚点和逐图视觉审核属于独立检查，报告中须说明是否完成。

归档路径默认 `screens/<画面>/<子态>.<扩展名>`。文件名使用可读子态，Windows不允许的冒号替换为下划线。画面文档中的 `source_image` 写测试仓相对路径。区域坐标由 `screen_info` 维护，不在索引复制。
