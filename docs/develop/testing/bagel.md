# 贝果测试入口

在主仓根目录运行以下命令。测试仓须克隆到 `zzz-od-test/`，并准备开发依赖和文字识别（OCR）模型。环境准备见[测试说明](README.md)。

| 用途 | 命令 |
| --- | --- |
| 日常开发 | `uv run --no-sync --env-file .env python zzz-od-test/run_bagel_tests.py fast` |
| 贝果完整回归 | `uv run --no-sync --env-file .env python zzz-od-test/run_bagel_tests.py full` |
| 全测试仓影响检查 | `uv run --no-sync --env-file .env python zzz-od-test/run_bagel_tests.py all` |

入口固定串行执行。独立导入模式允许不同目录中的测试使用相同文件名；离屏 Qt 让界面测试在不显示窗口的环境中运行。入口报告测试命令启动到退出的实际经过时间。可追加 pytest 参数，例如 `--durations=15` 或 `--junitxml=报告路径.xml`。计时不含依赖安装。

## 范围与组织

- `fast`：配置、数据格式、纯逻辑及关键状态流转，通过 `bagel_fast` 标记选择。目标为已有依赖的基准机器上60秒内完成。
- `full`：全部贝果业务测试、设置与编辑器GUI，以及直接相关的通用返回回归。包含日常集、真实截图识别和完整模拟流程。
- `all`：整个测试仓，排除需要通知凭据的测试；保留收集错误并继续执行。此结果须与已有失败基线比较，不能把部分通过称为全仓通过。

测试按业务行为组织。同一行为优先在能稳定验证它的最高层检查，不要求每个方法一个文件，也不重复展开与结果无关的参数组合。测试失败名称保留场景参数。

当前完整回归为400项（含6项通用返回），以400项为维护上限。新增独特风险若需要超过上限，先说明原因并重新评估预算，不能静默删除关键覆盖。真实识别与历史故障仍在完整集运行。短流程明确其已满足的前提，由少量完整流程验证前置流程的衔接。

受控时钟指测试中可推进的模拟时间，用于验证等待和超时。公共控制器、合成图、运行态清理与受控时钟放在测试仓 `test/harness/`。测试文件不相互导入。测试里的模拟控制器只记录输入，不向游戏发送按键。

贝果配置、记录和失败截图写临时目录；资源从当前主仓工作树读取。受控时钟只替换贝果操作和模拟控制器的模块引用，不修改共享 `time` 模块或事件线程的等待。

## 覆盖和材料

删除或合并前先核对覆盖去向，不能删失败用例来取得通过。发现失败时，先核对生产行为、测试画面和模拟范围，修正后验证，再决定是否合并测试。当前覆盖与限制见测试仓[覆盖说明](../../../zzz-od-test/BAGEL_COVERAGE.md)。

素材规则见[归档规范](../zzz/screenshot_archive.md)，历史缺口见测试仓[素材记录](../../../zzz-od-test/BAGEL_MATERIALS.md)。完整回归保留真实故障帧，离线流程通过不证明实机输入时序或成功率。

每次调整测试后，重新计数和计时，将运行结果记录在对应 PR 或 issue。记录测试命令、环境、计时范围和已有失败的对照结果；单次结果不能作为长期性能保证。
