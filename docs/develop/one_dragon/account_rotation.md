# 多账户轮换的结束判断

## 目的与配置

减少全部账户执行完成后不必要的切号、登录和等待，让多账户运行更快。

全局配置 `config/one_dragon.yml` 新增 `return_to_start_after_done`，缺省为 `true`，兼容旧配置。在“一条龙运行 → 运行设置”显示“完成后切回起始账号”，复用现有开关组件和属性适配器。它属于整次轮换的设置，不属于某个账户的登录方式。

使用步骤见[多账户轮换设置](../../usage/one_dragon_account_rotation.md)。

## 结束位置

执行前仍按原实现固定本轮参与列表，记录起始账户在列表中的位置。从当前参与账户开始，到列表末尾后接着执行列表开头；当前账户未参与时，沿用原实现从首个参与账户开始。

每个账户的应用组结束后，先计算下一个列表位置。若下一个就是起始位置且开关关闭，直接走独立的正常结束节点，不改当前下标、不切换账户配置、不检查不同游戏路径，也不执行切号、关闭或重新打开游戏。

开关开启时完整保留既有路径：切换配置或关闭旧游戏、切换账号，再由原来的切号后节点判断一轮结束。因此不调整开启状态下已有的跨路径收尾行为。

提前结束使用单独的明确状态边，不能落入“切换实例配置 → 切换账号”的默认边。最后一个账户的控制器和配置仍是当前状态，GUI 与 CLI 原有 finalizer（结束后动作的统一处理函数）继续按运行结果处理关闭游戏、关机、休眠或睡眠。

## 与登录方式的关系

本改动不修改登录界面、账号密码输入或历史账号 OCR；只决定是否发起最后一次回到起始账户的操作。账户之间仍调用原来的切号与进入游戏操作，因此可以和历史账号登录功能一起使用。

## 静态核对范围

| 情况 | 关闭开关时应走的路径 |
| --- | --- |
| 账户 1、4，从 1 开始 | 1 → 4 → 正常结束，当前配置为 4 |
| 账户 1、4、7，从 4 开始 | 4 → 7 → 1 → 正常结束，不重复执行 4 |
| 单个参与账户 | 执行一次后正常结束，不切号 |
| 仅运行当前 | 当前账户执行一次后结束 |
| 无参与账户，回退当前账户 | 沿用原回退逻辑，执行一次后结束 |
| 相邻账户游戏路径不同 | 中途换路径沿用原逻辑；最后一次结束判断发生在关游戏之前 |
| “结束后”配置关闭游戏或系统操作 | 仍交给原 finalizer，关闭游戏作用于最后一个账户的控制器 |
| 旧配置没有新字段 | 默认开启，保持原行为 |

以上是控制流逐项检查的预期，不是已运行的测试结果。按本次要求，只做源码审阅、语法、Ruff 与差异检查，不新增或运行自动化、GUI 或实机游戏测试。
