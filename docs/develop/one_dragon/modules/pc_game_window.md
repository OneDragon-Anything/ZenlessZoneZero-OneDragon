# PC 游戏窗口：候选标题与单窗口绑定

## 接口边界

框架负责发现和绑定窗口，不识别区服或游戏客户端。项目负责提供候选标题。

- `PcControllerBase.set_window_titles(titles: list[str])`：按传入优先级配置多个完整标题。
- `PcGameWindow.update_win_titles(titles: list[str])`：窗口层对应入口。
- 原 `set_window_title(str)` / `update_win_title(str)` 仍可用，等价于一个候选标题。
- 空列表或空白标题报错；重复标题保留首次出现顺序，框架保存独立副本。

例如传入两个客户端标题后，框架可以发现任一客户端，但不会同时控制两个窗口。标题只做完整精确匹配。

## 唯一绑定

首次查找按标题顺序选择：首个有匹配窗口的标题只有一个窗口时，绑定该窗口句柄及其进程身份。该标题有多个窗口时抛出 `WindowAmbiguousError`，不能依赖系统枚举顺序随意选择。

绑定有效时，重复初始化、刷新、切前台，以及后来出现优先级更高的窗口，都不会改变控制目标。控制器、截图策略与后台输入共享同一个 PcGameWindow；禁止各自查找其他候选窗口。

只有窗口或原进程失效、候选配置实际变化时才释放绑定。重新传入相同候选配置不会释放。进程身份检查使用所属线程、PID 和 psutil 的进程存活核验，避免进程退出及 PID 复用后继续控制旧目标。

`refresh_win()` 现在表示验证绑定并在失效时重新发现，不是强制丢弃有效窗口。

## 状态和错误

- `win_titles`：只读候选标题元组。
- `win_title`：首选预期标题，保持字符串或 None，不代表实际选择结果。
- `bound_win_title`：当前有效绑定的实际标题；未绑定或绑定失效返回 None，不触发重新选择。
- `is_win_valid`：查找或核验后的窗口有效性；多个同标题窗口会抛出歧义异常，不能被解释为 False。

操作执行器遇到窗口歧义会立即结束当前操作，保留明确原因，不沿“未发现窗口”的失败边启动游戏。运行前初始化也会拒绝歧义目标。非 Operation 调用方应在交互边界处理该异常。

## 读取进程路径

`get_executable_path()` 读取同一个绑定窗口所属进程的 exe 路径。没有绑定时按上述规则完成绑定，但不会激活窗口、初始化截图或启动游戏。读取期间原进程退出则本次失败，不改读另一个候选窗口。

调用方需处理：无窗口或无效文件路径的 FileNotFoundError、权限不足的 psutil.AccessDenied、窗口歧义的 WindowAmbiguousError，以及进程查询异常。只有成功返回后才能写入用户配置。

## 绝区零接入

默认候选顺序为“绝区零”“ZenlessZoneZero”，与账户区服无关。启用自定义标题时仅使用该标题，不回退。相同候选配置的账户切换与区服编辑不改变有效绑定。区服仍控制登录选区和刷新时间，不保证错误区服配置能完成另一客户端的登录。

绝区零账户页的“从运行游戏读取”按钮保存绑定进程路径到当前账户，失败时保留原值。通用账户页仅提供路径卡片创建扩展方法，默认仍只有手动“选择”按钮；下游无需实现新方法。
